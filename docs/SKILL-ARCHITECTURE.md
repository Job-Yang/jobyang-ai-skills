# 个人技能库架构规范：单一所有权、四层拆解与双模验收

> **定位：** 防止规则叠加成弱模型拐杖拖慢强模型，防止共享切面多头管理引发规则互搏；所有技能新增、重构与删改以此架构为准。

## 一、五类共享切面的唯一所有权矩阵

当多个技能在同一任务中串行或并行触发时，同一切面只允许一个技能拥有最终裁定权，其余技能引用并服从，不得在各自正文重写一套互相打架的规矩：

| 共享切面 | 唯一主责方 | 下游或相邻技能边界 |
| --- | --- | --- |
| **结构与小标题体例** | 上游主导文体技能（`engineering-docs` 用短关键词目录；`writing-craft` 按选定分支单读执行：`sharing` 用自然转场与同事口吻小标题、`opinion` 用口语直给判断、`tangshan` 用连贯散文与简短 H2 路标；`feynman-explainer` 按因果链展开） | `haohao-shuohua` 标题红线仅管无上游的独立成稿；被上游调用时严禁把上游小标题强改成另一种体例，也不得篡改表格或列表结构 |
| **比喻与反常识句型** | 机理清晰优先；各文体按读者决定合法类比尺度（`feynman-explainer` 合法机理类比、`writing-craft` 内 `sharing` 机理先于类比 / `opinion` 零门槛比喻 / `tangshan` 克制降维借例） | 上游不套 B2 翻案壳模板；`haohao-shuohua` 只清理坏动词、混搭/空心比喻与真翻案壳，绝不误杀上游合法类比，也不覆盖上游专有机制 |
| **段落版式与排版** | `haohao-shuohua/references/reader-layout.md` 分档底线（`120 / 150 / 200` 字及连排上限） | 统一遵循其版式分级；标准档可拆分超长段落墙，但不得重构上游章节骨架 |
| **外部取证与不确定状态** | `outside-view`（检索预算与降级纪律）与 `claim-check` / `argument-reading` 统一五级可信度 + 二过程态 | 未执行检索只能标「待外部核查」或「未执行外部核查」，严禁离线给出「已证实」或「证据不足」 |
| **改稿前置与终审验收** | `sansi-erhouxing` 仅管中大型文档结构变更前检查；`vdd` 专做宣称完成前的实证门禁与跨轮防漂移 | 局部微改（≤ 3 句或纯去 AI 味）不拦截、不出表、不叠双报告；只读 PR/Diff 审查找 `diff-review`，红灯排障找 `code-bugfix` |
| **编码规格、盲审、执行与 PR 备料** | `implement-spec`（编码规格与兼容拆分）、`spec-battle`（盲审对抗，绝不越权改 Spec）、`go-work`（只读 Spec 分步执行与归档）、`diff-review`（只读 CR 与 Skeptic 证伪）、`code-bugfix`（先红灯后修 Bug）、`pr-prep`（拆包说明、离线视觉导览 HTML 与回滚前检） | 共享 `shared/references/engineering-workspace.md` 单源契约：个人仓落 `docs/` + `Spec-Step` trailer，多人大仓默认 `.agent-work/` + `.git/info/exclude` 零污染；绝不擅自 `push` 或更改共享 `.gitignore` |

**图页与视觉交付归属：**

- **工程评审图与速读页：** 精确工程架构、时序、状态、部署图及技术评审文档（含 `Explainer` 技术速读页）统一归 `engineering-docs`。
- **文章概念图与封面：** 文章正文内的概念图解、步骤对比图与文章封面统一归 `content-infographic`（信息图与封面不跑工程图评审流）。
- **产品 UI 原型与设计系统：** 交互式网页原型、工艺视觉包、动效与设计规范统一归 `style-compass`。

## 二、四层物理分层规范（`L1–L4`）

详细双模分层与验证细则见 `skills/skill-library-keeper/references/dual-model-design.md`：

1. **L1 · 确定性护栏层：** 格式校验、半角标点、数值计算、视觉渲染、隐私门禁、不可逆拦截、检索上限与离线状态词下沉脚本或短硬红线，强弱模型同享收益。
2. **L2 · 高杠杆原则与品味层：** 只写决定产出上限的核心优先级、反迎合态度、读者锚点与质量判据，留白给强模型的自然推理路径（`SKILL.md` 尽量精干，轻任务直通）。
3. **L3 · 按需脚手架层：** 正反例手册、详细术语字典、长对照表、首轮建档话术全部沉入 `references/`，标清触发条件，禁止无条件起手全量加载。
4. **L4 · 应清理的弱模型拐杖：** 边写边做的机械修辞算术、禁止内部思考的官僚规定、在主干焊死几十条历史词对补丁、无差别横幅与强迫“重做”元收口、混入运行时的维护说明与版本考古，按消融结论清除或迁出。

## 三、双模 A/B 验收硬门禁

每次重构或升级核心技能，必须同时通过静态体检与盲评 A/B 对比，缺一不可：

- **静态零冲突：** `library_doctor.py --strict` 检出的 `F / D / R / P / C / X` 阻断项与冲突线索清零，全库 `description` 总字符控制在 `≤ 4500` 字符预算内，避免宿主截断丢技能。
- **强模型不降分且超裸跑：** 用相同真实难例与对抗用例盲评 `bare`、`old` 与 `new`，要求 `new ≥ bare` 且 `new ≥ old`（防过度脚手架负增益）。
- **弱模型守住底线：** 较弱模型加载 `new` 后，五维均分不明显回退（`≥ old - 0.2`）且单项最低分 `≥ 8` 分；若掉底线，优先补 `L1` 脚本或 `L3` 按需短范例，不回退到重度过程微操。
- **中立路由零撞车：** 更新后全库中立路由盲测正例召回达标且边界误抢为零。
