# 技能体系缺口体检

> 用法：这是从**全局流向图**反推"还缺什么"的体检，不是看到一个好 prompt 就想加技能。
> 基线：2026-10-22，25 个技能、4 个共用枢纽、9 类产出。配合 [流向图](./skill-map.html) 一起看。

## 判定原则（准入五问，由 skill-library-keeper 统一执行）

缺口判定不凭"看到好东西就想要"，而是按 [技能管家](../skills/skill-library-keeper/SKILL.md) 的准入闸门走，详见 [admission-gate.md](../skills/skill-library-keeper/references/admission-gate.md)：

1. **需求成立**：高频反复的痛；或低频但高重要、长期解决不了。
2. **分层归因**：先判断问题在模型 / Harness 常驻规则 / 工具脚本 / 技能方法哪一层，只有该归技能层且现有接不住才继续。
3. **业界方案三档**：能直接用→用；有绑定→炼化；评测确有硬伤→才重造（不许没评测就造轮子）。
4. **独立且不打架**：一句话唯一性 + 流向图检查上下游、触发撞车、规则矛盾。
5. **能持续**：先定成功判据，预留评测/召回回路。

五问都过才记为「确认缺口」；只满足需求但不满足独立性/层归属 → 记「观察项」或「不补」并写理由。结构性体检（撞车/孤儿/单点/硬绑定/漂移）跑 `skill-library-keeper/scripts/library_doctor.py`，人工补规则矛盾与真实触发率。

## 一、结构信号（从流向图连接关系算）

| 检查项 | 结果 | 判断 |
| --- | --- | --- |
| 死胡同（技能产出后没有任何下游消费） | 无 | ✅ 没有建了没人用的技能 |
| 实验反馈 只有「最小实验」一个来源 | 单点 | 职责本就单一，**不算缺口** |
| 可迁移规律 只有「反向拆解」一个来源 | 单点 | 同上，**不算缺口** |
| 交付 只有「完成验证」收口 | 单点 | 这是唯一收口点，正确，**不算缺口** |
| 最宽枢纽：去 AI 味汇入 6、取证 4、产品需求 4 | 高负载 | 是体系枢纽不是缺口；但取证单点依赖检索能力，离线时已在 claim-check 内做降级 |

## 二、确认缺口

**当前无硬缺口。** 没有"一类真实任务在图上找不到承接技能"的情况。

## 三、观察项（等真实需求触发，不提前建）

1. **多候选的发散/创意生成**。现有思维技能都在"给定材料上收敛"（钢人选、核查验、重推只在既定问题上推），缺一个"连选项都想不出来时，系统生成多个本质不同方向"的能力。触发信号：多次卡在"不知道有哪些路"，而不是"不知道选哪条"。届时再建，避免和钢人抉择抢触发。
2. **想法 → 多周任务/项目排期**。`product-brief` 管 PRD 和里程碑，不管跨项目的任务拆解与优先级排期。真出现这类需求再考虑。
3. **最小实验/反向拆解的产出回流是否顺畅**。它们都回流到产品需求/设计；若实际使用中出现"实验做完、规律拆完却没人接"，优先修回流动作，而不是加新技能。

## 四、明确不补（已论证，避免反复讨论）

- **问题澄清 socratic-clarify**：缓建，等触发两次真需求再说。
- **纵横分析法**：框架留档，低频，真做大调研再建。
- **天赋挖掘 / 人生设计**：已拍板放弃，过于宏大、易产正确废话；有效内核已并入现有技能。
- **双层解释（小白版+专业版）**：与 feynman"脚手架不印成品"的铁律冲突。
- **成稿前事实自检**：不新建；需要时让写作技能**软依赖** `claim-check`（缺了就降级），避免重复造核查能力。
- **专家多视角会诊**：同一模型扮多角高度相关，是假独立；有效内核（对立质疑、退出条件）已并入钢人抉择。

## 五、每次改技能后的固定体检动作

新增 / 删除 / 重连一个技能后，回到流向图问四句：

1. 有没有**任务源**在图上找不到承接技能？（空入口）
2. 有没有技能**产出后没人消费**？（死胡同）
3. 有没有关键产出**只有一个来源且风险高**？（危险单点）
4. 新技能是真补缺口，还是和现有技能**解决同一件事**制造冗余？

> 一句话：**缺口要从图里长出来，不从外部"看起来不错"的东西长出来。**
