## 0.1.11 — 2026-11-06

- 工程示例改为通用文档导航、组件选择、依赖检查、构建与观测场景，去掉公司平台、项目编号、具体业务及未通用化的指标；同步重生成SVG、PNG和draw.io。

## 0.1.10 — 2026-11-05

补齐新旧图型差集与有边界的兜底：

- `capabilities` 从源码注册表解析旧27个layout；`render --backend auto` 按原生Schema或旧layout选择后端。缺少专用视图时可以兜底，未知类型、混合／错误输入、生成或检查失败不盲目换图。
- 旧SVG／静态HTML保留JSON源、实际后端和兜底理由；冻结本次输入，检查通过后原子提交，拒绝覆盖源文件并保留既有权限。不给静态旧图冒充原生交互能力。
- 复核修正原生架构、ER、树等合法 `layout` 配置对象被误判为旧格式的问题；同名类型按输入族区分，不做丢字段的强制互转。
- 专用旧模板对齐浅色面与轻实体／Group轮廓，保留关键连线与显式终态、状态编码。三组同输入文本、位置、路径和画布保持，刷新31张当前结构图库。
- 定量SVG按标准展示验证，裁剪／蒙版等合法标准功能不等同画板兼容；脚本和foreignObject仍拒绝，标准SVG检查与画板检查不能混用。
- 新增能力差集指南，更新入口及费曼／分享的兜底分工；完整221项回归通过。矩阵、思维导图、图片圈注、定量漏斗真实兜底通过，原生ER保持原生路径。

## 0.1.9 — 2026-11-05

先改善旧外观，再桥接新后端：

- 旧 `diagram_kit` 改为浅色面和轻实体轮廓，Group边框、实体边框、连线颜色分开；保留分类色、明确状态色、旧主题、灰阶和SVG／draw.io接口。九张真实历史图的文字、位置、画布和路径保持一致，固定布局留白不在本轮改动范围。
- 随包固定Archify 3.2.0，保留上游源码与许可；新图默认经 `archify_bridge.py` 调用官方生成与来源检查，缺Node或失败不悄悄回退旧图，不自动升级或启动系统浏览器。
- 桥接工程图、一页式讲解、架构前后对照、局部面板修订；输入保留JSON／`.archify.md`，新图不套旧灰框主题。
- 增加 `archify-bridge.md`、`archify-reading.md`；修正入口、选图、交付、视觉与旧维护指南。图型不再按卡片或步骤数量硬判；同名对象不自动视为图文重复。
- 正式图记录接受HTML和Archify JSON格式；分享与费曼稿可选借用一页式阅读增强，正文归属不变。
- 实测原生浏览器PNG导出可用；含CSS样式的原生SVG被本机rsvg转换为黑块，明确新旧静态渲染边界，不误报平台编辑兼容。
- 全量196项测试通过，桥接包含11项边界／真实后端测试；另跑分享技能26项回归。测试与用户观察证据分开，独立Playwright验证步骤高亮，完整复杂图的页内字号限制保留为真实边界。

- 刷新 44 个当前模板／结构图示例。八组 800px 宽对照的业务文字和几何属性一致，主题名页脚除外；不据换色宣称阅读速度提升，不修改原飞书文档。

## 0.1.7 — 2026-11-03

选图思维定势（bad case：一份 8 张图的方案，7 张都是「分区 + 白卡片 + 折线 + 底部结论卡」，任务状态有 8 个却没有状态图，执行回流画成泳道卡片，对象模型画成卡片图，两张图逐行重复正文表格）：

- 根因：SKILL 硬约束写「研发技术图一律用 diagram_kit」，而 diagram_kit 只有卡片/分区/连线/结论卡；时序/状态/ER 的数据驱动渲染器存在但工作流里没提；工作流只给 3 个卡片图示例；「底部放两三张结论卡」写成了默认。30 多种图型的选择表藏在二层参考文件里。
- 新增 `references/diagram-selection.md`：关系形状 → 图型 → 工具对照表；「一篇文档 1 张结构总览 + 其余按章节选型」；章节讲状态/一来一回/对象模型就必须有对应图型；图不重复正文（卡片与表格逐行对应即重复）；结论卡、胶囊标签、图例按需。
- `SKILL.md`：新增「先选图型，再画」短表；画图硬约束与归属改为结构图 `diagram_kit`、时序/状态/ER/泳道/回路走 `render_templates`；工作流第 6 步先选图型，示例按图型给。`diagram-system.md` 声明只管结构图视觉语法，结论卡改为可选。
- 新增渲染器 `sequence`（时序图：参与者、生命线、同步/异步/返回/自调用、阶段底色）与 `er`（ER 图：网格实体、基数、L 形关系、穿实体即报错）。
- `state_machine` 回退路由重写：分叉回父状态画成平行短边；其余回退从卡片底边出入、每条独占走廊；新增「两边共线重叠」「回退横穿前向边」两条渲染期硬错误（旧版会把多条回退叠成一条线）。
- `render_templates` 修复 `text-anchor=end` 标签的重叠误判。
- `doc_check.py`：正文有状态表却没有状态图、有一对多对象模型却没有 ER 图、多图却看不出图型差异时提醒。
- 新增金标准 `seq-agent-dispatch`、`er-task-graph`、`sm-task-lifecycle`（取自真实方案文档）；新增 7 项测试，全量 162 项通过。

## 0.1.6 — 2026-11-03

正文格式反转：结构优先、段落是例外（bad case：成稿大段文字，没有主次层级）。

- 根因：旧规则在反向推段落——“因果和取舍写成句子”“列表每项是完整的话”“加粗一屏 ≤2 处（8/千字）”“列表行 >55% 报警”“章首不能是引用块”“段落 200 字才报”；同一内容的段落墙版本检查更干净，结构化版本反而被扣分。
- 新增 `references/formatting.md`：内容形状 → 格式对照表（对比/风险→表格，步骤→有序列表，要点/属性→`- **标签**：`，结论/前提→引用块/高亮块），强调三层级，列表写法，改写示例，飞书 callout 映射。
- `SKILL.md` 新增“正文格式”硬约束；第 5 步按形状选格式；第 7 步明确 haohao-shuohua 收尾不得把表格/列表改回段落。
- `writing-contract.md`/`human-reading.md` 删掉与之冲突的旧规则；模板改为表格/列表/引用块骨架。
- `doc_check.py`：段落线 200→120 字；新增段落墙（>2 段连排）、长章节无表格/列表、纯段落占比 >55%、整句加粗、单段多处加粗；结构性加粗标签和表格内加粗不计入密度；章首允许 `> **结论**：` 引用块；放宽列表占比与箭头密度。新增 4 项测试，全量 155 项通过。
- description 从 458 字压到约 300 字：删掉实现细节，开头直接写做什么、产出什么样的正文。版式规则与 haohao-shuohua `references/reader-layout.md` 对齐（本技能为最高密度档）。

## 0.1.2 — 2026-10-19

写作规则收紧（标题即目录、正文不泄漏对话与隐私）：

- 标题（H1–H3）改为只写**短关键词/模块/方向**，写宽便于章节扩展；不再允许把一句话、具体作用域或结论塞进标题（如“聚合校验 是什么、为什么会被下掉”改为“聚合校验”，“tag T+1 的两条数据线怎么对照验收”改为“tag T+1”）。
- 标题**禁止编号**：不写“第 N 步”“1.”“一、”，先后顺序由目录位置表达。
- 正文禁止写入对话来源与提问者（“老板/同学问”“你让我”等），禁止手机号、个人邮箱、真实姓名加称谓等个人信息。
- `doc_check.py` 与 `engineering_docs.py` 检查器把上述四类问题作为**错误**直接拦截；`references/writing-contract.md` 改写“章节”小节并新增对照表，`SKILL.md` 工作流第 4 步固化规则。新增 7 项针对性测试，全量 150 项通过。
