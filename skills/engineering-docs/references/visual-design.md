# 技术图的视觉设计

在图型已选、关系已确认后读取。目标是让读者先看到结构，再找到关键关系，最后读到细节。示例见 `assets/visual-examples/README.md`；样例提供设计起点，不约束真实系统必须长成同一种形状。

## 从阅读任务选择版式

| 阅读任务 | 视觉组织 | 避免 |
| --- | --- | --- |
| 看边界与组成 | 明确的包围关系、层级标题、同类节点对齐 | 所有方框等大等重，边界像装饰底板 |
| 沿路径找结果 | 主路径连续，分支并列，异常与回路留独立走线 | 把真实分支串成长链，箭头穿过文字 |
| 找交接与等待 | 泳道或生命线保持稳定，交接物就近标注 | 用同色暗示职责，靠上下位置猜先后 |
| 看排期与依赖 | 任务表与共享时间轴对齐，阶段分组 | 用等距卡片冒充按比例的时间轴 |
| 比较数据与解释变化 | 共同基线、直接标签、局部注释 | 多色大图例、双轴制造相关、装饰性面积 |

## 建立层级

一张正式图通常包含：

- **标题**：直接说对象或可证实的判断。图型、状态、范围放副标题，不挤成超长主标题。
- **主体**：主要节点或数值占最大空间。相同层级用相同字号、形状与间距。
- **重点**：高亮本轮决定、变更或异常。普通关系降低视觉强度，但不能淡到看不清。
- **注释**：解释一处会误读的机制、阈值或例外，就近放置；不把正文缩成一块小字。
- **来源与口径**：图旁或图下注明。合成数据必须显式标为示例。

别给每个节点配装饰图标。图标用于区分角色、存储、进程等类型时才有价值，且仍保留文字名称。2.5D、透视和阴影可用于非定量总览，但不能遮挡连接、改变面积或制造不存在的层级。

## 让布局承担解释

先写出读者应当首先发现的对象、其次追踪的关系、最后查阅的细节，再安排视觉强弱。不能每个节点都填满彩色、每条线都加粗，最后只剩标题承担重点。

分组优先使用邻近、对齐和适量留白；需要表达系统边界、责任方或处理阶段时再加包围区域。区域的标题和边界应比内部实体轻，避免背景和节点争夺注意。浅底表示阶段时，边仍承担先后关系，不能靠区域的位置猜执行顺序。

多行名称和说明优先左对齐，减少每行起点漂移；短动作、状态和数值可以居中。甘特的任务、负责人、时间条共用行基线；组成比较和长类别名可改为横向，让标签自然展开。横纵方向改变时，图注中的“高度”“宽度”“上／下”也要同步更新。

留白要服务分组。大块空白旁边却挤满标签，通常需要重新分配空间；不要用装饰填空，也不要为了消灭空白打乱合法路径。

## 把说明放到需要它的位置

可直接标注的曲线、阈值、极值和差值，优先就近写名称、数值与单位，减少图例和主体之间的来回查找。说明过密时保留共同图例或单独注释区，不强行给每个点加字。

关键数字从数据计算；强调最大值、变化量或关键任务时，一并说明高亮的含义。不能手写一个“看起来合理”的数，也不能把某个样例的高亮位置留到下一份数据里。

标注连接线应比数据线轻，且不能让读者误认成另一条观测曲线。标签避开数据、转折和箭头尖；白底只保护必要文字，不遮住真实关系。轴单位尽量横排，保留量纲、精度和统计定义。

轴线和网格用于定位尺度。保留有用的刻度与基线，降低辅助网格的强度；有直接数值的类别比较不必铺满双向网格。去掉装饰线不能连同边界、须线、缺测和弱信号一起去掉。

## 正文起步参数

以下是本技能的设计起点，不是外部标准。按真实载体调整。

| 项目 | 680px 正文图的起点 |
| --- | --- |
| 外边距 | 28–36px；内部网格以 8px 为间距单位 |
| 图标题 | 24–28px，字重 600–700 |
| 分区标题 / 节点标题 | 16–18px / 15–16px，字重 500–600 |
| 节点说明 / 边标签 | 14px；内容太多先减字或拆图 |
| 图注 / 数据来源 | 12–13px；不得用小图注承担关键语义 |
| 连线 | 1.5–2px；关键路径可略加粗 |
| 节点边框 | 1–1.5px；承载必要边界时保证对比 |
| 圆角 | 8–12px；状态、活动、存储仍遵循各自符号 |

系统字体回退可用 `Arial, "PingFang SC", "Noto Sans CJK SC", sans-serif`；中文环境优先选择实际存在的中文字体。别绑定宿主品牌字体。跨平台同时附 PNG；SVG 的可编辑文字和接收端字体可移植性是两件事。

尺寸单位必须分清：上表按最终显示像素描述，Matplotlib 的字号和线宽使用 pt，SVG 的数值取决于 viewBox 缩放。不要把相同数字直接抄给不同引擎；以最终阅读尺寸检查。

关键路径已经通过颜色、描边和文字标出时，不再叠加贯穿节点的粗横线。需要加重时，相对普通线增加不超过约 0.5px，并检查正文尺寸下是否仍显得克制。

## 颜色表达含义

先决定颜色承担什么，再选色板：

- **分类色**：区分无顺序类别，如模块或团队；同一实体跨图颜色一致。
- **顺序色**：表达从低到高的数值，亮度单调变化。
- **发散色**：存在有意义的中点，如零变化；正负两侧都要有刻度。
- **状态色**：成功、风险、失败是业务语义，不宜同时拿来区分无关组件。

默认使用 `document-pastel` 主题，唯一配置源为 [theme.json](../assets/visual-examples/theme.json)。它参考飞书画板经典色板，语义描边适度加深，以适应正文尺寸；不是飞书所有产品的统一官方规范。旧图和新增模板共用这份配置。

| 角色 | 深色 | 浅底 |
| --- | --- | --- |
| 正文 / 中性关系 | `#1F2329` / `#707680` | `#F2F3F5` |
| 蓝 | `#4063A8` | `#F0F4FC` |
| 绿 | `#367747` | `#DFF5E5` |
| 紫 | `#7456B2` | `#EAE2FE` |
| 黄 | `#896B21` | `#FEF1CE` |
| 红 | `#AF4643` | `#FEE3E2` |

分区用浅色，内部实体用白底和同组边框，正文统一深灰。普通关系线用灰色；定量数据线、阈值和关键路径保留足够深度。颜色按当前图的语义分配，不把“绿”永久绑定为某种模块或好结果。同一实体跨图保持一致；不要每次因为排序改变就换颜色。

不要求每张图用满色板。大面积保持白或浅底，高饱和色集中在重点。文字与背景按 WCAG 常规文本至少 4.5:1、大字至少 3:1 检查；理解内容必需的非文本图形与相邻颜色通常至少 3:1。纯装饰分隔线不机械套用这一要求。颜色必须有文字、形状、线型或直接标签作第二条线索。

## 线与标签共同设计

先为线留通道，再放节点。每条线能够从真实起点追到真实终点；分组背景不代替参与者。交叉点不画实心点，汇合点才明确标识。两条线共用一段时，读者必须能识别各自去向。

标签与所解释的线保持邻近，不压在箭头尖或转弯处。用短白底清出文字空间可以，但不能遮住其他关系。回路线写明触发条件和回到哪里。不同图型的线型语义各自成立，不设“虚线一律代表异步”的全局规则。

同一篇文档的图共享色板、字体和标题层级；布局按图型变化。组件依赖、时间进度和性能分布不应都被改造成同款卡片。新增的[常用模板](../assets/diagram-templates/README.md)分别使用分层、树、环、时间轴、屋形、矩阵和定量坐标，统一主题不等于统一外形。

## 美化旧图

先保存旧图和关系清单。选择最影响理解的一项改进：分区、重点、标签、走线或密度。参考图只借这些设计手法，不能借入其业务节点。成熟工具通常将主题、尺寸、语义映射和布局分开；主题负责一致性，图型和标注仍由阅读问题决定。

改完做同尺寸对照：读者是否更快找到主体、主路径或极值？是否仍能复述全部关键条件？如果只是换色而没有改善阅读，继续调整信息组织。不要为了新鲜感重画已经清晰的部分。

修改节点、数据或标题后重新检查，不沿用旧位置的美观结论。数据变化时复算高亮、标注、轴范围与标题；节点增删时重排关系。包内固定样例用于学习设计，复杂拓扑应优先调用成熟布局引擎；不要照抄坐标充当通用布局算法。

## 验收

先核对语义与数据，再看实际渲染的正常阅读尺寸；放大图仅用于定位问题。检查文字、线、箭头、边界、图例、灰度可辨性和视觉焦点。图内信息密度过高时拆成总览与详图，不靠缩字号过关。

正式复杂图交独立读者复述关系，并指出具体误读位置。审美评分只能辅助比较，不能抵消错边、假数据或不可读文字；没有独立读者时如实说明验收范围。

需要证明一次视觉改动是否更好，读取 [visual-evaluation.md](visual-evaluation.md)，固定同题、显示尺寸和读图问题，保留平局与负例。普通成图不必运行整套比较实验。
