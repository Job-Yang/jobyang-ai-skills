# 视觉改动怎样证明有效

用户要求比较效果、更新公共样式或替换绘图引擎时读取。普通图只按 `visual-design.md` 检查，不强制展开评测流程。

## 先冻结比较条件

保存旧图、图源、输入数据或关系清单，以及这轮准备改善的问题。挑选受改动影响的典型图，不能只选最容易展示优势的图。

双方使用相同内容和正常阅读尺寸。布局需要改变方向或高度时可以改变，但不能只向读者展示新版的放大图。新增标注只能来自同一份事实；若改了数据或范围，就不再是纯视觉对照。

给每图预先写一至三个能核对答案的问题，如“失败重试到哪一步”“哪个分支必须等待”“阈值以内的比例是多少”。正确答案单独保存，读者只看问题和图。

## 将正确、好读和好看分别判断

| 判断 | 证据 | 不能替代什么 |
| --- | --- | --- |
| 内容正确 | 独立复算、边与条件核对、真实渲染 | 文件生成成功不能证明内容正确 |
| 读图清楚 | 读者回答预设问题，记录误读位置 | 审美偏好不能证明理解正确 |
| 视觉改善 | 同尺寸前后比较、具体偏好理由 | 新配色或高分不能证明阅读更快 |
| 修改后仍稳定 | 增删节点、长标签、变化数据与字体复验 | 固定样例通过不能认证任意输入 |

关键错误单列：漏边、错方向、假汇合、数据缺失、误导尺度、文本裁切、颜色成为唯一线索。任何整体评分都不能抵消这些错误。

## 匿名对照

有独立评审条件时，把两版随机标成 A/B，不提供作者、版本身份、工具名或预期赢家。多个评审者独立完成，不先交换意见。

按以下维度比较：信息层级、布局与留白、文字与标注、视觉编码、关系追踪。可用内部五级量表辅助记录：难以使用、明显干扰、可读但有明显缺点、清晰成熟、精确且无明显冗余。分数是有锚点的主观评价，不是客观测量单位。

每图保留 A 胜、平局或 B 胜以及具体原因。揭盲后汇总胜／平／负和维度变化；不能把旧版胜改写成“不计入”，也不能仅报告平均分掩盖某张图退步。

没有两个独立评审者时按实际条件缩小结论。模型评审应标为代理读者；没有真实人类计时和受控实验，就不能宣称阅读速度提升或统计显著。

## 复验不覆盖历史

先冻结首轮结果，再修复被证据指认的问题。修正后的图另存版本与指纹，定点复验；首轮退步仍保留。不得要求评审者“打到通过”为止。

每次改变公共规则，同时检查邻近图型。改了标题、图例、字号、线型或横纵方向，尤其要复核默认样例以外的输入。变化输入暴露出固定坐标或手写结论的限制时，收窄工具支持范围或改用成熟渲染器。

## 对用户报告

交付可直接查看的前后对照、实际结果、主要改善和仍有限制的部分。方法和完整评分放附件，正文只说这轮证据支持的结论。不能把图示样例的改善直接等同于所有技术文档质量的改善。
