# 统一色板的参考与边界

**本文记录旧引擎的参考，不约束 Archify 新后端。** 2026-11-04 曾将基础色收为中性主题；实际用户结果证明过度去色和重灰边框削弱表达。2026-11-05 再小改旧引擎，将浅分类面、实体边、Group边和连线分开；新图保持Archify原生视觉，不继承旧色表。

## 采用什么

| 原则 | 本技能的实现约定 |
| --- | --- |
| 中性底、少装饰 | 白色画布，中性浅灰面板，默认无阴影 |
| 区分颜色用途 | 灰蓝标重点，浅分类面区分归属，状态色表达结果，不让所有框一样重 |
| 状态色按需 | 通过、警告、失败有明确含义才用绿、棕、红 |
| 深字与可辨的线 | 字与底色检查对比度，装饰分隔色不当关键连线 |
| 图形服务关系 | 配色不决定图型，不把所有内容改成等大卡片 |

基础色见 `visual-design.md`；唯一机器事实源是 `assets/visual-examples/theme.json`，浅底由共享实现派生。`diagram_kit`、`render_templates` 的结构图和数据图读取同源；数据系列仍保留分类色，不混同状态含义。

## 不采用什么

- 不依赖豆包的 renderer、宿主标签、账号或文件路径。
- 不复制其脚本或整套技能，不把私有素材加入发布包。
- 不沿用早期截图取色得到的黑结论条、粉米紫类别卡和高亮胶囊组合。
- 不把“克制”变成全图浅灰、没有重点；未强调内容仍需可读。

## 旧接口兼容

`DOUBAO`、旧主题名和 `verdict_bar / category_card / status_pill / evidence_action_row / matrix_table` 接口保留，颜色从统一色板派生。旧脚本无需为换色改节点、连线或坐标；外观有意更新，不保证旧图像素级复刻。

本轮不改变 SVG/draw.io 交付与既有导入边界。能本地渲染不等于已在每个平台验证可编辑性，发布检查仍按对应适配器执行。
