# 流程语义与布局

在流程涉及条件、并发、交接、重试或事件等待时读取。先明确控制规则，再选择符号和布局；不能为画面紧凑而删掉分支或把串行改成并行。

## 先选表达方式

| 要解决的问题 | 选择 | 需要保留的语义 |
| --- | --- | --- |
| 少量顺序步骤 | 列表 | 顺序、输入和结果 |
| 条件判断与循环 | 普通流程图 | 条件、出口、回到哪里、何时停止 |
| 工作由谁接手 | 泳道图 | 活动责任方、交接物、交接条件 |
| 并发汇合、消息或定时事件等待 | BPMN，或明确标注这些规则的流程图 | 排他/并行/包容、等待、取消和终止 |
| 多条件组合决定结果 | 决策表；需要标准交换或执行时用 DMN | 规则覆盖、重叠、优先级、默认结果 |
| 谁向谁发消息 | 时序图 | 调用边界、时间先后、同步与异步 |
| 一个对象怎样变化 | 状态图 | 状态、事件、守卫条件、非法转换 |
| 数据怎样加工 | 数据流图 | 数据名称、处理、存储、去向 |

泳道是职责分组，不自动代表并行。中心辐射和卡片矩阵适合能力分类，不能替代需要明确先后的执行流程。

## 从材料得到可核对的关系

普通任务在草稿中列节点和关系即可；复杂或反复改图时保存一份简短的语义记录，用稳定编号对应图源。无需为每张小图创建 JSON。

记录中至少能核对：

- 触发事件、成功结果和各类失败结果。
- 活动及责任方，名称用“动作＋对象”。
- 节点间的有向关系，以及关系是控制流、消息还是数据。
- 判断条件、默认分支和不能同时发生的分支。
- 并行启动点、汇合条件，以及失败或取消后是否继续等待。
- 回路入口、重试次数或停止条件、耗尽后的去向。
- 关键来源、未确认信息、所属阶段和有意省略的范围。

可采用以下简写，不把它印进正文：

```text
N1 接收任务（执行器）
N2 校验输入（执行器）
G1 输入有效？（排他）
N1 → N2 → G1
G1 有效 → 后续处理；无效 → 输入被拒绝
```

画完逐条对照关系清单。节点都在但漏了一条失败路径，同样不合格。顺序号、框的左右位置和颜色都不能替代边的语义。

## 网关和事件

普通流程图可以用带文字的判断节点；只有采用 BPMN 符号时才声明 BPMN。外观像 BPMN 不代表可执行，执行还需要合法模型、表达式和引擎验证。

| 控制规则 | 分支与汇合 |
| --- | --- |
| 排他 XOR | 只选一条满足条件的路径；汇合只合流，不等所有分支 |
| 并行 AND | 同时启动所有分支；需要全部完成才继续时，明确画出等待全部的汇合 |
| 包容 OR | 启动一条或多条满足条件的路径；汇合按已激活路径等待，不能当作 XOR 或无条件 AND |
| 事件等待 | 等待消息、定时器等事件；先到者胜出时说明其他等待如何取消 |

分支与汇合能形成逻辑块时，成对表达并尽量对齐，拆开“汇合”和“再次分支”。分支直接结束、不再汇合时，不为了对称添加虚假的汇合点。

BPMN 的 pool 表示参与者，lane 表示参与者内部职责。顺序流不跨 pool，跨参与者用消息流；lane 内跨职责仍是顺序流。数据关联不表示执行先后。

开始事件写触发条件，结束事件写明确业务结果。超时、取消、失败是否中断已有工作，要按事实标明；不能把普通结束事件当作终止所有并行活动。

## 按关系组织布局

1. 找到成功主路径，尽量沿同一轴从左到右或从上到下排列。
2. 将排他分支或并行分支放在主路径两侧，按真实汇合点收回。并行活动应并列，条件分支明确标注条件。
3. 异常终点和回退路径放到外围，回线绕开主路径，箭头清楚落在真正的重试入口。
4. 再按阶段或责任方分组。只有交接本身影响理解时才加泳道，避免空泳道挤压正文。
5. 为标签预留空间，调整同层节点和泳道顺序以减少交叉，最后才处理配色和图标。

阅读方向是布局偏好，真实回路允许逆向。长回线跨屏时拆成子流程或有明确对应编号的连接点，不能删除回路。

过长主链先检查能否按独立阶段拆分，并用总览与详图连接。确实串行的流程保持串行，禁止为凑宽高比伪造分支、随意折成蛇形或改变先后顺序。

合并异常路径前确认它们有相同的处理和终态。不同异常可以共享一段视觉走线，但条件和箭头必须可追踪，不能把不同恢复动作压成一个“失败”框。

## 布局工具怎样选

- **Mermaid / Graphviz dot / ELK**：适合有向分层关系，先调整方向、分组和节点顺序。dot 会尝试减少交叉与边长，ELK 支持端口、正交连线等约束；它们不判断业务分支是否正确。
- **直接 SVG 或 Draw.io**：需要精确分区、复杂标签或正式排版时使用。显式坐标提供控制，也增加碰撞、文字溢出和连线错误的可能，必须看渲染结果。
- **专用 BPMN / DMN 工具**：目标需要标准模型交换、模拟或执行时使用。通用流程图不能冒充可执行模型。
- **可用的远程绘图服务**：仅作为可选生成器，接收相同语义、目标载体和质量约束；未授权或不可用时继续本地出图，不降低语义验收标准。

更换渲染器前保留语义记录。不能靠加几个不可见的业务节点、伪边或调换真实顺序强迫布局。

## 参考图、模板和局部迭代

有参考图时，先分辨可借用的是分区、层级、间距还是视觉语言，再映射当前节点。模板不合语义时换模板，不能让事实迁就模板。

改旧图先读取图源和当前文档，保留稳定编号；没有图源时提取能确认的节点与关系，模糊连线列为待确认，不擅自补齐。

每轮只改变明确的范围，例如“保留关系，缩短回线”“新增取消事件”。沿用已有图源或绘图任务，再对照语义记录复检；一次布局变好不能证明信息没有丢失。

上述方法可从公开建模规范和可编辑绘图实践获得。观察到某个服务能生成 SVG，不足以推断它采用了哪个模型、提示词或布局算法。

## 验收与依据

先按语义记录逐项核对，再按 `portable-delivery.md` 的载体标准看实际渲染。颜色、圆角和总体评分不能抵消漏边、错误汇合、越界连线或不可读文字。

- [Camunda：可读流程模型](https://docs.camunda.io/docs/components/best-practices/modeling/creating-readable-process-models/)：明确命名、成功主路径、对称逻辑块、减少交叉和按需使用泳道。它包含可读性建议，并非每条都属于 BPMN 语法硬约束。
- [OMG BPMN 2.0.2](https://www.omg.org/spec/BPMN/2.0.2/About-BPMN)：活动、事件、网关、pool、lane 及连接语义。
- [OMG DMN](https://www.omg.org/dmn/)：决策与规则表达。
- [Graphviz dot](https://graphviz.org/docs/layouts/dot/)：有向图分层布局与交叉控制。
- [ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)：分层、端口和边路由。
