# 平台独立交付

技术判断、协作方法、图型选择和图文验收都在本技能内完成。飞书、MindAI、其他绘图 Skill、iLoop 和 OPC 均不构成独立使用的前置依赖。

## 默认交付

用户未指定平台时，采用可搬运的本地文件：

```text
design/
  document.md
  diagrams/
    flow.svg
    flow.png
    flow.mmd          # 若使用 Mermaid，保留原始图源
```

按实际需要保留文件，不为目录样式生成空文件。直接 SVG 就是可编辑图源；Mermaid、PlantUML、DOT、Draw.io、BPMN 模型等保留其原始格式。PNG 是预览，不替代可编辑源。

Markdown 使用相对路径引用，如 `![任务处理流程](diagrams/flow.png)`，并在附近提供图源链接。不要默认把原始 `<svg>` 标签嵌进 Markdown：有的平台会过滤 HTML，另一些只支持 SVG 文件或位图。不支持图语法的平台使用预渲染图片并附图源。

移动或打包时一起带走正文、图源、预览和必要附件。禁止把本机绝对路径、临时链接、远程字体或需要登录的绘图会话作为唯一可读入口。确需保留私有证据引用时说明可见范围，不把它误当作可公开搬运的附件。

## 按载体验收

| 交付载体 | 布局与验证 |
| --- | --- |
| Markdown / 文档正文 | 默认以 680 至 900 像素内容宽度检查。主要文字不得小于约 12 像素；按实际读者调整，优先 14 像素以上。宽图拆成总览与详图 |
| 可缩放画板 | 可以大画布。总览层级要清楚，常用缩放下局部文字可读，平移后关系仍能追踪；导出正文版时单独适配 |
| 幻灯片 | 以目标投影尺寸和页面比例验收。没有模板时可从 16:9 起步；必要时跨页展开，不能缩小整张复杂架构图 |
| PDF / 打印 | 按实际纸张、边距、分页和最终字号验收。跨页连线用明确连接点，检查黑白可辨性 |

正文中的“缩放到 70% 以下”“约 20 个节点”“6 条生命线”是拆图警戒线，用来触发检查；最终以目标尺寸下的语义完整、文字可读和路径可追踪为准。不要把这些数值推广为画板或所有图型的标准。

同一语义可以生成正文版和画板版。两个版本的边、条件和终态必须一致；若某版仅为摘要，明确指出详图位置和省略范围。

## 无平台账号也能完成什么

| 环境 | 工作方式与结论边界 |
| --- | --- |
| 有文件与本地渲染能力 | 从用户材料形成 Markdown，生成图源、本地渲染预览并检查；整包可离线阅读 |
| 没有专用绘图 Skill | 按包内图示规则生成 Mermaid、PlantUML 或自包含 SVG，用宿主现有渲染器验证 |
| 没有网络 | 使用已提供的材料和本地工具；缺少事实时保留待确认，不调用远程绘图器 |
| 只有对话，没有渲染工具 | 交付完整正文和图源，明确“图源已生成，视觉未验收”；不能宣称图已经可读或发布成功 |
| 用户指定在线发布但缺权限 | 保存已完成的本地交付；只将发布标为受阻，遵守目标平台授权要求，不反复申请或绕过权限 |

方法可移植不意味着所有模型、字体、渲染版本的效果完全相同。检测当前宿主能否读写文件、渲染图、查看图片，再选择可执行路径。生成源码不等于看过图片。

## 生成器和发布适配器分开

先用用户材料建立图的语义，再选可用生成器；发布位置在文档和图通过验证后处理。生成器返回的节点、标签、连线、图源和渲染结果都要检查。

MindAI 可用且任务允许上传材料时，可以使用它生成或调整 SVG；其账号、CLI、会话和飞书导出均局限在该条路径内。不要自动要求普通用户安装 MindAI，不把内部域名写进默认命令，也不将在线出图作为质量保证。

用户指定飞书时，先确认交付要求：需要在线拖拽修改则用原生画板；只需阅读时可按用户要求和平台能力导入预览并附图源。明确要求原生画板的任务不能偷偷改成图片交付。其他协作文档平台同理。

调用外部 Skill 前读取其当前能力和约束，确认与已选交付方式相符。若它固定绑定某个平台、字体或缺失参考文件，选择当前环境可验证的其他路径，不把那项依赖传递给整个技能。

原生画板转换后再查节点、连线和文字；文档上传后回读最终页面。只有实际检查过该平台的结果，才报告该平台发布完成。

飞书公开画板接口主要操作节点、分组、连线及主题。本技能按图的语义生成本地内容，不依赖“模板名直接生成整图”的远程接口。当前可用的 `whiteboard-cli` 可以把 SVG 转为 OpenAPI JSON，但坐标连线不等于已绑定节点，普通分组也不等于组织树或思维导图模型。只有本地转换成功时，应准确报告“节点数据已生成”；需要在线编辑保真时，再核验拖动端点、父子归属、字体、箭头和重新导出的画面。

## 开放格式的兼容检查

- SVG 带 `xmlns`、`viewBox`、`title` 和 `desc`，使用系统字体回退与自包含样式；不要依赖远程脚本、字体或图片。
- SVG 尽量使用基本形状、路径和文本；`foreignObject`、复杂滤镜或 CSS 在部分导入器中不可靠，必要时附 PNG 阅读版。
- Mermaid / PlantUML / DOT 保留图源和渲染版本信息，验证实际产物。GitHub 等平台对语法和嵌入形式的支持不能靠推测。
- 中文字体回退后要检查换行、字形和边界。对外分发优先同时提供已验收的 PNG，减少接收端字体差异。
- 普通交付可用系统归档工具保持目录结构，不要求包内 Python 或特定宿主。OPC 交接才读取 `handoff.md`。
- 当前 OPC `artifact_io.py pack --attach` 将附件放在 `<topic>/prototype/`。使用它时，正文引用必须与打包后的路径一致；不能假设它会自动保留任意附件根或改写链接。

## 更新和复验

更新正文时同时更新受影响图源与预览，旧图不可继续代表新决定。跨平台转换只改变展示方式，不改变图的关系模型。

交付前在另一个目录打开副本：检查相对引用、图源和预览是否齐全；在声明的目标尺寸检查字与线。验证记录区分“正文已审阅”“本地图已渲染”“目标平台已发布”，未执行项不能写成已完成。
