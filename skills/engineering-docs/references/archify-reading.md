# 图外能力：一页式讲解与可定位修订

**Archify 不只是绘图。** 其 Explainer 把结论、图、表格、步骤、代码和来源编译为一页自包含 HTML。这是可选阅读增强，不替代我们的研究、正文判断或中文清洗。

## 什么时候值得用

| 场景 | 可增加的能力 | 内容仍归谁 |
| --- | --- | --- |
| 技术方案速读页 | 结论、方案主图、取舍表、验收清单 | engineering-docs |
| 仓库／机制调研讲解 | 图中节点对应源码片段和固定版本来源 | feynman-explainer |
| 给同事的技术分享 | 图文联动、逐步定位、独立阅读链接 | talk-smith |
| 重构／迁移评审 | 架构前后对照、变更标记、来源核查 | engineering-docs |
| 已有一页式讲解的反馈 | 稳定面板ID、局部替换、带位置的追问 | 原文体技能 |

普通一句话、短回复和已经清楚的正文不强制做页面；公众号稿或长RFC仍保留原正文。不能因为增加网页就把图的说明堆成另一面文字墙。

## 具体能做什么

- **图文组合**：一段结论、最多四条原因，H2划为面板，图表和列表各承担一类信息。
- **步骤与节点联动**：`@steps` 引用图中的稳定ID；点击步骤可定位对应节点或路径。
- **来源与代码**：`@source` 给事实来源；`@code` 从指定Git提交读取代码行，不允许模型自填代码冒充原文。仓库来源必须真实可读，工作区改动不替代已提交版本。
- **局部修订**：同一面板ID可通过 `patch` 替换，未受影响的冻结内容保留；来源或结论变化仍须全文检查。
- **阅读与反馈**：节点聚焦、上下游和路径追踪；“追问这段”复制页面位置与ID，不会自动给人发送消息或调用远端Agent。
- **导出**：自包含HTML、原生图的SVG／图片、页面打印／长图能力。实际格式是否能在目标平台展示，仍须按平台验证，不宣称直接等同于Office或画板原生格式。

## 写一页式讲解前必读

读取 `vendor/archify/references/explainer-authoring.md`，按其草稿语言组织 `candidate.archify.md`。不要把它当普通Markdown导入器：嵌套列表、原始HTML等并非都支持。

```markdown
# 核心判断 {#answer}

先写一句明确结论。

- 支持结论的一项原因。

@answer scope="结论成立的范围"
@meta locale=zh-CN style=clean

## 核心关系 {#mechanism}

@diagram lifecycle id=task-flow source=task-lifecycle.json

## 需要读者做什么 {#checks}

- [ ] 核对关键条件。
```

关系图从真实结构数据编译，表格来自事实，来源不编造。复杂图面板需要足够宽度，生成后实际检查；页面提示“文字过小”时，重新组织面板或打开原生交互图，不用缩字压过。

## 分工与默认

原文体技能先完成内容和事实检查，`haohao-shuohua` 清洗中文，再由桥接编译阅读页。Archify 的写作检查只辅助定位长句、重复或缺范围，不能覆盖专业术语、事实和原文体。

- 不默认给每条回答生成网页，也不改全局常驻提示词。
- 不将四种页面风格或动效固化成文章模板，先让图和阅读顺序成立。
- 不把“路径可达”说成业务可执行、运行模拟或故障影响分析。
- 不主动部署、改文档、更新依赖、发送反馈或更改权限。
