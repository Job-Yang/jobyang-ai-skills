# 团队模板适配

团队模板决定内容放在哪里，不替代工程判断。

## 适配顺序

1. 先按 `decision-model.md` 形成标准决策对象。
2. 识别模板里的必填、选填和条件章节。
3. 建立模板章节与决策字段的映射。
4. 补入团队术语、权威事实源、风险清单和审批要求。
5. 删除当前任务不适用的选填和条件章节。
6. 模板缺少关键字段时，在最接近的位置补上最小内容。
7. 运行 G0 至 G12，不因模板缺少某节而跳过门禁。

## 模板章节分类

| 类型 | 处理方式 |
| --- | --- |
| 必填 | 保留；不适用时按团队要求填写理由 |
| 选填 | 只在能回答真实评审问题时保留 |
| 条件 | 命中对应风险或场景时展开 |
| 展示性 | 不提供新信息时删除 |

团队强制保留“不适用”章节时，按要求填写“不适用”及理由。技能默认模板不保留空标题和占位话。

## 映射表

适配时维护一份临时映射：

| 标准决策字段 | 团队模板章节 | 处理 |
| --- | --- | --- |
| `problem.current_state` | 现状 | 直接映射 |
| `criteria.non_goals` | 无对应章节 | 只有边界容易误解时，才在相关段落补一句 |
| `decision.accepted_costs` | 技术选型 | 合并进选型结论 |
| `delivery.rollback` | 发布计划 | 命中高风险时强制展开 |

映射表默认不进入正文。用户要求审计模板适配时再交付。

## 不可覆盖的底线

模板不能要求：

- 把未核实内容写成事实。
- 省略推荐结论和取舍依据。
- 隐藏主动接受的代价。
- 省略高风险场景的验证、感知和止损。
- 为了填满章节加入无关信息。

模板和底线冲突时，保留模板形式，但明确标出缺口或补充最小章节。

## 已有模板的读取方法

先通读完整模板及一至两篇真实范例，确认：

- 每一节实际由谁阅读。
- 哪些章节用于评审，哪些只是归档。
- 团队术语和状态名称。
- 哪些事实源被视为权威。
- 哪些风险和审批是团队硬要求。
- 空章节通常删除还是写“不适用”。

不要只看标题猜模板含义，也不要把某篇范例里的业务细节误当成长期规则。

## 模板学习的沉淀边界

适合沉淀：

- 稳定章节及其用途。
- 团队术语。
- 权威事实源。
- 长期有效的风险清单。
- 审批和状态规则。

不适合沉淀：

- 临时负责人。
- 某次发布的灰度比例。
- 当前版本号。
- 一次性项目排期。
- 未经确认的历史方案写法。

## 适配验收

适配完成后检查：

- 标准决策对象里的关键字段都有去处。
- 模板新增章节是为补决策缺口，不是另造一套结构。
- 必填章节按团队规则处理。
- 选填章节没有空壳。
- 正文、图表和结构化记录仍表达同一个决定。
