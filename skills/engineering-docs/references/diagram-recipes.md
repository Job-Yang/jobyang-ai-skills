# 常用技术图的画法

按需要读取对应图型。通用语义见 `diagram-guidance.md`，视觉设计见 `visual-design.md`。成图、源文件和复现方法见 `assets/visual-examples/README.md`。

## 架构图各自回答一个尺度的问题

| 图型 | 必须有 | 推荐版式 | 完成前核对 |
| --- | --- | --- | --- |
| 上下文 | 目标系统、角色、外部系统、带意图的关系 | 目标居中，外部参与者围绕；按交互方向排 | 没有夹入内部组件；目标边界明确 |
| 容器 | 独立运行或存储单元、职责、技术、协议 | 系统边界内按运行职责分区 | 容器不等同于容器技术；队列、任务、存储归属正确 |
| 组件 | 单个容器内模块、接口和依赖 | 入口、核心、适配器分组 | 箭头含义是调用还是代码依赖；不直接复制目录树 |
| 部署 | 环境、故障域、软件实例、入口与网络 | 故障域并列，软件实例嵌入真实运行位置 | 副本数、主备、路由与共享故障点有依据 |

架构图中的相对位置不天然表示调用顺序。能力地图只有分区而没有技术关系时，就叫能力地图；不能靠叠几层方框冒充运行架构。迁移前后对照采用同一命名和布局，只高亮真实变化；上线步骤另用流程或排期表达。

## 流程图和泳道图

主成功路径连续；真实分支在空间上展开，回路在外围回到准确入口。判断用问题或条件，活动用动词，终点写结果。每项重试包含上限、间隔或停止条件。并行启动与等待全部的汇合必须可见。

多角色交接时用泳道。选择横向或纵向泳道，让主交接方向自然前进；责任方稳定，跨道线标交接物。泳道不表示同时执行。不要为了对齐把不同责任方的活动塞入同一道。

复杂控制语义读 `process-modeling.md`。示例中的普通流程图不是 BPMN 模型。需要 BPMN XML 交换或 DMN 执行时，使用专用建模器并验证模型；本技能的方法说明不等于已经提供执行引擎。

## 时序图

输入先列参与者、消息顺序、调用类型、返回边界和异常。横向是参与者，向下是时间顺序；未给真实时间戳时，纵向距离不代表耗时。

| 关系 | 表达 |
| --- | --- |
| 同步调用 | UML 风格实线、实心箭头，按需加激活条 |
| 异步消息 | UML 风格实线、开口箭头；发送不等同于处理完成 |
| 返回 | 虚线并标返回值；沿实际调用边界返回 |
| 条件 | `alt` 或 `opt` 框，守卫条件与分支分隔明确 |
| 并发 | `par` 或等价说明；不能把普通上下排列称为并发 |
| 重试 | `loop` 写次数和触发条件；耗尽出口不能丢 |
| 超时与取消 | 表明由谁观测、谁取消，以及在途工作是否仍可能完成 |

使用 Mermaid 时，以实际版本为准：常见 `->>` 是实线实心箭头，`-)` 是实线开口箭头，`-->>` 是虚线箭头。语法名称不替业务语义，交付图必须有一致图例。不能照搬“虚线=异步”的泛化规则。

通过紧凑的参与者表头、浅色交互区域、编号与直接标签改善阅读。编号与短消息重叠时移位或取消编号。复杂组合框分图，避免嵌套细线将主路径切碎。成功图省略的失败机制应在邻近文字或配套状态图交代。

## 状态图

输入是一张“起始状态 → 事件 [守卫] / 动作 → 目标状态”的转换表。每个节点表示稳定状态，避免“执行校验”这类瞬时动作冒充状态。

将常见生命周期排在同一轴，等待与重试在一侧，失败或取消在另一侧。复合状态可减少重复线，但不改变合法转换。图上的终态意味着本次生命周期结束；允许重新开始时，明确是重开原对象还是创建新对象。未画的边是否禁止，要在范围中说明。

## 数据流图

先列数据源、处理、存储、接收方及数据名称。箭头表示数据移动方向，区别于架构图中的调用发起方向。批处理和流式、读取和写入、原始和转换后数据分别标明。

推荐按数据阶段组织，而非把服务器部署层级搬过来。存储有专门形状或类型标签，数据标签放在边旁。信任边界、脱敏点和跨区流出影响决定时必须可见；没有依据的加密或合规承诺不能补进图。

## ER 图

输入明确实体、键、关系两端的最小/最大基数及可选性。字段仅保留主外键与本次变更相关内容，其他字段不影响本图判断时省略。

每个实体用表格结构，标题与字段分开。关系线端点贴在实体边缘；采用乌鸦脚、UML multiplicity 或明确数字均可，但图例与全文一致。`1`、`0..1`、`0..*` 的含义不能只凭位置猜。主键/外键文字标识保留，不只用颜色。多对多是否需要关联实体取决于逻辑/物理视图，不自动替用户设计数据库。

## 甘特图

先确认任务、负责人、持续时间、依赖和日历；没有依据时用相对工作日和估算范围。不要先画日期条再凑任务。

推荐左侧任务与负责人，右侧共享时间轴。任务按工作流或团队分组；并行任务在同一时间刻度上可比较。用独立视觉通道表达进度和状态，不能拿条形长度同时表示工期和完成度。

- 明确区间约定，例如 `[开始, 结束)`；工作日、自然日和时区分开说明。
- Finish-to-start 依赖从前项结束指向后项开始；多依赖需全部满足。其他依赖类型需显式说明。
- 里程碑零时长，不用带宽度的任务条假扮。
- 只有经前推/后推计算零总时差，或由有效计划工具给出时，才标“关键路径”。有资源冲突、日历或延迟约束时必须纳入模型。
- Mermaid `crit` 只是样式标记，不会替你计算关键路径；`after` 和 `excludes` 的行为需按渲染器版本核对。
- “今天”线和进度只用于有状态日期的真实计划。示例不能制造虚假完成状态。

包内甘特例是明确假设下的 Finish-to-start DAG：任务估算已知、资源不冲突、以相对工作日计算。它演示依赖和关键路径，不是完整项目排程器。

## 里程碑与路线图

里程碑写可验收成果、时间、负责人和证据。示例“契约通过评审”是结果，“开发中”不是。与甘特同现时，从同一份计划派生，不另写一份日期。

按比例时间轴必须忠实日期间隔；等距阶段卡片应明确“阶段示意，不按时间比例”。路线图用于表达方向和时间窗口，不能把尚未估算的事项画成确定到日的承诺。

## 选择边界

| 需要的内容 | 处理方式 |
| --- | --- |
| 少量条件决定结果 | Markdown 决策表，列输入、规则优先级、默认结果；不必画图 |
| 方法调用的精确耗时 | 使用真实 trace 的 span 时间线；普通时序图不承担耗时分析 |
| 火焰图 / 调用栈 | 用 profiler 的采样结果与专用工具，保留采样口径 |
| 大规模依赖拓扑 | 先分层聚焦，再用图布局工具；不强塞 680px |
| Sankey / 地图 / 网络流量 | 有流量守恒、地理或拓扑问题时再使用专门工具 |
| UML 全套或可执行 BPMN/DMN | 仅在交付要求触发，查对应规范与工具，不承诺包内样例覆盖 |

技术图集中的 12 种视图均有可复现示例。它们覆盖常见阅读任务，不构成所有符号组合、平台导入器和复杂输入的全面认证。
