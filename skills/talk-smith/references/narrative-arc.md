# 技术分享叙事弧（narrative-arc）

> 用途：talk-smith 第三步搭大纲时读。把一个技术主题从"听过"带到"能反驳、能搬走用"。
> 与 feynman-explainer 的区别：它负责把问题讲透、并可直接交付研究报告/机制解读/选型研判（对内对外都接）；本叙事弧在讲透之上多三件事——**开头先给读者一个入口（TL;DR/先成果/现场钩子）、自我诚实拆台、几点启示收口**。分界不是"发不发出去"（公开研究本来就面向读者），而是这篇是不是做来讲给别人听的技术分享或经验叙事；幽默口语只是执行风格，不是启用条件。
> **分工（去重约定）**：本文件主讲**结构**（开头选哪种、节与节怎么排、先成果还是先过程、组织装置、收口）；中文语气、术语怎么说、比喻密度、幽默剂量与判定线、口语度上限、标题写法见 `style-cn-tech.md`，两边不互相复制。

---

## 1. 主推进链（改造后的链，不是八个并列要点）

一篇公开技术分享按这条链往前推。前一拍是后一拍的入口；删掉中间一拍，后面就接不上。

```
① 开头结构（三选一，默认 TL;DR 卡片）  见 §2
② 一句话主线 + 埋 1 个主线词并回收      见 §3
③ 摆现象/案例/背景痛点                 用具体案例把"这事真的在发生/为什么非做不可"摆出来
④ 拆"为什么是这样"                     段内三步：白话画面→命名术语→工程事实（公式/复杂度/边界）；句子写法见 style §1，不分双轨栏
⑤ 最易想错的一点单独成节               见 §6，问句标题可选不强制
⑥ 自我诚实拆台/划边界                  亮半成品 + 紧跟"留下了什么"，见 §7
⑦ 可搬走的东西                         对做 XX 的人，哪几块能搬进日常工作
⑧ 收口                                 几点启示 3 条平实体会 + 可选签名档/系列预告，见 §9
```

**反面模式（出现即错）**：
- ❌ 平铺要点：「XX 有以下几个特点：1…2…3…」——词条，不是叙事。检验：抽掉中间一节，后面还接得上吗？接得上 = 并列要点，错。
- ❌ 开头寒暄：「大家好，今天我分享的主题是……」「本文将介绍……」「随着 XX 的发展……」——开头必须先给读者入口，不许空导语。
- ❌ 机制只有比喻没有原样：比喻删掉后读者对机制零损失 = 装饰；硬机制必须先用一两句话写清"它实际算了什么/做了哪几步"，比喻叠在后面。

## 2. 开头结构（三选一，默认 TL;DR 卡片）

动手搭大纲第一步先选开头结构，不要默认"现场钩子"。

### 2.1 TL;DR 卡片（默认起手，五字段写死顺序）

标题之后、正文之前，先给一张五字段卡片，5 条以内、每条一句话、加粗词压在句中、不放过程细节：

1. **干了啥**（一句话说清做了什么）
2. **最大的坑**（路上最容易卡住的那一点）
3. **真正的收获**（做完之后最值钱的东西）
4. **这篇讲什么**（本篇覆盖到哪、不覆盖哪）
5. **最后引出什么**（结尾把读者引向哪个判断/方向）

卡片之后可紧跟一个**可选"系列交代"引用块**：本篇是系列第几篇、上一篇是什么、下一篇预告什么（未分享也可写"下一篇讲 X"）。不是系列文就省略。

> 短文出口：短篇科普/短分享不必撑满五字段，取一两句结论行即可；talk 口播自行压缩，不强制五字段卡（避免臃肿），机器也不对 talk 态查五字段。

### 2.2 先成果后过程（第二次预告）

- TL;DR 是第一次预告（给结论性收获）；机制讲完前，正文前部再单列一个"**先看数据 / 最终效果**"节，先亮看板硬数据与一句拟人工观感，再回头讲为什么能做到。
- **顺序红线**：不是"背景→原理→最后给结果"，而是"结论→数据先亮相→再拆机制"。建设型复盘、成果分享优先用这个顺序。

### 2.3 现场钩子（第三种，可选素材）

不寒暄，前 3 段给一个具体入口：一个真实的人说的一句话 / 一个具体画面 / 先承认读者脑中最可能冒出来的反驳 / 一个反直觉数字（但别替外部数字拆台，那是评论体）。老故事、历史类比仅在题材贴切时垫情绪，不强制。

> 红线（三种开头共用）：禁止"本文将介绍……""在当今时代……""随着……的发展……""众所周知……"式导语。

## 3. 一句话主线 + 埋主线词

- **一句话主线**：这篇只能留一句话，先甩出来（TL;DR 卡片即主线的展开）。
- **埋主线词**：关键概念首次出现时，明说一句"**记住这个词，下文会反复提到**"；**全文只埋 1 个主线词，不埋多个**；后文每讲一个零件/阶段都挂回这个词，在关键节点回收它。
  - 通用化例子：核心词是"反馈"，背景节末点一句"记住反馈这个词，下面补的每个零件都是在补它"；后面每讲一个零件都回到"这一段补上了反馈的哪一环"，结尾启示再收一次。

## 4. 组织装置（按题材选用，不是全上）

| 装置 | 干什么 | 适用题材 | 范例骨架 |
|---|---|---|---|
| **收窄链**（题材专用可选） | 每一步只回答一个问题、只淘汰一种可能，不抓着几个猜想乱试 | 仅排查/归因/踩坑复盘 | "第一步，查 A……被一条证据排除。第二步，查 B……也排除。第三步……只剩 C。" |
| **算账/代价**（题材专用可选） | 引入取舍时先算"错了代价多大"，代价决定讲到多深、做多严 | 仅选型/方法论/要不要上某方案 | "改一行文案，扫一眼截图够了；改的是核心链路，验证怎么繁琐都不为过。" |
| **N 步流水线** | 把一个黑箱拆成可数步骤，建立全景图 | 讲一个系统/流程/工具怎么跑 | "这一行背后大致要经过 7 步。"逐步展开。 |
| **可数分点**（常用） | 把内容压成 N 阶段 / N 层 / N 项自检，每一块给不同的验收口径，方便转述 | 任何长文 | "分四个阶段，每个阶段的验收标准不一样。" |
| **设问推进**（常用，见下） | 节首替读者把下一句问出来，再自答 | 任何长文转场 | "为什么是 X，别的手段真的做不到吗？……" |

### 设问推进写法

- 位置：节首转场处、可行性自检节、替读者抬杠处。
- 密度：正文每 **2–3 节一个**；8–12 个是**长文上限不是配额**，短文更少，不为凑数硬设问；**不连续两段都设问，不堆排比问句**。
- 写法两种：①转场设问"为什么是 X，别的手段真的做不到吗？"，下一句自己答；②替读者抬杠"什么，它拿不到？那就是我们要解决的问题。"问完必须立刻答，不悬空。

> **速记口诀/速查表**：从强制降为可选——内容确实复杂、读者需要收藏回顾时才配一张"N 步/几条"总览表，不口诀化、不兜底。
> 装置是施工结构，写进大纲时用；正文里 H2/H3 化成短模块目录（模块/方向关键词，不编号、不写成论点句），论点放该节正文首段；不把"第一步/第二步"当标题印出来。

## 5. 选型对比：三列表 + 图导读

- **三列表**：横向比较几个方案时用表，列 = **方式 / 行不行 / 原因**；状态符号用 ✅ / ❌ / ⚠️（功能性标记，不是装饰配色，符号规范见 style-cn-tech ⛔1）；表下补一句边界注（"其实走 X 的过程中也会大量造工具提效"这类）。

| 方式 | 行不行 | 原因 |
|---|---|---|
| 方案 A | ✅ | 一句原因（成本/复杂度/适用边界） |
| 方案 B | ❌ | 一句原因 |
| 方案 C | ⚠️ | 能用但有前提 |

- **图配一句导读**：闭环/流程用 mermaid，真实运行态用截图/看板图（图量大于文字节也正常）；每张图旁写一句"这张图在看什么"。对比/分层/清单一律上表，不堆纯文字罗列。

## 6. 最易想错的一点单独成节（原"反直觉节"）

- 保留"把读者最容易想错的一点单独拎成一节，不埋在正文里"。
- ~~必须用问句显式标出~~：已删除强制；问句标题（"你以为 X，其实 Y"）可选，反差陈述句标题也行。
- 写法：先摆常见误区，再一句纠正，紧跟工程依据。

---

## 7. 自我诚实拆台（替换评论体拆台）

**结构动作**：成果节之后、阶段收尾处，主动亮底，紧接着补"留下了什么"——不能只泼冷水。

- 主动亮明：材料是经验值而非全对、待确定项多；某环节是"半自动 + 人工兜底"；某条"路没走完"。
- 紧跟一句："但沉淀下来的工具/方向留下了，成了后续的前身"。
- 语气上的自嘲怎么写见 style-cn-tech §4（剂量/判定线/场合归零）。

> **评论体三件套（仅调研评论体可选，建设型复盘不用）**：开头声明立场 / 替外部数字或对方观点拆台（"别被这个数字带偏"）/ 区分证据与修辞。本技能默认是建设型分享，不替外部文章拆台。

---

## 8. 幽默在结构上的位置（剂量细节见 style-cn-tech §4）

结构上只把幽默放三处：**成果区一句拟人类比、节与节之间的转场、自我拆台处的自嘲**。频率（上限非配额：不超过每 2000–3000 字一处、全文 8–10 处封顶，凑不满不硬凑）、留不留的判定线、严肃事故复盘/正式对外发布/法律安全场合归零，全部以 style-cn-tech §4 为准，本文件不重复。

---

## 9. 结尾收口（第⑧拍）

- **默认：几点启示 3 条平实体会**，每条一个判断、能落地，不写对仗警句、不喊口号。
- **可选**：一句立场金句、一条读者明天能做的动作、一行签名档/小广告、系列预告。
- ❌ 禁止空收："以上就是我的分析""希望对你有帮助""欢迎留言讨论"。

---

## 10. 大纲产物模板（第三步交付给用户确认的东西）

```
【分享大纲】《标题：口语钩子：正式术语》
- 读者：锁定哪个工种；听完要他记住的一句话主线是「……」
- 开头结构（第①拍）：TL;DR 卡片（五字段逐条列）/ 先成果后过程（先看数据节放哪）/ 现场钩子（[具体那句]）
- 主线 + 主线词（第②拍）：主线「……」；埋的词「……」，在哪几个节点回收
- 摆现象/背景痛点（③）：具体画面/案例/硬数据……
- 拆机制（④）：段内白话画面→术语→工程事实（公式/复杂度/边界）……
- 最易想错的一节（⑤）：读者最容易想错的是……
- 自我拆台（⑥）：亮明哪处经验值/半自动/没走完；留下了什么……
- 可搬走的（⑦）：对做 XX 的人，几块硬货……
- 收口（⑧）：三点启示「……/……/……」；可选金句/明天动作/签名档
- 装置：本篇主用 [收窄链(排查专用) / 算账(选型专用) / N步流水线 / 可数分点 / 设问推进]
```

> 5–8 行确认方向后再填正文。预计超 4000 字的文章/超 20 分钟的 talk，先出这份大纲对齐，避免写完砍半。
