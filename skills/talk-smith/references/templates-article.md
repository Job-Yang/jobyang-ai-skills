# 模板 · 中长文（templates-article）

> 用途：talk-smith 产物是技术分享中长文（深度解析/系列博客/公开技术文章）时读。
> 篇幅参考：2000–5000 字服从内容，不凑字数；预计超 5000 字先出大纲对齐。
> 结构顺序查 `narrative-arc.md`，句子语气/幽默剂量查 `style-cn-tech.md`，本模板只给排版骨架与占位。

---

## 结构骨架

```
标题：口语钩子 + 冒号 + 正式术语
├─ TL;DR 卡片（默认开头，五字段，见下）
│    └─ 可选：系列交代引用块（系列第几篇/上一篇/下一篇）
├─ 主线（这篇只能留的那句话，加粗）+ 埋 1 个主线词（"记住这个词，下文反复提到"）
├─ 成果（先成果后过程：先亮看板硬数据 + 一句拟人工观感，再回头讲机制）
├─ 背景（具体画面 + 硬数据/一线体感）
├─ 机制（段内三步：白话画面 → 命名术语 → 工程事实；不分双轨栏）
├─ 易错点（单独成节；标题不写成问句/论点句）
├─ 边界（亮明经验值/半自动/半成品/路没走完 + 紧跟"留下了什么"）
├─ 可搬走的（对做 XX 的人，几块硬货）
├─ 选型对比（需要时上"方式/行不行/原因"三列表，见下）
└─ 启示（3 条平实、能落地的体会）+ 可选签名档/系列预告
```

## TL;DR 卡片模板（五字段，5 条以内，每条一句话）

```
> **TL;DR**
> - **干了啥**：一句话说清做了什么。
> - **最大的坑**：路上最容易卡住的那一点。
> - **真正的收获**：做完之后最值钱的东西。
> - **这篇讲什么**：本篇覆盖到哪、不覆盖哪。
> - **最后引出**：结尾把读者引向哪个判断/方向。
```

可选系列交代（非系列文省略）：

```
> 本篇是「系列名」第 N 篇。上一篇：《……》；下一篇预告：《……》。
```

## "先看数据"成果节模板

```
## 先看结果
- 看板/截图一张（图旁一句"这张图在看什么"）
- 硬数据 2–4 条（带出处/口径），每条跟一句"它意味着什么"
- 一句温和拟人工观感（成果区允许的一处拟人幽默，剂量见 style §4）
```

## 三列选型表模板

| 方式 | 行不行 | 原因 |
|---|---|---|
| 方案 A | ✅ | 一句原因（成本/复杂度/适用边界） |
| 方案 B | ❌ | 一句原因 |
| 方案 C | ⚠️ | 能用但有前提 |

> 表下补一句边界注（例如"其实走方案 A 的过程中也会大量造工具提效"）。✅/❌/⚠️ 是功能标记，不是装饰配色。

## 几点启示结尾模板

```
## 几点启示
1. 一条平实判断（能落地，不写对仗警句）。
2. 一条平实判断。
3. 一条平实判断。

（可选）一行签名档 / 系列预告。
```

## 写作要点

- H2/H3 是**短模块目录**（模块/方向关键词，如"反馈回路""发布与回退"），不编号、不写成论点句；论点放该节正文首段。关键句加粗；对比/选型/流程上表格。
- 图：只在文字绕三句才理顺的关系处画。帮读者记住的直观图（步骤链、对比卡、概念比喻、封面）交 `content-infographic`；要评审的精确工程结构图交 engineering-docs 出 SVG。图旁一句话讲「这张图在看什么」。
- 段落：一段 ≤ 150 字，纯段落不连排超过 3 段；并列、对比挪进列表或表格。
- 引用按平台规则内联；硬数字带出处。
- 幽默只在成果区拟人、节间转场、自我拆台三处，按剂量放；严肃事故复盘/对外正式发布/法律安全场合归零。
- 结尾禁"以上就是我的分析/希望对你有帮助"。

## 三态互转要点

### article → talk（文章改成口头分享）
- 砍：工程公式细节、长引用、三列表（口播不念表，改成一句对比）。
- 留：TL;DR 结论、主线与主线词、最易想错的一节、可搬走的动作。
- 加：每节开头一句"过渡口播"（上一节留下的问题 → 这一节回答它，即设问口播）；开头加一句"今天讲多久、听完你能带走什么"。
- 把 2000–5000 字压成 15 分钟约 2500–3500 字口播稿（口播语速约 200–240 字/分钟）。

### article → slides（文章改成演示分镜）
- 一节论点 → 一页 slide；每页只留一个论点 + 一个支撑（图/数字/短句）。
- 细节进 speaker notes，不堆上幻灯片。
- 出 `.pptx` 文件交本地 ppt 技能，talk-smith 只产"叙事分镜页"。
