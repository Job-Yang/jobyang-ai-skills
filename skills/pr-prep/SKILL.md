# PR Prep · 变更打包、视觉导览与发布前检

只备料不越权；在发 PR/MR 前消除过大拆包、泄漏本地状态与缺少回滚预案三大隐患，让审阅者一分钟看清全貌。

## 1. 合入前卫生与拆分检查

1. **防本地工作区与隐私泄漏**：核查待提交与已提交变更是否误包含 `.agent-work/`、调试残留（`console.log`、`pdb`、`dbg!`）、硬编码密钥或未同步的锁文件/生成物；按需查阅 [工程工作区契约](references/engineering-workspace.md)。
2. **过大 PR 拆分判据**：当改动超过 `600` 行或横跨多个独立业务主题时，主动建议按「基础设施/重构 → 核心逻辑 → 接线/清理」拆成多个可独立合入的小 PR，降低审阅疲劳与回滚半径；详细拆分与大仓规范按需查阅 [PR 拆分与合入前检清单](references/pr-checklist.md)。

## 2. 审阅者友好 PR 说明（Markdown）

围绕「审阅者需要做什么决定」按模块组织说明，不堆砌提交流水账：

- **背景与目标**：一句话交代改什么、解决哪个业务或工程问题（附关联需求或 Spec 链接，仅限入库文档）；
- **模块变更摘要**：按受影响模块归类，写清接口与行为变化及故意未做的边界；
- **重点人工核查区**：点名鉴权、数据迁移、CI、并发或跨团队契约等需维护者细看的文件；
- **验证证据**：如实写明运行过的检查命令、范围与实际结果（无运行即写「未跑」）；
- **灰度与回滚预案**：高风险改动按需查阅 [多人大仓生产安全清单](references/big-repo-safety.md)，写清灰度开关、监控指标与一键回滚顺序。

## 3. 大改动离线 HTML 视觉导览页（Visual PR）

当变更 `≥ 150` 行或跨 `≥ 5` 个文件（或用户主动要求「可视化 PR 导览」）时，运行脚本在系统临时目录生成自包含离线 HTML（**绝不写入业务代码仓污染 Git**）：

```bash
python3 scripts/pr_visual_report.py --root . --base <base-ref>
```

脚本会同步输出 Markdown PR 骨架与临时目录下的 HTML 路径，包含总览卡片、模块影响分布、风险路径徽章、提交时间线、逐文件走查清单与回滚核对表，零外链可直接离线打开。

## 4. 只备料、不越权推送

默认只交付 PR 描述文本与离线导览页路径；**绝不擅自执行 `git push`、创建远程 PR/MR 或合并分支**，除非用户明确指令且宿主具备对应权限。
