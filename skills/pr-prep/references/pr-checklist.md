# PR 拆分与合入前检清单（按需查阅）

> 仅在准备发 PR/MR、拆分大分支或填报大仓发布卡时按需查阅。

## 1. 大 PR 拆分四策略

当单分支超过 `600` 行或跨越 `3` 个以上独立模块时，优先按以下正交轴拆包：

1. **重构先行，特性跟进**：先发纯等价结构整理 PR（零行为变化，附表征测试），合入后再发小体量新特性 PR。
2. **Schema / 迁移与业务读写分离**：遵循 Expand-and-Contract，新增列/表与兼容读写先走一个 PR，回填与清理走独立小 PR。
3. **公共契约 / SDK 与消费方拆分**：跨团队共享接口定义与本地替身先合入，各业务消费方分批接入。
4. **机械批量改名与手工逻辑分离**：全仓重命名、格式化或自动生成物单起纯机械 PR，方便审阅者秒批。

## 2. 合入与上线前八项核对

- [ ] **零私有产物污染**：diff 内无 `.agent-work/`、临时日志、`TODO` 调试代码或密钥占位之外的真实凭证。
- [ ] **生成物与锁文件同步**：接口生成代码、文档索引与依赖锁文件已随源码一并刷新。
- [ ] **兼容与混跑安全**：新老代码并存期（滚动发版中）不会因缺字段、缓存反序列化或枚举未知值报错。
- [ ] **开关与降级退路**：高风险路径具备配置开关或明确回滚步骤，且回滚不依赖破坏性数据订正。
- [ ] **观测与报警信号**：关键异常分支有清晰错误码/日志（已脱敏），上线后知道看哪个指标判断健康。
- [ ] **测试范围诚实标注**：写清实跑过的模块测试及未覆盖部分，不拿局部跳过冒充全仓通过。
- [ ] **人审标记显式置顶**：触碰鉴权、计费、迁移、CI 或删除路径已在 PR 说明顶部加粗标红。
- [ ] **Commit 整理按团队规范**：如团队要求 squash 或线性历史，合入前整理好提交说明，保留关联单号。
