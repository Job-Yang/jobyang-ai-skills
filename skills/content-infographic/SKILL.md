# 内容信息图 · 让图承载内容，并和正文是一段

## 这个技能解决什么

随手配图配出来的常是抽象氛围图、角色摆拍——好看但没信息量，读者跳过它也不损失理解，那是为配图而配图。
更隐蔽的毛病是**图文两张皮**：读者以为图在解释上面那段，结果图里是另一套比喻、另一组词，对不上。
本技能同时治这两件事：

1. **图承载信息**：把几百字才讲清的道理（多路径、因果链、对比、分类、失衡）压成一眼懂的画面。
   合格判据：删掉它，读者的理解会不会变差？会才留。
2. **图文是一段**：每张正文图都锚定原文那一两段、配一句把读者带进图的过渡句，图上每个词都能在正文找到。

它是写作链路的下游：正文/结论成型后做可视化，**自己不写正文、不改作者结论、不替作者另起比喻**。

## 进场先自检

```bash
python3 scripts/doctor.py          # 渲染核心 / PNG 导出 / 文生图三级后端，能不能跑一眼看清
```

确定性渲染器只依赖 Python 标准库，任何平台都能跑；文生图随平台变化，按 `references/backends.md` 三级接。

## 两个后端（默认渲染器，文生图是例外）

| | 确定性渲染器（默认） | 文生图（例外） |
|---|---|---|
| 擅长 | 步骤链、对比、分类、流程、多标签、术语 | 一个具象场景把道理"演出来"、封面 |
| 中文/英文术语/数字 | **真文本，清晰、可改、可复核、跨平台** | 多标签有错字、漏项、误连风险，必须按清单逐项验收；必要的图像后期要如实标明 |
| 产物 | SVG（必）+ PNG（可选） | PNG |
| 入口 | `scripts/render_infographic.py` | 原生图像工具 / MCP / `scripts/gen_image.py`（见 backends.md） |

内容里有多个要排准确的中文标签、术语、数字或步骤，默认优先渲染器保证信息准确。**用户明确指定文生图、既有立体风格时，按指定方式生成，不静默改成工程流程图，也不为减少解释而删除主副标题、节点用途与关键关系。**先给完整的上屏文字清单，再检查真实图片；错字、虚构案例或错连线不得发布。当前已配置的 Ferry＋Codex 原生图像后端可由 `scripts/gen_image.py` 自动调用，见 `references/ferry-codex.md`。

## 整条链路

```
① 读全文，定位关键节点（不是每节都配）
       ▼
② 对每个节点：一句话拎出"这节想让读者接受的判断"；并找到/写好它锚定的那一两段正文
       ▼
③ 判断该不该出图 + 选后端                         —— references/selection.md
       ▼
④ 渲染器：内容填 JSON → render_infographic.py 出 SVG/PNG
   文生图：去品牌风格前缀 + 画面提示词 → 三级后端之一 → fetch_image.py   —— backends.md / visual-style.md
       ▼
⑤ 写一句"指图且点出图里具体东西"的过渡句；配插图包跑 check_linkage.py 对账  —— linkage.md
       ▼
⑥ 按 锚定正文 → 过渡句 → 图 → 图注 排版；要进飞书经作者确认后 media-insert（写操作）
```

## 快速上手（渲染器，最常用）

1. 读 `references/selection.md` 判定：出不出图、用哪种 layout（pipeline / columns / two_stage /
   compare / radial / metaphor）。
2. 照 `references/schema.md` 把这一节内容填成 JSON——所有上屏文字**逐字来自锚定原文**，术语原样，
   比喻优先用作者在正文里已经给的，不另造。`examples/` 有可直接套的样例。
3. 渲染：`python3 scripts/render_infographic.py spec.json -o out.svg --png`（1600×1067，约 3:2）。
4. 写过渡句，配插图包跑 `python3 scripts/check_linkage.py figure.json`，exit 0 才用。

### 六类布局一句话选型

- `pipeline` 有先后的步骤链（一次 API 调用的 7 步），下方可画阶段括号（Prefill/Decode）。
- `columns` 2~3 个阶段/方案并排讲差异（预训练/微调/RLHF），可带底部演进链。
- `two_stage` 两个对象各带属性对照（训练 vs 推理、Prefill vs Decode）。
- `compare` 多维度横向比较 2~3 个对象，单元格支持 good/bad/hl 语义色。
- `radial` 一个中心向外辐射 3~6 条性质。
- `metaphor` 一个"失衡/A 大于 B"的判断，几何版对比；要具象场景才升文生图。

一张图只讲一件事；超过 7 步或 4 列就拆两张。

## 图文咬合（硬要求，防"图文对不上"）

- 每张正文图 = **锚定正文（先在）+ 一两句过渡句（含"下图/如图"且点出图里的东西）+ 图 + 图注**。
  默认"正文保留、图辅助"（supplement）；也可"压缩正文、图承载细节"（replace），两种都要过渡句。
- 图上术语/英文/数字必须在锚定正文里查得到；正文用"预训练"图就别写 Pretraining，正文没有的不补。
- **比喻用作者自己的**：正文把三阶段类比成"编译 SDK→开发应用层→用户测试"，图就画这个，
  不替作者换成"读书学生→实习生→职场人"。正文没给比喻又确需加，先经作者确认并同步进正文。
- 规则与插图包格式见 `references/linkage.md`，机械对账走 `scripts/check_linkage.py`。

## 风格（固定视觉语言，不固定角色；去品牌、可移植；表现力优先于极简）

固定的是观感：白底/极浅灰、圆角卡片、橙色主点缀 + 克制蓝/红/绿语义色、细描边线性图标、柔和投影、
横版 3:2。**默认不画任何固定吉祥物 IP**，也不出现 logo/品牌名/水印。

但"无角色"不等于"极简静物"——实测画面空、单薄的锅不是吉祥物，而是丢了**体量悬殊 + 动作情绪 +
纵深细节**这三样。所以文生图叙事默认走 **rich 档**：把大小对比做足（3~5 倍）、让主体有动作和情绪、
有前中后景与动势，画面"满但不杂"；可放一次性无标记中性向导或真人剪影来承载动作（是为演道理，不是摆 logo）。
只有封面/极严肃场合才用 simple 档，且 simple 也要保住体量悬殊。要固定 IP 走自定母版图生图，母版不进技能包。
翻车点（箭头方向、多余道具、图上文字、角色标记）与完整提示词写法见 `references/visual-style.md`；
渲染器换品牌色在 JSON 传 `palette`。

## 硬边界

- **不编事实、不另起比喻**：图上每个字、数字来自原文；术语英文原词（Tokenizer、LoRA、Self-Attention）原样保留。
- **代码、API 签名、命令、公式、精确参数不入信息图**；要精确框线、可评审、可编辑的工程结构图/流程图/时序图走
  engineering-docs 的绘图桥接与专用能力兜底——那是“严谨”，本技能是“直观”，两者可成对但不互替。
- **密度**：按关键节点出，不按章节凑。长文一般 3~6 张承载图 + 1 张封面封顶。
- **插飞书是写操作**：默认先出图给作者确认，再 lark-doc 插入，原图不压缩。
- **文生图闭环不了时不静默**：当前平台没有原生/MCP/HTTP 文生图能力时，明说缺什么、怎么补（见 backends.md
  缺口告知契约），并降级——渲染器图照常出、场景图改 `metaphor` 几何版或只交付提示词，主目标不塌。
- 写正文交给写作技能（talk-smith / feynman / cuihuo 等）；本技能只在收尾可视化环节接手。
  反过来，本技能对它们也是**可选增强**：它们不依赖本技能就能独立成立，缺图时用文字把关系讲透。

## 文件

- `references/selection.md` —— 出不出图、怎么拎中心思想、怎么选后端（先读）。
- `references/linkage.md` —— 图文一体：锚定正文、过渡句、图注，插图包格式（必守）。
- `references/schema.md` —— 渲染器 JSON schema、六类布局字段、配色键、退出码。
- `references/visual-style.md` —— 去品牌视觉语言、默认无吉祥物、中性向导与自定母版、封面。
- `references/backends.md` —— 文生图三级后端、各平台现状（豆包/Claude Code/Codex/Trae）、3 步自接线口子。
- `scripts/render_infographic.py` —— 零三方依赖 SVG/PNG 渲染器（确定性后端）。
- `scripts/check_linkage.py` —— 图文咬合对账器（术语/数字出处、过渡句、另起比喻）。
- `scripts/gen_image.py` —— 跨平台文生图 HTTP/CLI 薄适配层（OpenAI 兼容 / 方舟 / generic / command）。
- `scripts/doctor.py` —— 进场自检（渲染、PNG、文生图三级后端可用性）。
- `scripts/fetch_image.py` —— 平台无关签名图 URL 下载（魔数校验，防下到错误页）。
- `examples/*.json` —— pipeline / columns / metaphor 样例。
- `tests/` —— 对抗式回归（渲染、英文整词不劈断、图文对账判别、适配器构造与降级）。
