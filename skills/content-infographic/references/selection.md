# 什么时候出图、走哪个后端

这是本技能的另一半灵魂：**不是每处都该配图，机械配图和不配图一样有害。**

## 唯一合格判据

**把这张图删掉，读者的理解会不会变差？**
- 会变差 → 它承载了信息，留。
- 不会 → 它只是装饰（抽象氛围、吉祥物摆拍），砍。

封面例外：封面不承载完整论证，判据换成「一眼说清这篇讲什么、什么调性」。

## 第一步：先拎中心思想，不是照标题凑画面

动手前用一句话说出**这一节想让读者接受的那个判断 / 那条逻辑**，不是"这段讲了 A、B、C"。

- ❌ 表面："这节叫'理解债'，画个债务图标。" → 出来个抽象钱袋子，没信息量。
- ✅ 拎判断："AI 写代码的速度已超过人看懂的速度，差距还在拉大。" → 画面自然长出来：一边代码堆成山，另一边人举放大镜追不上。

### 中心思想 → 画面母题

| 内容的逻辑形态 | 处理 | 后端 |
|---|---|---|
| 有先后的步骤链、流水线 | 编号卡片 + 箭头链，可加阶段括号 | 渲染器 `pipeline` |
| 2~3 个阶段/方案并列讲差异 | 分栏卡片 | 渲染器 `columns` |
| 两个对象多维度对照 | 对照表 | 渲染器 `compare` / `two_stage` |
| 一个中心向外多条性质 | 中心辐射 | 渲染器 `radial` |
| A 超过 B、失衡、追不上 | 体量悬殊对比 | 渲染器 `metaphor`（几何）或文生图（要具象场景时） |
| 抽象概念要打比方、需要具象场景/情绪 | 一个生活场景把道理演完 | **文生图** |
| 数据趋势/占比（定性） | 曲线、柱、饼 | 渲染器或图表工具；精确数字慎入插画 |

## 第二步：该出图 vs 老实写字

| 该出图 ✅ | 不要硬塞图 ❌ |
|---|---|
| 多路径、排除法、因果链、流程 | 一句话能说清的单个事实 |
| 对比、分类、结构、层级 | 严谨定义、术语的精确表述 |
| 抽象概念要打比方才好懂 | **代码、API 签名、命令、公式、精确参数** |
| 数据趋势和占比（定性） | 精确数字本身（图里易错、易糊、丢精度） |
| 一节的总纲、核心方法论 | 线性叙事、情绪铺陈 |

纯技术文档（接口、配置、代码解析）大多**不该**出插画；只有出现「架构关系、模块依赖、调用时序」这类结构时考虑，
而且那种要精确框线的图更适合结构图 / 流程图工具，不是本技能的信息图插画。

## 第三步：选后端（默认确定性渲染，不是默认文生图）

```
内容里有没有「多个要排准确的中文标签 / 英文术语 / 数字 / 步骤」？
  ├─ 有 → 渲染器（render_infographic.py，SVG/PNG，文字永不糊、可改、可复核）
  └─ 没有，主要是一个要"演出来"的具象比喻/场景 → 文生图（prompt-guide.md）
拿不准 → 先渲染器；渲染器的几何母题表达不了那个比喻，再升文生图。
```

理由：文生图模型在「成排标签、术语原词、连字符英文、精确数字」上必出错。你文章里
「一次 API 调用的 7 步」这种 7 个卡片 + Tokenizer/Embedding/Transformer/De-tokenize 的图，
**只能**用渲染器；文生图留给"机器人追代码山"这种标签少、靠场景说话的图。

## 密度控制

一篇文章按**关键节点**出，不按章节数硬凑，不是每个 H2 都要图。宁可少而精。
长文（5000 字以上）一般 3~6 张承载图 + 1 张封面封顶；短文 1~2 张。

## 文字纪律（两条后端都守）

1. 图上每一个字都必须来自原文/作者，或对原文判断的忠实概括；**不许借配图编事实、补数字、加结论**。
2. 术语和英文原词（Tokenizer、LoRA、Self-Attention）原样保留，不通俗化、不翻译。
3. 字数克制：标题一句、卡片几个词；塞一大段小字必糊（文生图）或必挤（渲染器）。
4. 语义色：红=排除/风险，绿=通过/坐实，蓝=方法/理性，橙=真正想高亮的那一处。
