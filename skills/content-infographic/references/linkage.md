# 图文一体：先有过渡、锚定正文、再过对账

## 先把"图文两张皮"说清楚

它**不只是**锚定和图注两个字段问题，而是：读者以为这张图在解释上面那段，顺着读过去却发现
图里是另一套比喻、另一组词、或多了正文没有的东西，**图和文各说各的、对不上**。常见三种：

1. **脱锚**：图没绑定它该解释的那一段，放到了不相关的位置，或锚错段。
2. **另起内容**：图里的术语/数字/比喻正文没有（正文说"预训练"，图写 Pretraining；
   正文用"编译 SDK"比喻，图却画"读书学生→实习生"）。
3. **缺桥**：图直接裸插在标题下，没有一句话把读者从正文带进图，读者不知道这张图要他看什么。

锚定 + 过渡句 + 图注 + check_linkage 对账，分别治这三种。**但手段是为目的服务的，别本末倒置：**
核心始终是"**用图增强理解、甚至替读者省掉一段文字**"。图要让读者更快 get 那个道理，
不是为了走流程硬加一张。删掉图理解不变差，就不该有这张图（见 selection.md）。
对账器挡的是"对不上"，不是替你决定"要不要图"。

## 铁律：图是正文那段的图，不是独立海报

每一张正文信息图，都由三样东西组成，缺一不可（封面除外）：

1. **锚定正文（先在）**：图要解释的那一两段，已经/即将出现在正文里。图不新增事实、不另换比喻。
2. **过渡句（1~2 句）**：正文末尾把读者带进图，**必须**含指图词（下图/如图/看图/这张图…），
   且要点出图里的具体东西，不能是空泛的"如下图所示"。
3. **图 + 图注**：图上每个词、术语、数字都能在锚定正文里找到；图注用同词复述这张图的结论。

模式有两种，都要过渡句：
- **补充（默认，supplement）**：正文保留，图让那段更直观。"文字还在、多一张图方便理解"就是这种。
- **压缩（replace）**：把正文那段的细节交给图承载，图旁留压缩后的话——这正是"用图减少文字"的用法，
  但仍要一句话告诉读者图里看什么，且被图承接的关键术语不能在压缩后丢失（对账器会查 W5）。

## 过渡句怎么写（一两句，把内容和图连起来）

- 顺着正文的结论往下引，点出图要看的那个具体对象：
  - ✅"这七步又分成两个阶段，对延迟的影响完全不同，如下图。"
  - ✅"先学知识、再学听话、最后学得让人满意，这三步对应的训练如下图。"
  - ❌"如下图所示。"（空指图，没说看什么）
  - ❌"这张图很好看"（和内容无关）
- 过渡句里的词要和图里、正文里**同词**：正文说"指令微调"，图和过渡句就别写"实习生阶段"。
- 一两句、一般不超过 90 字；它是桥，不是第二段正文。

## 图上内容只能来自锚定正文（不许图里自造）

- **术语、英文原词**：图里出现的 Tokenizer、base、instruct、RLHF，正文里必须有。
  正文写的是 Pretraining 还是"预训练"，图就用哪个；正文没有的英文阶段名，图不准自行补。
- **数字**：图里每个数字/量级（4-8 倍、A100、几万到几百万条）正文都要查得到。
- **比喻**：优先用正文作者自己给的比喻——那段文章把三阶段类比成"编译 SDK → 开发应用层 → 用户测试"，
  图就画这个；**不要替作者换成"读书学生→实习生→职场人"或别的吉祥物故事**，那正是两张皮的来源。
  正文没给比喻、确需加一个时，先跟作者确认，并把该词同步写进过渡句/正文（列入 `allow_new`）。
- **图注**：复述图的结论，用词与正文一致（如"预训练 vs 微调 vs RLHF · 编译 SDK→应用层→用户测试"）。

## 用 check_linkage.py 机械兜底

每张图配一份"插图包"JSON，跑 `python3 scripts/check_linkage.py 插图包.json`。
它逐字核对图上每段文字在锚定正文里有没有出处、过渡句有没有把人带进图：

```jsonc
{
  "mode": "supplement",            // supplement 补充 | replace 压缩
  "cover": false,                  // 封面 true 可免过渡句，其余检查照旧
  "source_text": "图锚定的那一两段原文，逐字粘进来",
  "kept_text": "replace 模式下留在图旁的压缩文字",
  "bridge": "这七步分两个阶段，对延迟影响不同，如下图。",
  "caption": "一次 API 调用的 7 步 · Prefill/Decode",
  "allow_new": [],                 // 确认要随图新增、并已同步进正文的词
  "figure": { "kind": "renderer", "spec": { /* render_infographic 的那份 JSON */ } }
  // 文生图：{"kind":"t2i","prompt":"…图上中文用引号写全…"}；封面 {"kind":"cover",...}
}
```

判级：
- **必改（exit 1）**：缺锚定正文/缺过渡句/过渡句不指图或空指图/过渡句没点图里的词；
  图里出现正文没有的术语、数字；命名标签与正文零重合（另起名字/另换比喻）。
- **待确认（WARN）**：措辞偏离正文但还没到编造程度、没写图注等——人工看一眼。
- 全过 exit 0 才允许把图插进文档。

> 它是机械初筛，挡的是"另起一套、自造术语数字、裸放图"这些硬伤；
> 画面好不好、比喻贴不贴，仍要人判。渲染器图天然好过（文字就是你填的）；
> 文生图还要额外逐字核对图里实际生成出来的字。

## 放进文档/飞书

- 顺序：**锚定正文 → 过渡句 → 图 → 图注**，图紧跟在引它的那句话后面，读者顺着读不会断。
- 飞书插入是写操作，默认先给作者确认，再 `lark-doc media-insert` 锚到对应标题/段落后。
- 封面不进正文也可，走交付；但封面标题同样要和文章主题对得上。
