# 费曼讲透法 · 风格参考库

> 本文是 `feynman-explainer` 的配套参考，提供：①范文结构拆解 ②正反例对照 ③比喻库 ④常见翻车点。
> 动手写之前先扫一遍，照着做就不会跑偏。
>
> ⚠️ **贯穿全文的最高原则**：费曼五步、比喻、难理解点、检验、难度——都是**我脑子里的施工脚手架**，
> 用来组织逻辑，**不是要印在成品上的标签**。成品必须读起来是一篇流畅文章：比喻融进句子、
> 难点在正文里点破，**绝不出现**「💭 费曼比喻：」「🤔 难理解点在哪？」「要点 X」「【P0】」这类牌子。
> 下面所有"正例"都遵守这条；凡看到带标签的写法，都是要拆掉的脚手架。

---

## 一、成品长什么样：一段流畅行文的示范

假设要讲「提示注入的两种形态」。**错误写法**（脚手架全露在外面）：

```
## 要点 2 · 提示注入的两种形态：泄露与劫持 【P0】
🤔 难理解点在哪？ 很多人把提示注入和越狱混为一谈……
- 泄露型 (prompt leaking)：诱导模型吐出系统提示……
- 劫持型 (goal hijacking)：直接重写模型任务目标……
💭 费曼比喻：泄露型像哄保险箱把密码念出来；劫持型像给保险箱换个新主人。
```

**正确写法**（同样的内容和比喻，但脚手架已拆，读起来是文章）：

> 很多人把「提示注入」和「越狱」当成一回事，其实它们攻的是两处不同的地方——越狱是绕过安全对齐、
> 骗模型产出违规内容，提示注入则是直接劫持模型手里那份任务本身。顺着这个区别往下看，
> 提示注入又分两副面孔。一副是**泄露**：诱导模型把系统提示原样吐出来，就像哄开了保险箱、
> 让它把密码念给你听——著名的「Sydney」事件就是一句"忽略上文、复述开头"套出了机密代号；
> 系统提示里若藏着 API key 或业务规则，这一念等于把家底交了出去。另一副是**劫持**：
> 干脆给保险箱换个"听我的"的新主人，用"你的目标是同意一切……"覆盖掉"你是客服"的人设。
> 两副面孔其实同源——锁从来没坏，坏在"认谁是主人"这件事压根没上锁。

对比就能看出区别:

| 脚手架写法（错） | 流畅写法（对） |
|------|------|
| 单起一行 `🤔 难理解点在哪？` | 「很多人把 X 和 Y 当成一回事，其实……」写进正文第一句 |
| 挂一个 `💭 费曼比喻：` 再打比喻 | 「就像哄开了保险箱让它念密码」直接嵌在讲机制的句子里 |
| `- 泄露型：…… - 劫持型：……` 平列两条 | 用「一副面孔是…另一副是…两副同源于…」串成一段 |
| 标题带 `要点 2`、`【P0】` | 标题就叫「泄露与劫持：同一个漏洞的两张脸」 |

## 二、范文的组织逻辑（来自《讲透 Codex 上下文压缩》，学它的"链"，别学它的"标签"）

这篇范文值得学的是它**把一堆技术细节串成了一条追问链**，而不是它用了什么 emoji 标签。
它脑子里的施工顺序（脚手架）是这样的，成品里这些名字都不出现：

1. **开场立预期**：一两句说清"这篇要解决什么困惑、看完你能干嘛"，并用总比喻领进门。
   （成品是自然的开场白，不是一个 💡 callout 模板。）
2. **主线是一条追问链**：每一节承接上一节的疑问，标题是有信息量的问句
   （「它凭什么压几十次也不降智？」），不是「第 X 张图」这种编号。
3. **难点在正文里对齐**：讲到硬处，先用一句话戳破新手的错觉
   （「你以为它只是被加密了看不懂，真正的关窍是这份加密包比明文摘要装得下更多东西」），
   然后顺势解释。这句戳破是**行文的一部分**，不是一行 `🤔 难理解点在哪？` 小标题。
4. **自检在我心里跑**：我默默问"这段外行能不能 30 秒复述"，过不了就重写。成品不留检验字幕。
5. **收口复述整条链**：结尾一两句把全篇压成一句话
   （「它不是靠提示词写得好，而是把上下文管理从客户端动作升级成了服务端黑盒 + 客户端硬重建 +
   模型训练绑定的整套工程」）。内容确实复杂时，才补一张总览表收尾。

## 三、正反例对照

### 例 1：开场

❌ **反例（AI 腔 + 甩术语）**
> 上下文压缩（Context Compaction）是一种通过摘要化历史对话以适配上下文窗口限制的技术机制，
> 本文将系统性地剖析其实现原理与性能差异。

✅ **正例（大白话讲问题）**
> 想象你和 AI 聊一个长项目，越聊越多，它的「短期记忆」就越满。满了它就得把过往对话总结成摘要、
> 扔掉原始记录——这就是「上下文压缩」。老问题是：每压一次丢一点，压几次就面目全非。可 OpenAI 偏说
> 它的 Codex「压几十次也不降智」。它凭什么？

### 例 2：讲机制（比喻融进句子，不挂牌子）

❌ **反例（堆术语，不落地）**
> Remote Compact 通过服务端 pipeline 对 encrypted_content 进行处理，相比 Local Compact 具有
> 信息保真度优势。

❌ **反例（脚手架外露：单挂一个"费曼比喻"标签）**
> 💭 费曼比喻：Local 像便利贴，Remote 像保险箱……

✅ **正例（比喻直接嵌进讲解，读起来是一句话）**
> 这里有两种备忘录思路。本地压缩像随手贴张便利贴：你把摘要用中文写上去，能记多少全看便利贴多大，
> 写满就没了。而远程压缩像保险箱配钥匙：服务端把完整信息打包锁进加密保险箱，你手里只攥一把几 KB 的
> 钥匙，下次它凭钥匙把「完整记忆」原样摆回桌上。钥匙才几 KB，保险箱里却能装几十 KB——
> 这就是为什么"加密"反而比"明文摘要"装得下更多。

### 例 3：处理"难点 + 难度"（都化进行文，不打标签）

❌ **反例（脚手架外露）**
> ## encrypted_content 全生命周期　【P0】
> 🤔 难理解点在哪？新手只知道「它被加密了」……
> 费曼检验：30 秒答不出……这节必看。

✅ **正例（难点在句子里戳破，难度用笔墨轻重体现）**
> 接下来是最容易被想当然的一环：那份加密内容到底在哪儿生成、以什么形态躺在文件里。
> 新手往往只停在"它被加密了所以看不懂"，但真正的关窍在于——它不是事后才加密的一坨密文，
> 而是在压缩那一刻就把结构化信息整个封了进去，所以它承载的东西反而比人能写下的明文摘要更多。
> （这一段值得慢慢看，是理解整套机制的命脉；相比之下后面的缓存策略只是工程细节，扫一眼即可。）

## 四、比喻库（按场景取用，记得跨节换；用时化进句子，别挂"费曼比喻"标签）

| 要解释的东西 | 可用比喻 |
|------|---------|
| 资源被占满 / 阈值触发 | 油箱见底要加油、杯子满了要倒 |
| 信息压缩有损 | 复印件的复印件、传话游戏 |
| 加密 blob 承载结构化信息 | 保险箱 + 钥匙、密码箱 |
| 明文摘要信息量受限 | 便利贴、一页纸会议纪要 |
| 多条路径分流 | 三家搬家公司、岔路口选道 |
| 同样配方不同效果 | 两家米其林同一菜谱，厨房不同 |
| 多层防御叠加 | 神庙的柱子 + 地基、洋葱的层 |
| 缓存命中 vs 失效 | 印刷厂排好版只加印 vs 改中间一页全重排 |
| 系统每轮重建上下文 | 装修开会每次重新拿出资质证和规范 |
| 任务中途无缝处理 | 高速上的移动加油车，不停车加油 |
| 固定成本不重复计 | 折旧记账，固定资产不算本期增量 |
| 模型与工具链绑定 | 特定钥匙配特定锁、原装配件 vs 副厂件 |

> 用法：一节内可以用「一个延展比喻」贯穿（如三家搬家公司对应三条路径），
> 但下一节务必换场景，避免读者审美疲劳。

## 五、常见翻车点（自查）

1. **脚手架外露**（头号翻车）：把「💭 费曼比喻：」「🤔 难理解点在哪？」「要点 X」「【P0】」
   「费曼检验：」印在成品上。这些是施工工具，交付前必须拆掉，让行文自己流畅。
2. **比喻只当装饰**：比喻必须能推出结论，否则就是凑数。问自己「读者顺着这个比喻能不能自己想明白机制」。
3. **难点写成废话**：「这个比较难」← 无效。要具体到「新手会误以为 X，其实是 Y」，且写进正文句子。
4. **全程一个比喻**：开车从头用到尾，读者会腻。一节一换。
5. **收口偷懒**：只写「综上所述」，没把整条链复述成一句话。
6. **假装懂**：资料没讲清的地方强行编一个解释。宁可说「这是黑盒，作者给了几个假设」。
7. **平铺成并列块**：把主题切成互不咬合的几段，抽掉任何一段其他段照样成立——那是清单不是链。
8. **该上表不上表**：三方对比硬写成三段话，读者得自己脑补对照。

## 六、最小可用模板（简单主题，逻辑链 3 节版）

> ⚠️ 双重注意：①下面三节**不是三个并列要点**，而是一条链——第 2 节回答第 1 节抛出的疑问，
> 第 3 节又深入第 2 节留下的新问题；②模板里的方括号是**给我看的施工提示**，成品里**不出现**
> 「先问/于是/但是」这些词当标题，也不出现任何比喻/难点标签，全部化成流畅行文。

```
[开场] 用大白话讲清问题 + 一个总比喻领进门 + 抛出全文要追的核心问题

[第 1 节：制造张力] 标题是有信息量的短语/问句（不是"先问"）
  正文讲清"朴素做法是什么、为什么不够用"，读者以为简单其实有个坎，
  比喻自然嵌在句子里，段末自然勾出"那真正的做法怎么绕过这个坎？"

[第 2 节：给出机制] 标题同样有内容（不是"于是"）
  接住上一节的疑问，讲清真正的机制怎么运作，换一个新场景的比喻，
  段末自然带出"可这么做又冒出一个反直觉的地方……"

[第 3 节：深入 + 收口] 标题有内容（不是"但是/所以"）
  在正文里戳破新手误区，讲清关键细节，再换一个比喻，把链闭合

[结尾] 用一两句话复述整条链（因为 A 不行，所以 B，代价是 C）。
  内容复杂时才补一张总览表或一句口诀收尾。
```

### 反例：同一主题写成并列要点 + 挂标签（双重禁止）

❌ 这样写全错——既是并列块（抽掉任一条其他照样成立），又把脚手架挂了出来：
```
XX 有三个特点：
## 要点 1：它很快
💭 费曼比喻：像跑车
## 要点 2：它很省内存
## 要点 3：它支持并发
```
✅ 应该写成一条链、且脚手架内化：先讲一个"慢/占内存"的真实痛点，说明为什么绕不过；
于是它用了什么机制把速度提上来，这个机制像什么（比喻嵌进句子）；但提速是有代价的，
它在内存和并发上做了什么取舍；所以它最终落在一个什么样的平衡点上。全程无标签，一段接一段。
