# 卡片格式与机会分 rubric

技术名词保留英文原词。每条卡片严格三行，不要把判断挤进第一行。

## 单条卡片

```
**[加粗标题](链接)**｜是什么：1–2 句客观事实，包含关键数字。
【我的判断】为什么重要 / 和读者有什么关系 / 对读者的工作或系统有什么可行动的启发。1–2 句，要有观点，不复述事实；关键结论加粗。
【机会分】⭐N：一句给分或扣分理由，锚定"对读者有没有用"。
来源 · 时间
```

## 机会分 rubric（锚定读者，不是新闻热度）

- **⭐5**：与读者当前的系统/工作直接相关，本周就该动手、安装或深读。
- **⭐4**：高度相关，值得安排时间看或纳入对照实验。
- **⭐3**：知道即可，是趋势佐证或备用素材。
- **⭐1–2**：干脆不收。

打分必须带一句理由（为什么是这个分）。读者画像从 `config.reader` 读，换读者后同一新闻的分可以完全不同。

## GitHub / 工具类条目的额外要求

判断里必须具体回答三件事，否则视为不合格：
1. **该不该用**（现在装 / 只读源码借鉴 / 观望 / 无增量）。
2. **怎么接入**读者自己的工作流或系统（作为技能依赖、vendored 后魔改、还是只借某个机制）。
3. **增量价值是什么**；没有增量就明说"无增量"。

## 周复盘（weekly GitHub Trending）

- 只在 `config.weekly_recap_weekday` 那天出现，独立一组「🐙 本周 GitHub Trending 复盘」。
- 覆盖整周，5–8 条，按"本周新增 star + 与读者相关度"综合排序。
- 每条：项目名+链接、本周新增 star、解决什么真实问题、接入建议。新增 star 必须来自脚本真实解析，拿不到要标注。

## 顶部与尾部

- 顶部「⚡ 今日最值得看的 3 条」：各一句说清为什么重要。
- 没有料的组：`今日无值得报的。`
- 文末固定：`对哪条感兴趣，回我编号或名字，我接着深挖。`
- 文末附：3 条头条一句话、文档链接、各渠道真实获取状态（含 X 走的哪一档、是否成功）。

最终用 `scripts/render_brief.py` 渲染，保证版式每天一致；输入结构见 `examples/brief_input.example.json`。
