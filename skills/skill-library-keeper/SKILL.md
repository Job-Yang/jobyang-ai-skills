# 技能管家 · 把"技能集合"当成一个可迁移系统来治理

> **它管什么：** 站在整个技能库视角回答五件事——要不要加新技能、加了放哪跟谁配合、现有集合是否健康、既有技能是否拖慢强模型或互相打架、中立路由下会不会漏触或互抢。
> **它不管什么：** 不替你写单个技能正文（把关后交 skill-creator 类技能落地）；不执行同步分发（由库的同步脚本负责）；默认只管用户自有技能集合，范围由参数决定、不写死目录。
> **边界提醒：** 读或解读外部 GitHub 仓库、论文或提示词实践，即使对象本身是如何写技能，研究外部资料仍归 `feynman-explainer`；本技能仅在动作对象是「你自己这套已安装技能集合」时启用。

## 零环境依赖原则（本技能自己也要遵守）

- **库位置可发现、不写死：** 按用户显式给出 ＞ 当前目录或上级中第一个含多个 `<name>/SKILL.md` 的目录 ＞ 宿主约定目录的顺序发现；代码不内置绝对路径、用户名或平台名，宿主外部技能通过 `--external-skills` 传入。
- **平台能力只作可选增强：** 宿主具备检索、脚本或文档能力时可调用；缺失时照常产出判断与体检报告。
- **可迁移性是硬要求：** 强绑定特定平台的技能须先去绑定或拒绝收录。

## 五条主线

### A. 准入：要不要新增一个技能

完整判据与范例按需见 `references/admission-gate.md`，五问全过才建：

1. **需求成立吗：** 高频反复的痛，或低频高重要且长期无解。
2. **该归因到哪一层：** 模型能力、Harness 常驻规则、确定性脚本，还是技能方法层。
3. **现成方案能不能用：** 能直接用不重造；有绑定可炼化；证实硬伤才自研。
4. **值得独立且不打架吗：** 一句话唯一，放进图谱看是否抢触发或与邻居规则互斥。
5. **能持续与适时退场吗：** 先定可观测判据与回归回路，并在模型升级时复审退场。

任意一问答否，说明理由并给出已有承接方。

### B. 健康体检：结构合规、双模阻力与跨技能冲突

完整规则目录与 P3 语义清单按需见 `references/health-check.md`（先跑脚本再补人工与真实 query 验证）：

```bash
python3 scripts/test_doctor.py                                           # 先证尺子本身有效
python3 scripts/library_doctor.py <技能库目录>                            # 全量扫描（含 B/X 双模与冲突线索）
python3 scripts/library_doctor.py <目录> --strict                        # 把 mid 级阻塞也纳入非零退出
python3 scripts/library_doctor.py <目录> --baseline baseline.json        # 只报基线外新增问题
```

静态与文本线索聚焦七类问题（`F/D/R/P/S/C/B/X`）：

- **基础合约（`F/D/R/P/S/C`）：** frontmatter 与路由信号、断链与围栏闭合、平台硬绑定与硬编码密钥、正文超长与真孤儿文件、悬空交接（`C001`）与覆盖真空（`C003`）。
- **强弱双模预算与拐杖（`B001`–`B005`）：** 单条及全库 `description` 总字符是否挤压索引、隐形前置必读总行数是否过胖、机械算术与禁止内部思考等弱模型拐杖、运行时正文是否泄露维护说明或版本考古。
- **跨技能耦合与规则打架（`X001`–`X004`）：** `≥3` 跳串联或单向豁免、相连或并行技能在小标题体例/翻案句型/机理顺序上的互斥、同技能内部自相矛盾、近全域触发缺排除边界。

### C. 收录与炼化外部技能

- **直接用：** 质量达标、可迁移且不撞车时直接登记引用。
- **炼化：** 内核优秀但绑定特定平台时，剥离宿主依赖、改成中性降级，并过准入第 4、5 问。
- **重造：** 评测证实硬伤时先记明根因再自研。

### D. 减负与退场：强模型无阻力、弱模型有强化

完整四层分层法、双模验证与唯一主责协议按需见 `references/dual-model-design.md`：

- **四层物理拆解：** 确定性校验下沉 `L1` 脚本，高杠杆原则与品味留 `L2` 主干，详尽示范下沉 `L3` 按需 `references/`（不作起手必读税），纯属历史补丁的 `L4` 机械算术与元话语直接删除。
- **冲突唯一主责：** 上游主导文体定骨架、小标题与修辞；下游清洗只管保真与去 AI 味，不反向推翻上游体例；例外豁免须双向写明。

### E. 动态路由盲测（活卷体检 + 真实翻车回归）

只存考纲与真实翻车池，不固化 AI 死题库；做路由盲测时按需见 `references/routing-eval.md`：

```bash
python3 scripts/test_route_eval.py                                          # 先证尺子有效
python3 scripts/route_eval.py blueprint <技能库目录> --shuffle --out-catalog /tmp/cat.json --out-blueprint /tmp/bp.json
python3 scripts/route_eval.py audit <活卷.jsonl> <技能库目录> --strict --export-blind /tmp/blind.jsonl
python3 scripts/route_eval.py score <活卷.jsonl> <pred1.jsonl> [pred2.jsonl ...] --root <技能库目录>
```

只报漏触、边界互抢（`forbidden`）、轻任务误触（`NONE`）与多轮抖动警报，不打综合总分；改完技能描述后须用新随机序与全新口语活卷复验。

## 标准工作流

1. 确定技能库根目录（发现或传参）与本次主线（`A / B / C / D / E`）。
2. `B / D` 体检与减负先跑 `library_doctor.py`，再结合 `health-check.md` P3 清单与 `dual-model-design.md` 判断强弱两端影响；`E` 路由盲测按 `routing-eval.md` 跑活卷双模盲测并回归真实翻车集。
3. 产出「问题/结论 → 文件字段证据 → 具体动作（保留/下沉/合并/减负/退场）」；不擅自修改他人或范围外技能，由用户拍板后交对应责任技能或作者落地。
4. 库结构变动后提示运行库内同步脚本与图谱更新。

## 交付底线

- 根目录可发现，外部技能名单可传参，不写死宿主路径。
- 体检报告同时关注「少写漏防」与「过重拖慢强模型 / 规则互搏」两端。
- 不越权改文件，只给出带证据的最小高收益改造建议。
