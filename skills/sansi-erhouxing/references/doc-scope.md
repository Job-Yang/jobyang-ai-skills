# 文档场景:骨架先立,内容后填,过渡最后加

主文件把「骨架优先」提了,这里展开。文档改动最容易犯的病:过度设计一节把整篇改得面目全非、或者硬插一段跟前后不通气。根子都是没通读骨架。

---

## 骨架的定义

骨架 = 每一节一句话观点的清单。不是标题清单,是**观点清单**。标题是形式,观点才是骨头。

判据:把每节标题换成一句陈述句,能立住吗?串起来读一遍,承启顺不顺?

**反例**:
- 骨架:「一、背景 / 二、方案 / 三、实施 / 四、总结」——这不是骨架,是空模板。
- 真骨架:「一、这个问题一直没解决 / 二、根子在 X / 三、我们改成 Y,分三步走 / 四、这样就解决了原问题,还顺带解决了 Z」——每节都是一句能立住的陈述。

---

## 骨架优先的四步

### 列骨架

写文档前,先把每节一句话观点列出来,不是标题,是陈述句。例:

```
1. 局部改动是通病,一改一处就顾不上全篇。
2. 业界有四条成熟思路,但没打包成流程。
3. 我们打包成三步硬约束:通读 → 影响面 → 三问。
4. 三步各自的产物、豁免条件。
5. 反模式清单。
```

### 顺骨架

列完念一遍。问三个问题:

1. 每节的观点能不能立住?立不住 = 空模板,重写这节。
2. 相邻两节之间有承启关系吗?前一节的结尾能自然引出下一节的开头吗。
3. 有没有一节是"凑数"的?删掉主线还立得住?立得住 = 那节是废段。

顺不了 → 停在骨架层重来,别急着写内容。骨架不顺,内容再花哨也是补丁。

### 填内容

骨架顺了,再动笔。每一节内容展开,服务本节那一句观点。跑偏 = 内容和骨架不匹配,回骨架重看。

### 加过渡

内容都填完,最后一遍读全文,加过渡句。过渡句就一件事:让下一节的开头能承接上一节的结尾。

---

## 没指定改哪儿,更要先抽骨架

用户只丢一句「改一下」「优化一下」「通篇顺一顺」,没指任何具体位置。这时候最容易犯的错:从第一段起逐句抠措辞,越抠越细。局部每句都顺了,全局的病一个没治——论据放错了节、结论接不住主干、某节根本立不住,这些逐句读永远读不出来,一抽骨架就现形。

没有改动点,恰恰是全局视角最该上场的时候。动作还是骨架那一套,只是这回目标不是新写,是体检一篇已成稿:

1. **抽主干**:每节压成一句话观点,列出骨架(见前面「骨架的定义」)。
2. **顺承接**:相邻两节接不接得上(用前面「顺骨架」那三问)。
3. **查论据归位**:每节的论据,真在撑本节那句观点吗?有没有哪段其实在讲别节的事、被塞错了地方?
4. **查骨架闭合**:结论那节,兜住了前面所有主干吗?有没有前文没立过的点,到结论突然冒出来当解药?

**体检查出来的问题,直接就是改稿清单**:承接断了 → 补过渡或调顺序;论据放错节 → 论据归位;某节立不住 → 重写或删;结论收不全 → 补齐或收窄。每动一处,照样走三问(这处历史上动过吗、改法风险大不大、会不会把骨架越改越散)。

**例**:一篇《文档为什么没人看》,②讲"没想读者",却把"半年没更新、截图旧、照着做对不上"这段塞了进来——这段其实是独立原因"文档过时"。④的解药"建更新机制治过时"就是顺着这段误塞开的,可"过时"在骨架里根本没立过。结果摆了 A(没想读者)、B(太长)两个原因,末尾却只治 C(过时),A、B 全落空。逐句读挑不出,抽骨架一眼就看见:论据归位 + 结论补齐,病才治得了。

跟有明确改动点的场景就差一个方向:有改动点是「别乱动,看清这处牵连谁再动」;没改动点是「主动找哪几处该动」。但都得先有骨架,没骨架就下笔,不管哪种都是补丁。

## 改文档一节的规矩

任何一节改动完,都要回骨架重扫一遍,问:

1. 这节的观点变了吗?变了就得改骨架清单里对应那句。
2. 骨架清单改了后,前后两节的承启还立得住吗?
3. 立不住 → 要么调整前后两节,要么放弃这次改动。

**反例**:改文档第三节,加了一大段跟第四节强相关的内容。第四节没同步 → 现在第三、第四节讲的东西大量重叠,读者读到第四节觉得"这不是刚说过吗"。根子是改第三节时没回骨架看第四节。

---

## 新增章节的规矩

用户说「加一节 X」。别急着写这一节的内容,先做:

1. **看骨架**:X 应该放在哪个位置?插在哪两节之间?
2. **看承启**:插进去后,前一节结尾还能承下 X 吗?X 结尾还能引出下一节开头吗?
3. **看重叠**:X 讲的东西,已有章节里覆盖过吗?
   - 覆盖过 → 别新加,改那一节。
   - 部分覆盖 → 决定是合并还是拆得更清楚。
   - 完全没覆盖 → 才新加。

只有骨架能容纳 X,才开始写 X 的内容。挂末尾的新增 = 补丁。

---

## 过度设计一节的病

用户说「第三节这一段有点问题」。常见错误反应:把第三节整个重写,越写越长,越写越花,把原本简洁的一节改成一大坨。

**正解**:

1. 先明确问题到底是"这一句表达不清"还是"这一节的观点站不住"。
2. 前者 → 只改那一句,不动其他。
3. 后者 → 回骨架重看,这一节的观点在整篇骨架里还立得住吗?
   - 立得住 → 只需微调,别过度设计。
   - 立不住 → 骨架层面调整,不是内容层面的过度加工。

改动的大小要匹配问题的大小。小问题大改 = 补丁引入更多补丁。

---

## 反模式清单(文档场景)

- **改一节不看前后节**:改完前后节内容重叠或断裂。
- **新增章节挂末尾**:骨架里没这节的位置,硬挂。
- **过度重写**:一句话问题,改了一大段。
- **凑字数式过渡**:「综上所述」「由此可见」这些不是过渡,是废话。
- **只顺文字不抽骨架**:说"优化一下"就逐句润色,论据放错节、结论收不全这类骨架病全漏掉。
- **骨架和内容不匹配**:骨架说 A,内容写 B,靠"看似相关"糊过去。

---

## 一行 checklist(动手前对着念)

- [ ] 全文通读了吗?
- [ ] 骨架(每节一句话观点)列出来了吗?
- [ ] 要改的点在骨架里的位置知道吗?
- [ ] 相邻两节的承启看过了吗?
- [ ] 我的改动会不会让骨架某处失衡?
- [ ] 改完要不要更新骨架清单?
