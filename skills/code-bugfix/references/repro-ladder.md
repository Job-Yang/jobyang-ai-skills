# 复现回路与二分梯队（按需查阅）

> 排障前先建一条「红灯=缺陷还在、绿灯=修好了」的秒级确定性回路；按成本从低到高选择工具。

## 1. 十级复现工具梯队

1. **单元测试接缝**：直接卡在能触发缺陷的最窄函数/模块边界跑单测。
2. **HTTP 轻量脚本**：用 `curl` + `jq` 针对运行中服务验证响应状态码或关键 JSON 字段。
3. **CLI 夹具对比**：喂固定输入对比 `stdout` 与预期快照的差异。
4. **无头浏览器脚本**：断言 DOM 状态、控制台报错或真实网络请求响应。
5. **真实请求/事件重放**：把抓包 payload 或事件序列脱敏保存后独立重放。
6. **最小 Throwaway Harness**：剥离周边无关组件，在内存/临时目录中用最小替身跑通故障链。
7. **属性与压力循环**：针对偶现错乱做随机种子回归或并发连跑统计失败频次。
8. **临时 Worktree 二分（Bisect）**：定位何时开始退化。
9. **新旧双跑比对（Differential）**：同一输入先后喂给旧逻辑与新逻辑并 diff 输出。
10. **人机协同探针（兜底）**：仅当缺少真机/私有态无法自动触发时，给用户清晰脚本步骤采集脱敏输出回传。

## 2. 偶现（Flaky）问题放大准则

- 目标是 **2 秒级确定性回路**，而非 30 秒看天吃饭的偶现脚本。
- 通过提高并发、去掉无关耗时步骤、缩小竞态窗口或循环 `50` 次计数，把 `1%` 偶现拉高到 `≥ 50%` 可稳定观测后再动代码。

## 3. 安全二分操作规范（绝不破坏脏工作树）

先检查 `git status --short --branch`；只要工作树有任何未提交改动，绝不在当前目录直接 `git bisect`（防止切换提交丢失或污染现场），统一在临时 detached worktree 执行：

```bash
git worktree add --detach "${TMPDIR:-/tmp}/bisect-wt" HEAD
# 进入临时工作树运行 git bisect start <bad> <good> 与 git bisect run ./repro.sh
# 查出 culprit 后仔细阅读该提交全量 diff，最后移除临时工作树：
git worktree remove --force "${TMPDIR:-/tmp}/bisect-wt"
```

若回归点仅在最近几次提交内，先直接读 `git diff <good>..HEAD -- <suspect path>`，往往能跳过整轮二分直接定位。

## 4. 多人大仓最小影响面校验

- 优先运行故障所属包/子模块的单测、类型检查及直接上游调用方测试，避免冷启动耗时数十分钟的全仓构建拖垮排障节奏。
- 若发现本地通过而 CI 失败，先逐项比对运行时版本、环境变量、时区与工作目录，不盲猜业务代码。
