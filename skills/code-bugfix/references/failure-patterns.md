# 常见排障陷阱模式（按需查阅）

> 遇到「首修无效」「现象与代码看似对不上」或典型运行时/跨环境坑时查阅本表。

## 1. 高频陷阱速查表

| 现象 | 常见坑根因 | 正确排查动作 |
| --- | --- | --- |
| 改了源码但运行行为还是旧的 | 命中旧构建产物、脚本包装层（PATH shim）或过期工具缓存 | 先核对实际被执行二进制/脚本路径及包内产物，清理缓存后重跑 |
| 改对了某处但同症状还在 | 同类 surface 复制了多份，改到了未渲染/未生效那份 | 从真实渲染画面或入口调用栈反向追溯，找实际执行的那份代码 |
| 本地能过但双端/CI 报错 | 环境差异（工作目录、环境变量、时区、沙箱能力或冷启动顺序） | 补全冷启动、拖入文件、deeplink 或非默认 cwd 入口复现并对齐环境 |
| 切换主题/语言/模式后出错，重启恢复 | 状态未随开关重算，或 Reader 读到了未版本化的旧持久化缓存 | 沿切换事件追重算链；改结构时同步升级或失效旧缓存版本号 |
| 「慢」或看门狗频繁误杀健康任务 | 缺基准量化指标，或超时阈值按本地快路径拍脑袋定太死 | 先测慢速健康场景基线，改用真实活跃探针（增长文件/心跳）替固定死等 |
| 明明有权限差异却不报错，数据错一半 | API 对无权对象静默返回 0/空值并当正常展示 | 对比有权与无权主体各自的成功计数，找跨主体统一数据源 |
| 预览/dry-run 和实际执行范围不一致 | 两边各自写了一套过滤谓词 | 抽取同一套纯过滤函数作为预览、统计与执行的单一事实源 |
| 修复/自愈脚本一直走不通 | 修复前置条件依赖那个刚好丢失或损坏的文件本身 | 检查每条恢复命令前置条件在故障态下是否成立，逐条验证可执行路径 |
| 按展示文本比较总判错或版本更新死循环 | 用自由格式展示文案（本地化标签/URL 尾段）替代稳定机读 ID | 改用内容 hash、构建号或唯一 ID 比对，统一修复所有渠道 |
| 子进程卡死在大数据输入输出上 | `stdout/stderr` 管道缓冲区写满而父进程死等 `wait()`，或子进程等 TTY stdin | 流式读写管道或重定向到临时文件；显式关闭/隔离非交互 `stdin` |
| 取消/超时被当作正常业务失败或成功 | `SIGINT`/`SIGTERM`/超时未独立分类，临时文件与锁未清理 | 将中断态独立归类，并在回归测试中断言中断后临时文件与状态一致性 |

## 2. 排障反合理化红线

- 「我很有把握这次对了」 → 不算数，运行探针拿实际输出。
- 「应该和刚才那个是同一个问题」 → 先重读执行路径确认，不合并猜想。
- 「我本机是好的」 → 逐项列出环境差异，通过差异点复现。
- 记住：**「用户观测现象」与「日志显示一切正常」冲突时，永远相信观测现象——中间必有一条未埋点的真实路径。**
