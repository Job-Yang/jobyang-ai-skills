# Code Bugfix · 红灯驱动根因修复

先证明怎么复现，再动手修根因；绝不对着症状瞎贴补丁。

> **顶部硬底线（每轮必守）：** ① 「先别改代码/排查」仅出诊断报告、不输出业务代码补丁；② 所有真实密钥/token 在日志、命令、括注与正文对照中一律替换为 `<REDACTED>`（不回显明文原串）；③ 固定先给秒级确定性红灯复现命令 + **至少 `3` 个排序假设**与证伪探针，最后附红→绿回归测试与全仓同类清扫（Sibling Sweep）。

## 1. 授权边界与隐私脱敏

- **区分只查与可改**：用户问「为什么 / 排查 / 看看 / 定位」时只输出诊断报告，不改业务代码；仅当用户明确要求「修 / 改 / 修复 / 解决」或延续同一修 Bug 任务时才动产品代码，且绝不越权 push 或运行破坏性操作。
- **凭证脱敏**：所有命令、抓包与报错摘录中的密钥、token、口令统一替换为 `<REDACTED>`，复现脚本优先读环境变量。
- **现行事实优先**：记忆与旧备注只是线索，当前源码、运行日志和真实复现结果永远推翻旧猜想；多仓与工程目录规则按需查阅 [工程工作区契约](references/engineering-workspace.md)。

## 2. 七步红灯工作流（未过第 4 步不动业务代码）

1. **建秒级红灯复现回路**：在读取大段源码猜原因前，先搭出稳定触发该缺陷、退出码可判别、耗时秒级的复现命令；完整工具梯队与临时 worktree 二分法按需查阅 [复现回路与二分梯队](references/repro-ladder.md)。若完全无法构建复现路径，停下来列明已尝试项并向用户索要复现环境或脱敏样本。
2. **复现并最小化输入**：压缩触发用例到最小自包含输入；遇到偶现（flaky）问题，通过并发/循环/缩小时间窗口把复现率拉高（记录 `N` 次中失败 `M` 次），拒绝拿单次碰运气当作稳定复现。
3. **列 3–5 个排序假设**：基于当前证据列出最可能的 3–5 个候选根因并按概率排序。
4. **探针证伪锁定唯一根因**：用最小探针、断点日志或对照实验逐个排除假设，直到剩下唯一可证实根因，并用一句话说清「哪个文件哪一行在什么条件下出错」。
   - **三假设停损红线**：3 个假设全部证伪，或修完后原症状依旧，立刻停止猜测，按交接清单（症状、已排除假设及证据、当前收集的日志与环境差异、缺失的权限/上下文）向用户汇报停手。
   - **三次调数红线**：同一魔法数字或延时调到第 3 次仍出问题，说明结构或契约错误，停手改用具名 token 并找缺失约束。
5. **修复根因并锁入回归测试**：改动最小精确根因；为该缺陷补一条「改前确认跑红、改后跑绿」的自动化回归测试（若无测试接缝，在报告中说明原因）。
6. **全仓同类清扫（Sibling Sweep）**：用 `rg` 搜索仓库内相同错误形态或被绕过的同类入口；授权范围内直接补修，跨模块或风险未知处列出清单供确认。
7. **真实运行态验证并交付**：跑通对应模块测试与真实入口验证，遇到持续卡壳或运行时态异常时按需查阅 [常见排障陷阱模式](references/failure-patterns.md)。

## 3. 交付结果卡片

首行说明结论与改动是否已本地提交（或未提交），随后附固定结构汇总：

- **Root cause**：出错原因与精确 `file:line`；
- **Fix**：修改位置与根因改动说明；
- **Loop & Regression guard**：红→绿复现命令与对应回归测试位置；
- **Tests & Sibling sweep**：实际运行的测试范围、通过/失败数、同类清扫数量及结果；
- **Status**：`resolved` / `resolved with caveats`（写明受限未覆盖范围）/ `blocked`。
