# 常见高危审查模式（按需查阅）

> 仅当 diff 命中对应代码形态时按节查阅；能 Reach 用户或生产数据的缺陷为硬阻塞，其余作改进建议。

## 1. 反复出现的布局、时序或状态缺陷

- 若 diff 靠微调魔法常量（像素偏移、延时、阈值）修补复发缺陷，改为把判定逻辑抽成纯函数，针对被打破的不变量（如非零宽度、半开区间、有界偏移）补单测。
- 检查是否出现「只能绕过真实调用方去测一个浅助手」的 `no correct test seam` 缺陷；对直接删文件、提权或执行外部命令等危险原语，建议补调用点全扫描测试限制只走白名单包装。

## 2. 异步完成信号与捕获输出

- **禁止猜固定延时**：排查 diff 中用 `sleep`、`setTimeout`、`asyncAfter` 或帧数等待代替真实完成信号（回调、状态标志、导航完成、进程退出码）的写法。
- **结构化信号优先**：若代码靠解析错误文本或 stdout 分支处理，核实真实运行期日志是否被继承的 stdio 吞掉或仅含命令行字符串，优先改为判断退出码、错误枚举或已知对象状态。

## 3. 简化与删除归类

- 删减规范、文案或技能规则时，逐条回读被删行为并归类为「已合并进 X / 与 Y 冗余 / 能力已移除」，不拿「删得多」当好改动的证明。
- 宣称清理死代码时，需确认检索覆盖动态派发表、构建脚本、CI 配置、分发清单与文档引用，仅靠局部搜索不足以证明安全可删。

## 4. 历史敏感恢复与去重归一化

- 恢复曾被删除的符号、枚举、配置项或本地化键值时，确认当前主链仍在真正消费它，而不只是被某个兼容测试或过时规则引用。
- 把某条特殊分支「拉齐」兄弟分支前，追查当年引入该差异的提交或注释，避免把刻意绕过已知故障的保护逻辑顺手抹平。

## 5. 非原子覆写用户文件

- 凡涉及写入已有用户文件（如直接打开截断写入、重定向、`curl -o`），核查中途断网、超时或进程被 `SIGINT` 中断后是否留下半截损坏文件且丢失原件。
- 要求先写入同目录临时文件、完成后再原子重命名覆盖，并配置异常清理避免残留孤儿临时文件，不静默吞掉非零退出码。

## 6. 宽泛销毁匹配与安全汇

- 对递归删除、批量清理、通配符匹配或正则兜底分支，逐项核查：主分支与兜底分支是否都收窄到精确 ID 或规范化真实路径（防 symlink 逃逸与跨目录误删）、保护路径清单是否生效、校验防线是否写在删除原语内部而非只写在某一个调用点上。

## 7. 重复派生规则（多处各自算一遍）

- 当同一份分类、排序、阈值、资格判定或计数逻辑同时出现在预览与执行、摘要与列表、打分与解释、前端展示与后端门禁两处时，标记为高漂移风险，要求收拢到单一常量或纯函数。

## 8. 测试表面保真与虚幻测试

- 核对新测试是否真的在执行生产入口、在旧代码上是否真正跑出红灯；更新过的快照本身不等于新输出正确。
- 警惕「盲点断言」（仅过滤带特定标签的对象而放过漏标对象）与「过脆断言」（写死精确报错文案或切片位置导致正常改写即假红），应当锚定行为事实、唯一 ID 或结构不变量。

## 9. 尚未发布的迁移脚手架

- 若新功能、新配置键或新 Schema 仅存在于当前未合入分支（对比最新正式发布标签并不存在），却写了一套旧键兼容迁移与版本判定代码，直接标为死复杂度建议删掉。

## 10. 未知标识符与依赖锁文件漂移

- diff 中新引用的函数、配置键、命令或静态资源路径，若在本仓库扩散搜索无出处即属未验证依赖。
- 变更依赖清单或锁文件时，核对两件事：全文件反序列化是否意外破坏非 ASCII 字符或重排字段；对于安全升级类 PR，用依赖树检查该包是否真正编入交付产物，避免对仅存在于锁文件里的惰性条目过度报警。若存在版本钉死（pin），先用 `git log -S` 查明当年钉死的原因再决定是否动。
