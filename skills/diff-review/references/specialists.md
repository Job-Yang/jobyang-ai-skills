# 专家视角、Deep 对抗与怀疑论证伪（按需查阅）

> 仅在 `Standard` 或 `Deep` 档位按需加载；所有 HIGH/CRITICAL 发现进入正式报告前必须走完第 4 节证伪步骤。

## 1. 安全专家视角（碰外部输入、鉴权、凭证、CI 或路径拼接时激活）

- **注入路径**：追踪所有不可信输入到 SQL、Shell、文件路径、`eval` 或模板渲染汇的链路，核查参数化与规范化位置（UI 校验不能替代服务端校验）。
- **鉴权与信任边界**：检查新路由或分支是否跳过身份核验、权限检查是否放在敏感操作之后、是否把客户端/LLM/外部响应字段直接当作可信身份。
- **凭证泄露**：检查硬编码密钥、写进日志/错误消息的 token 或含敏感字段的环境变量打印。
- **CI 与发布工作流安全**：核查写权限 Job 是否缺少细粒度 `permissions`、第三方 Action 是否未钉死 commit SHA、或把 `github.event.*` / `inputs.*` 直接插值进 `run:` 脚本（未先经 `env:` 与格式校验）。

*跳过范围*：纯文案、纯样式、纯文档与纯单测改动不激活。

## 2. 架构专家视角（碰模块边界、公开签名、跨模块依赖或主锁时激活）

- **跨层耦合与方向倒置**：核查核心领域层是否反向导入框架、UI 或具体基础设施客户端，原本可独立演进的模块是否新增隐式共享状态。
- **公开契约与抽象泄漏**：检查导出类型、API 字段、位置参数顺序改变是否无兼容路径，或把数据库原始行、内部实现结构体直接暴露在公共接口上。
- **新引入的扩展瓶颈**：重点标记本次 diff **新引入**的单锁串行化、大表全扫、N+1 查询或跨事务长同步调用（已有陈旧瓶颈单列 `pre-existing`）。

*跳过范围*：单文件局部修补、样式微调与纯文档不激活。

## 3. Deep 级四角度对抗攻击（仅 `Deep` 档激活）

追问「如果我要专门通过这次 diff 把系统打挂，怎么做」，给每条对抗推演打置信度（`0–1`），低于 `0.60` 直接舍弃：

1. **假设违背**：代码隐含假定哪些格式、顺序、非空或取值范围永远成立，越界会怎样。
2. **并发与部分失败组合**：新代码在并发写入、重试乱序或外部服务半失败时，与既有代码拼在一起会怎样撕裂状态。
3. **合法操作级联坏状态**：一连串单步都合法的操作按特定顺序组合，能否把系统推进死锁、孤儿资源或永久卡死态。
4. **极端规模与发布期双写**：第 1,000 次请求、冷启动、滚动升级新老实例混跑或两人同时编辑同一资源时会发生什么。

## 4. Skeptic 独立证伪协议（降噪核心）

专家视角与对抗攻击容易基于命名和局部切片过度报警。任何 `HIGH` / `CRITICAL` 发现正式入表前，必须切换成「专职反驳它」的视角执行核查：

1. 重读引用处完整函数体及所有上游入口、中间件、类型约束与调用方保护代码。
2. 逐项排查：是否已被外层输入校验/事务边界/幂等键/框架默认行为彻底拦住？是否属于文档明确写定的预期取舍？是否为现实输入绝不可能触发的理论孤例？
3. **证伪成立即删或降级**：只要实际代码证明保护有效，立即删除该误报或降级为低优先级建议；保留下来的每条高危发现，必须把「为什么既有防线没拦住」写进正式证据栏。
