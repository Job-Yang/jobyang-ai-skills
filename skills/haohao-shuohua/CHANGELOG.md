# CHANGELOG

本技能的版本变更记录。日期为 Asia/Shanghai。

## 1.4.0 — 2026-11-03（minor：版式底线，给人看的字不写一大坨）

bad case：各写作技能成稿普遍是大段平铺，阅读成本高。本技能作为所有成稿的收尾层，原规则会顺手削掉上游的格式：满屏加粗允许「一处都不加」、第五层把条理清晰的列表当排比病、三项并列建议合并成一句；「条目和话」的豁免只给了技能自己的说明书。另外 description 写着「不替代各文体技能的内容主导」，「写个周报」「整理成文档」这类没有文体技能承接的说法无人负责内容。

改动：
- 新增 `references/reader-layout.md`：全写作技能共用的版式底线。内容形状 → 格式对照表、各文体单段上限与格式密度（技术方案 120 字、分享/调研/硬文 150 字、畅想 200 字）、清洗时保护格式的四条硬约束。
- `SKILL.md`：总纲加「先降阅读成本」；使用面新增「版式底线」；「条目和话」判据推广到成稿；第五层补「不误伤列表」；建议层加段落墙；自检加两问；description 改为没有文体技能承接时本技能直接起草并负责内容与版式。
- `references/symptom-dictionary.md`：满屏加粗豁免结构标签；A1、B4、逢三凑数区分「凑数」与「真并列」，真并列拆列表。
- `references/workflow.md`：三档都保护版式，标准档可拆段落墙。
- `scripts/quick_scan.py`：新增 `wall` 检查（超长段、引用块内超长段、纯段落连排；跳过代码块和 frontmatter），建议层不卡退出码，`--para-max`/`--run-max` 按文体调。新增 5 个测试，共 29 个，全绿。
- 三段宪法块一字未动，`check_integrity.py --expect` 哈希一致。

## 1.3.0 — 2026-10-31（minor：「给作者」提醒和出处核对不再漏进正文）

同事在 Codex 上做了一轮加载/消融实验：GPT-6 Astra 加载本技能时，12 条回答里有 7 条在正文后面跟了「以上仅依据……未做额外核验」这类免责尾巴，去掉技能后是 0/12；文档列出的 GPT-6.1 Terra 回答，开不开技能都没有这种话。两个模型在 Codex 里的系统提示词逐字相同，而且明令禁止主动加免责声明，所以问题出在技能本身：出处核对、正文后面附「给作者」提醒这两条规矩没说清边界，对技能指令更敏感的 Astra 把它们直接写进了要交出去的正文。

改动：
- `SKILL.md`「两种活」：新增「给作者」提醒的边界，只在原文或材料缺具体、原句有几种读法两种情况下写；单起一段，以「【给作者】」开头；作者给的材料直接当事实用，不加「没有核实」这类声明；原文里的「预计」「初步」「尚未核实」「还要看测试结果」照留，不确定的地方原文怎么说就怎么说，不再补一句；不替作者许原文没有的承诺，删掉以后正文到原文说到的地方就收住；这几条只管替作者写稿改稿，Agent 汇报自己干的活时测了什么、没测什么照实写，不算免责。「出稿」一步改为指向这条；出稿前自检加一问「正文能原样交出去吗」；交付硬闸的建议层加上免责声明一类。
- `references/workflow.md`：出处核对只进修改报告的「事实核对」一栏，不进正文；随手一段的提醒单起一段写。
- `references/symptom-dictionary.md`：结构级新增第 6 条「正文里的免责尾巴」，给判据和改法。
- `scripts/quick_scan.py`：新增 `disclaim` 检查，属建议层，默认不卡退出码，`--fail-on disclaim` 才卡；报告里标成「免责尾巴（原文有的照留）」，免得拿去删原文本来的限定。实验文档列出的 24 条回答里，同事标红的 5 条全部命中，其余 19 条零误报。
- `tests/test_lint.py`：新增正反用例各一组和 3 个测试，共 24 个，全绿。
- 三段宪法块一字未动，`check_integrity.py` 哈希不变。

## 1.2.0 — 2026-10-16（minor：定位明确为「AI 中文文本清洗」，覆盖写作之外的全部 AI 产出）

市场用户实际把它用在开发迭代里的模型回答、答复、汇报、总结上，而不只是写文章。这一版把定位从「中文写作清洗」摆正为「给任何 AI 产出的中文去 AI 味、优化表达」，写作是其中一大场景，不是全部。

改动：
- frontmatter `description` 重写：第一句即「给任何 AI 产出的中文去 AI 味」，显式列出模型回答、开发迭代答复、总结、汇报等场景和对应触发词（豆包技能列表会截断描述，定位必须在最前面）。
- `SKILL.md` 标题与开场、「使用面·默认常驻」改为表达规范口径，明确「模型直接吐出的中文也是清洗对象」。
- 只改定位与触发面的表述；四条原则、五条红线、三段底线条款一字未动（`check_integrity.py` 哈希不变），清洗行为与扩展点（自定义黑话库等）不受影响。
- 已自行修改本技能的用户：升级只涉及 SKILL.md 顶部文案与使用面第一条，你的自定义词表和其他改动按原扩展位置保留。

## 1.1.0 — 2026-10-16（minor：跨平台脚本化 + 单一事实源写死 + 对抗测试）

上一版 1.0.0 的四条零容忍里，半角标点那条一键命令用 `grep -P`，在 macOS BSD grep 上直接报 `invalid option -- P`，本就该"机器零误报"的硬闸在本机失效。这一版把它落成自带脚本。

新增：
- `scripts/quick_scan.py`（纯标准库）：跨平台扫半角标点（硬闸，退出码即门禁）、破折号串、B2 变体、元话语、章节机械编号；自动屏蔽围栏代码块/行内码/URL/链接/HTML 注释，英文词尾贴半角逗号故意不报以免误杀。`--checks` / `--fail-on` / `--quiet` 可控。
- `scripts/check_integrity.py`：校验 SKILL.md 三段宪法（底线条款）注释标记配对完整，逐段算 sha256，`--expect` 可钉住哈希，被改即非 0 退出。
- `tests/test_lint.py`：17 个用例，正反 fixture 齐全（含代码块/URL/数字/英文混排/繁体/嵌套引号的对抗反例），`python3 -m unittest tests.test_lint` 实跑全绿。

改动：
- `references/quick-scan-regex.md`：一键命令改为调用 `quick_scan.py` 为主，perl 单行与 Windows 说明作备选；`grep -P` 写法清除；新增"每条靠什么兑现（机检/人读）"表。
- `SKILL.md`：新增"何时读哪个 reference"导航；新增"规则分层与单一事实源"——作者改宪法、eval 只发 daily-learning、冲突以宪法为准、`check_integrity.py` 进场校验；交付硬闸改为真跑脚本。
- 作者全部中文写作方法论、四条原则、各条红线与底线条款一字未动（三段宪法块哈希逐版不变）。
