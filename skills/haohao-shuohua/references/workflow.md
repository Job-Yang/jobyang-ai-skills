# 成稿完整工作流(从主文件下沉，随手一段不需要看这页)

主文件的四条原则 + 速查够随手一段用。一般成稿(手记/周报)、对外成稿(硬文/对外文档)要走下面这套完整流程。**这里的每一条都是从原版主文件原样搬下来的铁规矩/判据，一条没减；后来补的只有两处：事实闸门的反向核对，第三段按力度三档分开写的约束。**

这页说的「随手一段 / 一般成稿 / 对外成稿」是按任务大小分，决定走多少流程；力度的「轻改 / 标准 / 重改」是按用户要改多狠分，决定动多大范围。两套不是一回事，别混。

---

## 五段主流程(一般成稿、对外成稿必走；随手一段并进心里做)

### 第一段：事实闸门(改前锁账本)

改任何一个字之前，先把**关系账本**列出来。账本 8 项：

- **数字**：所有数字、单位、比例、时间、人名。
- **命令 / 代码 / 术语 / 专有名词**：凡是引号、代码块、`code` 包住的、以及首字母大写的英文术语，视为不可修改的**受保护跨度**(protected span，详见 `protected-spans.md`)。
- **谓词方向**：「A 导致 B」不能变成「B 导致 A」;「A 大于 B」不能变成「A 小于 B」;「A 属于 B」不能变成「B 属于 A」。
- **效果类型**：上升 / 下降 / 不变 / 存在 / 消失，不许翻转。
- **关系类型**：因果 / 并列 / 转折 / 递进 / 让步，不许换。
- **模态**：「可能」「一定」「大概率」不许升级或降级。
- **硬机制描述**：「Q-K 点积加权求和」「反向传播」「AST 遍历」这类精确算法/机制描述，不许替换成比喻或简化说法。想加比喻，叠在机制后面(先给准确机制，再补比喻)，不许替换。
- **论文级证据**：「Kenneth Li 等在 Othello-GPT 里发现……(ICLR 2023)」这类可追溯的实验描述，作者/机构/年份/结论不许被简化成「有研究发现」「科学家表示」。

账本用几行清单记住(或写到暂存区)。改完最后一步逐条对回去。**任何一条对不上，该句作废，回去重改**。

**账本要双向对。** 上面 8 项查的是原文的东西在改写里有没有走样；反过来，改写里的每条信息也要在原文或上下文里找到出处。数字、时间、原因、场景、承诺、身份、经历，找不到出处的就是自己加的，删掉，缺的写进修改报告的「给作者」一栏。原文本来就含糊的地方，照原样含糊，别替作者挑一种说法。

### 第二段：症状库五层扫描 + 回译兜底

按 `symptom-dictionary.md` 逐层扫描，标注命中项：标点级 / 句式级 / 词汇级 / 结构级 / 结构排比级。

标注完密度先自检：**某段命中 > 5 处 → 该段整体不对，单点改不救，直接考虑整段重写；轻改档(用户点了「别大改」)改成整段列进删除清单**。

**回译测试兜底**：任何一句拿不准是不是 AI 味，默读一遍翻回英文。英文一次成型 → AI 味；英文别扭需要意译 → 中文。**注意**：回译是给人用的疑难句判定器，不逐句逐段跑，不当自动化流程的门槛(极简白话/技术议论中文本身回译也顺，别一刀切)。

**回译也管单个可疑词(借译词)**：碰到一个词读着别扭、又说不上哪儿不对，把这个词单独翻回英文。**一翻正好是个地道英文词、而中文另有更顺的现成说法 → 就是照着英文硬拼的借译词，换掉。** 典型 Bad Case:「死线」→ deadline，中文本来说「截止时间 / 最后期限 / 交稿日」。**边界(重要，防误伤)**：只测那些**读着就别扭、圈子外听不懂**的词。已经进日常、或计算机领域本来就这么叫的标准词——软件、硬件、进程、线程、指针、句柄——不测不动，它们没有更自然的替代。判据只有一条：**有没有一个更顺的现成中文能替？有才换，没有就留。**

### 第三段：按"改多狠 × 动多大范围"动刀

按上一段扫出来的密度和当前力度(轻改 / 标准 / 重改，用户没说就是标准)下刀：

- **减法下刀**(见 `symptom-dictionary.md`「下刀」节)：名词化→动词；后缀病→删或换；破折号→逗号/句号；前者后者→重复主语；长复合句→短句串珠。
- **加法自问**(见主文件「加中文味」几问 / `chinese-four-principles.md`)：动词扛住了没？有具体没？句子该补气口/拆开没？段末多话删了没？

**轻改(只换词，范围限在句内)的硬约束**：
- 不拆句，不擅自删整句。发现某句该删，记进**「建议删除清单」**，主流程末尾统一交作者定夺。
- 结构级重排(合并两段、拆分一段、调整章节顺序)必须先问，不许直接做。

**标准(默认，范围限在句段内)**：句子、段落全洗，多余的句子、段落可以删；结构级重排仍然必须先问，不许直接做。

**重改(范围放开到可动结构)**：结构级重排可自主做，但每次都要在修改报告里说明「原来是……，改后是……，因为……」。

**三档都一样**：每处改动都说得出治的是哪个毛病，说不出就放回原样；原文没有的信息一个字不加。

### 第四段：回读(对外成稿强制；一般成稿抽查)

改完不许直接交。分遍念，**三遍分开做，不许合并**(合并的结果就是「越改越顺、越顺越不像原稿」，最终跑题)：

- **第一遍 · 只对事实**：拿第一段的关系账本一条条对回去。**只查、不改结构、不查行文**。任何一条对不上，回第三段重改该处。
- **第二遍 · 只查残留 AI 味**：整篇再念一遍，只找漏网的五层症状。**发现问题只做局部替换，不许借机重写全文**，这步是收尾，不是再来一遍。**这一遍也把「改前逐字扫」再跑一次**(SKILL.md 四条零容忍 + `quick-scan-regex.md`)，看有没有改稿过程里新长出来的、或者第一遍漏掉的。手和眼是同一双，机器扫是这一层唯一的第二只眼。
- **第三遍 · 节奏终审**(对外成稿强制；一般成稿只跑憋气句)：按 `rhythm-check.md` 四个字面指标(憋气句/句长单调/软尾串/调子单一)粗筛标红，逐处念一遍定夺。**只补气口、只微调句式，不推向口语化，不拆好长句。** 误报(URL、排比、专名列表)放过。

**收尾一问(减法都查完再问一遍，不打分)**：这稿子除了「没病」，有没有一句是作者自己想说的、砸得下去的实话？一句都挑不出来 → 它还是白水汤，回加中文味几问补一记实的。**这一问只用来自问，绝不落成打分表、绝不拆成几个维度逐项评分**：分数是伪精确，还会引诱模型逢稿凑分，又造一套新公式。它只提醒一件事：查完病，还得往「好」上推一把。

### 第五段：主线反思(软性，不强制约束)

改完自己回读全文，回答三问，跟着修改报告一起给：

1. **主线是什么？** 一句话讲清整篇核心主张。讲不出来 → 主线已散，需作者定夺是否重来。
2. **每一节还在为它服务吗？** 逐节问「删掉这节，主线还立得住吗？立得住 → 这节是废段，标出来。」
3. **比改之前更清楚，还是更散？** 只跟改前比，不跟理想比。改后更散(常见于补丁摞补丁)→ 标出偏离点交作者，**不擅自回滚**。

**不当硬约束**：有时候作者就是想改结构、想让主线松一些，不能限死。这步只做提醒。

## 修改报告模板(一般成稿、对外成稿必给；随手一段不给)

```
【改后正文】
<改完的中文>

【事实核对】
- 关系账本 N 条,全部对齐 ✓
- 反向核对:改写里的信息都能在原文或上下文找到出处 ✓
(如有对不上,说明该处未改动或回退原状)

【本次动刀】
- 下刀命中:XX 处(简要 1 行)
- 加法补充:XX 处(简要 1 行)

【建议删除清单】(只在轻改,或标准档想动结构时给)
- 第 N 段第 M 句「……」建议删,理由:段末打钉/同义反复/凑三/……

【主线反思】
- 主线一句话:……
- 有无偏离:无 / 有(说明哪一节偏了)
- 比改前:更清楚 / 更散(简答)

【给作者】(没有就不写这一栏)
- 原文缺的具体:第 N 段「……」没有数字/原因/时间点,我没替你补,需要的话你来填
- 有几种读法的句子:第 N 段「……」可以读成 A,也可以读成 B,我按原样保守改了,你定一下
```

随手一段只给改后正文，不给这套修改报告；有要提醒作者的，正文后面附一两句「给作者」。
