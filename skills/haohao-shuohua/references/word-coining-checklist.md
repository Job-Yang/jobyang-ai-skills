# 造词自检清单

**这是一条不能破的底线。**

AI 有一个恶习：为了显得凝练、显得深刻，把一个本来能用现成词说清的意思，压缩成一个自造的新词。「体验债」「沟通债」「协作势能」，这类词看着精悍，读者一脸懵。**AI 造的词大多一眼假。**

现成的中文词已经很够用。宁可多用两个字讲清楚，不要造一个词让读者猜。

> **先分清：是自造词，还是既有术语？** 有些看着像造词的，其实是某个领域/理论里已经立住的专业提法(例如软件工程「技术债」谱系里的「意图债」「理解债」)。既有术语不算造词，该用就用，只做减法、不当反例批。这条清单打的是**为了炫技临时硬造**的词，不是一竿子扫掉所有带后缀的词。

---

## 硬约束

1. **一稿最多一个自造词。** 超过就是滥用。
2. **必须造的地方，同段内必须翻译一次。** 用一句大白话把自造词的意思讲出来，写「XX，说白了就是……」/「XX，也就是……」。
3. **禁止在标题里放自造词。** 标题必须用同行都懂的现成词。自造词进标题 = 读者第一眼就懵。
4. **禁止在文章不同处反复用同一个自造词当锚点。** 反复用等于强推，是 AI 味升级版。用一次就够，后面回归大白话。

---

## 造词合法性测试(每造一个词都要过)

出稿前把每一个可能是自造词的地方拎出来，逐个问：

### 问一：是不是真的没有现成词？

先在脑子里找 3 个现成表达。找不到，才有资格造。

**大部分「找不到」是懒得找。**

例：
- ❌ 「体验债」——现成的：「体验欠账」「体验没打磨好」都能说。删。
- ❌ 「沟通债」——现成的：「沟通没到位」「话没说清」都能说。删。
- ❌ 「动词扛事」——现成的：「动词发力」「用动词开路」「让动词做主」都能说。删。
- ✅ 「技术债」——软件工程里已经立住的术语，不是临时硬造，可以直接用(同理，其所属谱系里已被认可的「意图债」等既有提法也照用)。

### 问二：这个自造词是新概念，还是给旧概念换个凉鞋？

- **新概念**(现有词汇覆盖不了) → 可以造，但必须翻译。
- **旧概念**(有现成词，只是想说得更炫) → 一律删。

判断方法：把自造词翻译成大白话后，读者理解成本降了还是升了？升了 → 是炫技，删；降了 → 是新概念，留(仍需翻译)。

### 问三：念给同行听，他能不能一次听懂？

对着一个真实同行(或想象一个)念这个词。**如果他要停下来问「什么是 XX?」**，你就失败了。

例：
- 「动词扛事」——同行大概率会问「什么叫扛事？动词自己扛？」——失败，删。
- 「协作势能」——同行大概率会问「势能是啥？能量？」——失败，删。
- 「技术债」——同行一听就懂「哦欠下的、迟早要还的工程账」——过关(既有术语)。

### 问四：这个自造词是不是对仗式硬凑？

「体验债」「沟通债」——为了 X 债、Y 债的对仗美感硬造(注意区分：某领域已认可的 XX 债提法是术语，不在此列)。
「前置化」「系统化」「闭环化」——为了三连罗列硬造。
「XX 逻辑」「XX 心智」「XX 属性」——为了显得有理论感硬造。

**对仗式造词一律砍**。要对仗回中文对偶传统去，不要造术语式对仗。

### 问五：这个自造词能被反驳吗？

好的判断是可被反驳的。**自造词往往不可反驳，因为它模糊**。

例：「动词扛事」——什么叫扛事？怎么算没扛住？没有清晰定义就没法反驳。**不可反驳的判断没有信息量**，删。

## 造词红线的例外(极少)

以下情况可以留自造词：

1. **对方社区已经有共识的新提法**(哪怕不严谨)，沿用不算造：「上下文工程」「智能体」「Agentic」等——虽然新，但社区已在用。
2. **某个领域/理论里已经立住的既有术语**(如软件工程的「技术债」及其谱系)，不是临时硬造，沿用不算造词。
3. **作者在多篇文章里已经反复用出来、读者群里已成共识的锚点词**，后续文章可继续用，视为个人风格锚。
4. **文章的核心主张确实需要一个新词才能命名**，但此时必须在标题下方第一段用一整段解释这个词。不写解释就用 = 违规。

## 常见 AI 造词模式(见到就删)

| 模式 | 举例 | 处置 |
|---|---|---|
| **XX 债** | 体验债、沟通债、认知债(临时硬造的)| 删，改大白话；**但既有术语除外**(如「技术债」及其谱系) |
| **XX 化** | 前置化、系统化、闭环化 | 删，还原动词 |
| **XX 性** | 结构性、颠覆性、系统性 | 删或换 |
| **XX 属性** | 工具属性、协作属性 | 删，直接说做什么 |
| **XX 心智** | 用户心智、产品心智 | 换成「怎么想」「印象」 |
| **XX 逻辑** | 底层逻辑、商业逻辑 | 换成「怎么运作」「根本原因」 |
| **XX 范式** | 开发范式、思考范式 | 换成「做法」「路子」 |
| **XX 势能** | 增长势能、组织势能 | 换成「劲头」「动力」 |
| **XX 生态** | 内容生态、开发者生态 | 换成「圈子」「生意」 |
| **XX 打法** | 增长打法、产品打法 | 换成「做法」「路子」 |
| **XX 抓手** | 增长抓手、业务抓手 | 换成「办法」「切入点」 |
| **XX 颗粒度** | 管理颗粒度、任务颗粒度 | 换成「拆多细」 |

**这张表不封闭。凡是「常见业务词 + 抽象后缀」的组合，都进这个筛。**

## 出稿前自检

三个问题走一遍：

1. **这稿里有几个自造词？** 超过一个 → 砍到一个。
2. **每个自造词都过了「合法性测试」五问？** 没过 → 删。
3. **留下的那个自造词在同段内翻译了吗？** 没有 → 补。

任何一条不合格，回去改。
