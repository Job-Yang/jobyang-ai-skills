# 版式底线：给人看的字，先降阅读成本

> **一句话**：读者先扫形状，再决定读哪里。一大坨字没有形状，只能逐字啃。这是最大的阅读成本，也是最明显的 AI 痕迹。

所有写作技能共用这条底线。文体不同，**格式密度**不同；但「清晰、有逻辑、精简、准确」不分文体。

## 共同底线（所有文体）

| 项 | 线 | 超了怎么办 |
| --- | --- | --- |
| 单段长度 | 按下方文体表，默认 ≤ 150 字（约 4 行） | 拆段；或把并列、数据挪进列表/表格 |
| 段落墙 | 纯段落连排 ≤ 3 段（文体表另有规定的从其规定） | 插入小标题、列表、表格、引用块或图，或删掉一段 |
| 一段一事 | 首句就是这段的结论 | 首句不是结论，说明这段在绕 |
| 加粗 | 只加粗关键词或数字（≤ 16 字），每段 ≤ 1 处 | 整句加粗 = 没有重点 |

## 先认内容形状，再选格式

写之前问：**这块内容是什么形状？** 不是什么都写成段落。

| 形状 | 用什么 |
| --- | --- |
| 结论、要读者记住或拍板的事 | 单独成段，或 `>` 引用块 + 加粗标签（**结论**：…） |
| 多个对象 × 多个属性（对比、选型、风险） | 表格 |
| 有先后的步骤 | 有序列表 |
| 并列的理由、约束、要点 | 无序列表，每项 ≤ 2 行 |
| 「属性：取值」 | `- **标签**：内容` |
| 前提、例外、注意 | `>` 引用块 |
| 因果推理、论证、叙事 | 短段落（这才是段落的本职） |
| 关系、流程、结构、数据对比 | 图（工程图走 engineering-docs，传播图走 content-infographic） |

> **判据**：把这段的句子拆开、换个顺序还成立 → 它是列表或表格。拆开就断了因果 → 它才是段落。

## 各文体的格式密度

| 文体 | 突出什么 | 单段上限 | 格式密度 |
| --- | --- | --- | --- |
| engineering-docs 技术方案 | 决定、代价、风险 | 120 字 | 最高：表格/列表/引用块为主，段落只放推理 |
| talk-smith 技术分享 | 故事线 + 可带走的结论 | 150 字 | 高：TL;DR 卡、对比表、加粗金句、启示列表 |
| feynman-explainer 调研讲透 | 一条推导链 | 150 字 | 中：推导用短段串起来；并列的形态/方案/对比用列表或表格 |
| cuihuo 观点硬文 | 一节一个判断 | 150 字 | 中低：观点句直陈；论据、数据、反例可列 |
| tangshan-style 畅想长文 | 画面与纵深 | 200 字 | 低：小标题分节、金句单独成段或引用块、每节有一个视觉锚点（短句段/引用/图） |
| 通用起草（周报、汇报、通知、整理成文档） | 读者要知道的事和要做的事 | 120 字 | 高：结论先行 + 列表/表格 |

密度低不等于可以写一坨：tangshan 也要守段落上限和段落墙。

## 清洗时保护格式（本技能收尾的硬约束）

上游文体技能给的格式是结构，**清洗只改说法，不拆结构**：

- **不把表格、列表、引用块改回段落。**
- **真列表不是排比病。** 第五层抓的是「用数量和对仗贴标签」（「三板斧」「五个维度」）和**段内**凑数的三连；内容本来就是几样并列的东西，拆成列表是对的，不合并成一句。
- **标签式加粗不算满屏加粗。** `- **保留期**：`、`> **结论**：`、表头里的加粗是结构的键，不计入「每段 ≤ 1 处」。
- 发现**段落墙**（超长段、连排太多段），按上面形状表拆，这属于「改说法」的一部分，标准档就可以动；用户点了「别大改」时，只列进建议清单。

## 机器检查

`python3 scripts/quick_scan.py 稿子` 的 `wall` 项会报超长段和段落墙（提示项，不卡退出码）。阈值默认 150 字 / 连排 3 段，可用 `--para-max`、`--run-max` 按文体调。
