# 节奏检查：把"念出声"落成机器能跑的字面指标

## 为什么单开一层

前面的下刀、加法自问，治的都是**一句之内**的病：名词化、后缀、破折号，都看得见，能照清单机械做，有天花板。削干净了，稿子顶多"没病"，还不一定"好"。

**"好"落在句与句之间。** 汪曾祺那句话点得最透：语言的美不在一句一句的话，而在话与话之间的关系。长短有没有错开、该喘气的地方有没有留气口、是不是从头到尾一个调子拖到底，这一层前面的清单管不了。

治这层只有一招：**念出声**。老一辈写文章的人早说过，文章的气顺不顺，读出声就知道了——那口气摸不着，但它老实落在句子的长短和停顿上，眼睛滑过去，耳朵能逮住。

问题来了：**AI 读不了声音。** 沉淀到技能里怎么执行？

答案：**念出声=耳朵在查四个东西，这四个东西全都落在字面上，机器能数。** 所以做成"机器粗筛 + 人念终审"两道：机器按下面的字面指标把可疑句标出来，人只在标红处念一遍定夺。机器不替耳朵做最终判断，只负责把 90% 干净的地方筛掉，让人把注意力放在剩下 10%。

---

## 一条压顶的界(先划死，再谈指标)

**节奏检查管的是"顺不顺、憋不憋气"，绝不管"够不够口语"。**

- 长句不是病。技术文档、严谨论述该长就长。**长句里没有一个喘气的地方，才是病。**
- 憋气句的第一修法是**补气口**(补逗号、断句读)，不是拆句，更不是掰成大白话。
- 下面所有指标，命中只代表"这里可能憋/可能单调",**一律不推向口语化**。掰过头是另一种矫枉过正。

这条界写在最前面，因为它最容易被 AI 带偏成"把长句全拆短、把书面语全改口语"。

---

## 四个字面代理指标(机器粗筛)

把稿子按 `。！？；` 切成句，每句再按 `,、:` 切成气口段。然后查四项：

### 指标一：憋气句(最重要)

**定义**：两个相邻停顿(`，、；：。！？`)之间的连续字数。

**阈值**：一个气口段 **≥ 28 字**且中间无任何停顿 → 标红为憋气句。

**注意误报**：URL、连续英文串、专有名词长列表、正当的排比，会把字数撑高但读着不憋。机器标红后交人念，念着不倒气就放过。**阈值宁可偏松**(只咬真憋的)，不要把严谨长句误伤。

**修法**：优先在自然停顿处补一个逗号。补完仍塞了几件独立的事，才考虑断句。

### 指标二：句长单调(一个调子拖到底)

**定义**：整段各句字长的序列。

**信号**：连续 3 句以上字长都落在同一档(比如都在 25–35 字)，没有一个短句穿插 → 段落节奏平、闷。

**修法**：别把长句都拆短，而是**在长句群里插一个真正的短断句**提气。一长一短错开，气就活了。段落该有起伏，句句一样长就闷。

### 指标三：软尾串(节奏发飘)

**定义**：句子结尾落在虚字/名词化尾上——`的了性化问题工作东西事情情况方面` 等 + `。`。

**信号**：连续 3 句以上都是软尾收束 → 通篇端着、没有一句砸得下去的实词收尾，读着没骨头。

**修法**：挑一两句，把结尾改成动词或实词落地(参见加法自问·动词发力)。**不是每句都要硬收**，软尾本身不是错，连成串才是。

### 指标四：调子单一(全程一种句式)

**定义**：句式类型分布——陈述/疑问/短断句/长复合的比例。

**信号**：整篇只有一种句式(全是四平八稳的陈述长句，没有一个短问、一个短断) → 这正是 AI 味最深的那种"匀速感"。

**修法**：别加感叹号装活泼，在关键处让句式变一变就行，插一个短判断、一个直问，打破匀速。

## 执行流程(技能里怎么跑)

1. **粗筛**：按上面四个指标扫全文，把命中句/段标红。可以用一段小脚本数字数、切句、跑正则，不需要模型判断，纯字面。
2. **终审**：只在标红处"念一遍"(在心里过节奏)，逐处判：真憋/真单调 → 按修法处理；误报(URL、排比、专名列表)→ 放过。
3. **守界**：每一处修改只问"顺了没"，不问"口语了没"。首选补气口，不是拆句。
4. **按任务大小分**（跟力度的轻改/标准/重改无关）：
   - **随手一段**（对话）：不跑节奏检查，凭语感悄悄顺一下即可。
   - **一般成稿**（手记/周报）：跑指标一（憋气句），其余凭手感。
   - **对外成稿**（硬文/对外文档）：四项全跑，标红逐处终审，写进修改报告。

## 字面代理指标的机器扫（配合"念出声"）

节奏是耳朵活，但四指标全落在字面上，机器可以先粗筛。**指标一（憋气句）**是最要紧的一条，一般成稿和对外成稿必扫；其余三条以手感为主，机器扫是辅助。

### 指标一 · 憋气句（≥ 28 字气口段）

**判据**：两个相邻停顿之间的连续字数 ≥ 28。停顿字符包括 `，、；：。！？,;:.!?` 以及中英文引号内的边界。

**Python 一行**（保存成 `~/rhythm-scan.py` 或 alias 都行，不塞到技能里）：

```python
# 用法: python3 rhythm-scan.py 稿子.md
import sys, re
text = open(sys.argv[1], encoding='utf-8').read()
# 剥离代码块和 URL，避免误报
text = re.sub(r'```[\s\S]*?```', '', text)
text = re.sub(r'`[^`]+`', '', text)
text = re.sub(r'https?://\S+', '', text)
stops = r'[，、；：。！？,;:.!?\n]'
for i, line in enumerate(text.split('\n'), 1):
    if not line.strip() or line.strip().startswith('#'): continue
    for seg in re.split(stops, line):
        seg = seg.strip()
        # 只数中文字符 + 常见英文字母，避免标点空白撑数
        cnt = len(re.findall(r'[一-龥A-Za-z]', seg))
        if cnt >= 28:
            print(f"L{i}  [{cnt}字]  {seg[:60]}{'...' if len(seg)>60 else ''}")
```

**输出示例**：
```
L42  [34字]  基于对大量线上问题的分析我们发现在当前的开发流程中验证环节的滞后性是导致代码质量问题的一个不可忽视的重要因素
```

**误报豁免**：命中不等于真憋，念一遍再判。以下常见误报直接放过：
- 段落只有一句、且是完整判断——虽然长，但读得下去
- 段中含 URL、连续英文串、长专名列表——机器已剥离，若漏剥自行豁免
- 排比句、术语枚举——非叙述句，节奏另算

**处置**：真憋气 → 优先补气口（在意思自然停顿处补一个逗号）；补完仍塞了几件独立的事 → 才拆句。**绝不为了口语拆句**。

### 指标二·三·四

- **句长单调**：连续 3 句字长同档（都 25–35 或都 8–15），无长短错落 → 段落闷。机器可以按段切句、算方差，方差过小标红。
- **软尾串**：句末字符匹配 `[的了性化题作情况方面]。` 且连续 3 句以上。正则：`([的了性化题作]|情况|方面)[。！？]` 频次统计。
- **调子单一**：整篇疑问句 / 短断句占比 < 5%，即"匀速"警告。

**这三条以手感为主**，字面扫只提示"这段可能闷"，不做机器判决。**指标一是节奏检查的命根子，其余三条不到位不阻断**。

## 一句话记住

减法有底，节奏无顶。清单能让稿子"没病"，念出声才能让它"好"。而念出声，对机器就是：**数长短、找气口、查软尾、看调子；标红交人念，只补气口，不掰口语。**
