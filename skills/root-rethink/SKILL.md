# 归本重推 · 从基本事实重新推导，而不是在旧方案上打补丁

> **一句话理论**：**第一性原理（First Principles）**——不沿用"大家都这么做"的类比结论，而是把问题拆到不能再拆、必须接受的基本事实，把事实与"习以为常但没验证过的假设"分开，只从事实、真正目标和现实约束重新推导。
> 向内重推仍解不开时，用第二招**跨领域借解**：剥掉行业术语，把问题抽象成底层结构，去相距较远的领域找已经被验证的机制，再翻译回来。
>
> **它解决什么**：方案越改越复杂、补丁摞补丁，或本行业所有常规答案都不好使——判断当前方案是在修表面，还是真的回到了问题本身。
> **它不做什么**：不在两个现成选项里抉择、不验真说法、不读文章、不学成品、不直接替代工程排障。

## 触发与边界

启用：用户怀疑在打补丁、要从本质重推、或本行业常规做法失效要向外借机制。

| 情况 | 去向 |
| --- | --- |
| 问题本身说不清、真正目标不明 | 先澄清（可多轮一问），别急着重推 |
| 已有 A/B 两个成形选项要权衡 | `steelman-choice` |
| 重推依赖的某个事实/数据不确定 | 先 `claim-check` 或取证，再推导 |
| 想看某个优秀成品怎么做 | `reverse-teardown` |
| 重推完要把新方案落成 PRD/计划 | `product-brief`；要低成本先试 → `minimum-experiment` |
| 代码级 bug、加 if 特判式补丁的根因 | 工程环境自带的根因/补丁判据流程（如收口三问：意图/毗邻影响/整体一致性） |
| 只是想要个常规最佳实践、问题不复杂 | 不启用，直接给常规答案，别为用而用 |

投入闸门：第一性原理重推成本高。能用现成成熟方案且代价可接受时，明确告诉用户"这题不值得从零推"，不要把简单问题哲学化。

## 模式一 · 向内：第一性原理重推

### 1. 拆成四堆（严格区分，不许混）

1. **基本事实**：已确认、绕不开、不依赖假设的东西（能被证据/现场支持）。
2. **未验证假设**：习惯性接受、但从没验证过的前提；逐条标注"若它不成立会怎样"。
3. **真正目标**：用户最终要达成的，不是当前手段本身（区分"我要 X"和"我要 X 是为了 Y"）。
4. **现实约束**：资源、时间、技术、团队、合规等不可忽略的边界。

拿不准是事实还是假设时，默认先放假设堆并标"待验证"，不要当成事实用。

### 2. 放下惯例与现成方案

暂时不看行业惯例、竞品做法、当前实现，只从基本事实 + 真正目标 + 现实约束出发，重新推导可行路径。允许路径看起来"不符合惯例"，只要它真的由事实推出。

### 3. 输出

- **原方案中只在修补表面的部分**：指出它在掩盖哪条未验证假设或哪个真问题。
- **从基本事实重新推导出的新路径**：写清每一步由哪条事实/约束推出。
- **新路径成立的前提**：哪些假设必须为真。
- **验证它的第一步**：成本最低的确认动作（随后可交 `minimum-experiment`）。
- **代价**：新路径牺牲了什么、增加了什么复杂度；只说好处不说代价不算重推完成。

## 模式二 · 向外：跨领域借解（向内推不动才用）

### 1. 剥术语、找底层结构

把行业名词全部换成通用描述，回答三问：

1. 问题的**底层结构**是什么（它在抽象层面属于哪类问题：分配、协调、缓存、纠错、激励、降维、排队、信任传递……）。
2. **真正的核心矛盾**是什么（两个都想要但互相拉扯的东西）。
3. **普通解法为什么失效**（在什么约束下常规机制不 work）。

### 2. 去远领域找机制

至少看 2–3 个**彼此距离较远**的领域（历史、生物、城市治理、供应链、航空、餐饮、医疗、游戏等），每个案例写清：那个领域遇到的问题 → 用了什么**机制**（不是表面做法）→ 与本问题的结构相似点 → 哪些可迁移 → **什么条件下会失效**。

### 3. 翻译回本处境

选出最值得借的 1–3 个机制，翻译成适合当前约束的方案，并给一个最低成本、可逆的试做。

## 防失败模式（硬规则）

- **禁止空话伪装深刻**："回归本质""打破常规""做减法"这类口号零价值；每条结论必须落到具体事实、具体机制、具体动作。
- **禁止把假设当事实**：两者必须分堆，关键假设标"待验证"。
- **禁止为了不同而不同**：若重推后发现惯例方案确实最优，如实说"惯例在此约束下成立，无需重造"——这是合法结论。
- **跨域借解防类比陷阱**：借的必须是**机制**不是表面形式；相似点要具体到结构，且强制写失效条件。形似神不似的类比直接弃。
- **不无视约束**：推导出的路径必须在现实约束内可走；约束解不开要明说，不画饼。
- **不扩大范围**：只回答"当前方案是否在打补丁、根本路径是什么"，不顺手重做整个系统（那要另立任务）。
- **诚实标注**：事实靠证据，推断标推断，借域案例不确定时不编造细节。

## 可感知信号（触发宣告与收口）

命中本技能并完整走流程时：

- **开头一行轻量宣告**：`〔思考：归本重推〕把问题拆回基本事实、假设、目标和约束，从根上重新推一条路`，让用户知道是哪个技能在起作用、这轮要做什么。一句话快答或顺带提一句时不贴标签。
- **收口自检多答一句**：在结论后用一句话说明"这轮让你的下一步具体改变了什么"（例如把纠结缩成一个待查事实、给出一个本周可做的动作、指出一条不该照搬的点）。读完仍不知道下一步该干嘛，视为本次失败，重做。

好坏的用户体感判别与反馈话术见仓库 `docs/SKILL-QUALITY-CARD.md`。

## 输出骨架

```text
真正目标 vs 当前手段：……
四堆：基本事实 / 未验证假设（含不成立的后果）/ 真正目标 / 现实约束
原方案在补表面的部分：……
重新推导出的路径：事实/约束 → 每一步
（若向外）底层结构与核心矛盾 → 远领域机制 ×2-3（含失效条件）→ 翻译后的方案
新路径成立前提 / 牺牲的代价 / 验证第一步：……
```

## 交付前自检

- [ ] 事实与假设严格分堆，关键假设有"待验证"标记。
- [ ] 区分了真正目标和当前手段。
- [ ] 指明了原方案哪些部分只是补丁。
- [ ] 新路径每步能指回事实或约束，不是口号。
- [ ] 写了新路径的代价和成立前提，以及最低成本验证第一步。
- [ ] 跨域模式借的是机制、写了结构相似点和失效条件；没有形似类比。
- [ ] 若惯例其实最优，已如实给出"不值得重造"的结论。
