# 裁判协议

裁判只做一件事：对着原文和上下文，核对这份改写哪里改坏了、哪里没改好。不打总分，不评文采，不比几份改写谁更好。每条问题都要引用原句，`loop.py verify` 会逐字核对，引用对不上的问题作废。

体检题（`calib/queue.jsonl`）和盲评题（`judge/queue.jsonl`）用同一套判法、同一个答案格式。

---

## 判一份改写的步骤

1. **认场合。** 读文体、读者、原文和上下文，归到五类之一：官方对外 / 敬语 / 要气势 / 私人软场合 / 技术议论。定义见 `haohao-shuohua` 的 SKILL.md「场合口语化红线」。
2. **正向对账：原文的每条信息，改写里还在不在。** 有事实清单的题，逐条写进「对账」，结果是保留、丢了、变了之一，清单上每一条都要写。没有清单的题，自己把原文的关键信息过一遍：数字、承诺、因果、程度、范围、模态、术语、身份、敬语和气势，丢了或变了的写进「问题」。
3. **反向对账：改写的每条信息，原文或上下文里有没有出处。** 找不到出处的就是新加的，按 A1 到 A4 记。正文后面「【给作者】」一段是写给作者的提醒，里面提到原文缺什么不算新加。
4. **看场合对不对。** 该正式的说成聊天口吻，该有温度的说冷了，该有气势的说白了，记 D；把敬语、客套、气势当废话删了，记 G。
5. **看表达。** 改写自己添的毛病（E1 到 E3）、原文没毛病却动了手（H）、AI 味没洗掉（R）、车轱辘话没删（F）、原句本来有几种读法却不声不响挑了一种（U）。
6. **回应每条机器旗标。** 队列里每份改写都带着「旗标」，每条都要写确认或排除，并写一句理由。确认了的，问题清单里要有对应的条目。旗标只是提示：「一半」换成「50%」、「若干」换成「几个」这类等价说法，排除。
7. **下结论。** 有任何改坏类问题（A、B、C、D、G）就是「改坏了」；没有改坏，但有 E、H、R、F、U 就是「没改好」；都没有就是「合格」。真拿不准才用「不确定」，规矩见下文。

## 编码

| 编码 | 叫法 | 判据 | 作者的原例 |
|---|---|---|---|
| A1 | 编数字 | 原文和上下文里没有的量化说法 | #23 原文只说做了优化，改写写「响应时间降了差不多一半」 |
| A2 | 编承诺 | 替作者许了原文没有的诺、给了没有的时间点 | #7「第一时间同步您」「下周给个时间点」；#49「改天我请客」 |
| A3 | 编因果、场景 | 补了原文没有的原因、做法、业务场景 | #10「连接池配置不当」被写成「连接数偏小，已扩连接池」 |
| A4 | 编身份、经历 | 给作者安了原文没有的身份或经历 | #25 自称「后端」、编「高并发经历」 |
| B | 丢信息 | 盖住被删的部分，读者对原意的理解会少一块 | #9「最具竞争力的解决方案之一」整句没了 |
| G | 删了功能件 | 把敬语、客套、气势、本来就对的表达当废话删了或改了 | #49「圆满收官」改成「顺利收尾」；#22 客服话术删成冷冰冰 |
| C1 | 程度、范围、模态漂移 | 强弱、覆盖面、确定性变了，「预计」「可能」被删也算 | #1「显著提升」改成「顺了不少」；#33「全面覆盖」改成「关键服务」 |
| C2 | 术语通俗化 | 有确切定义的术语被换成了大白话 | #6「重构」改成「重写」，「横向扩展」改成「加机器」 |
| C3 | 主被动调换 | 主动做的事说成自然发生，或反过来 | #32「对流程做了优化」改成「流程也顺了」 |
| C4 | 抬头、语气降格 | 头衔、定位被拉低，或带出轻蔑 | #13「顶尖专家」改成「一线工程师」 |
| D | 场合错配 | 语气档位不合这个文体和读者 | #21 落地页改得过分口语，丢了准确 |
| E1 | 破折号硬接 | 新加的破折号前后接不上 | #36 该用「但是」的地方用了破折号 |
| E2 | 自造黑话 | 去掉别人的黑话，自己又造一个 | #33「业务增长也就有了底座」 |
| E3 | 绕口不通 | 语序或搭配别扭，读着费劲 | #47「最后却得拿出一个大家都认的结论」 |
| F | 冗余没删 | 车轱辘话、铺垫小结还在 | #31「路口」前面说了后面又说 |
| H | 无必要改动 | 原文这处没毛病，改写动了，却说不出治的是什么 | 各种「没忍住把好句子也重写了」 |
| U | 原句不清没提醒 | 原句有两种以上读法，改写挑了一种，也没在「给作者」里提 | 主语不明、指代不清的句子 |
| R | AI 味残留 | 症状库里的毛病还在，「病灶」从下面挑一个 | 翻案体、三连排比、段末拔高 |

R 的「病灶」只能从这些里选：翻案体、三连排比、量词标题、名词化、万能动词、元话语、段末拔高、翻译腔句式、空心比喻、车轱辘、半角标点、套话、被字句、造词、词不配位、姿态、标题。都对不上就照实写你看到的，它会进待判断的题问作者。

## 引用规则

- 引用从原文或改写里原样复制，连续的一段，可以用「……」省略中间。脚本会去掉空白、统一全半角标点再比，别的一个字都不能差。
- 每类问题要带的引用：
  - A1 到 A4：改写引用，引的必须是新加的那段，不能是原文里本来就有的话。
  - B、G：原文引用，引被丢掉或删掉的那段。
  - C1 到 C4、H：原文引用和改写引用都要，一段原话对一段改后的话。
  - D、E1 到 E3、F、R：改写引用。
  - U：原文引用，引那句说不清的原句。
- 引用尽量短，能指清楚就行，一般 4 到 30 个字。

## 答案格式

每份一行 JSON，写进 `answers.jsonl`，不要换行排版。`jid` 照抄队列里的。

```json
{"jid": "J007", "场合": "技术议论", "对账": [{"事实": "F1", "结果": "保留"}, {"事实": "F2", "结果": "变了", "编码": "C1", "原文引用": "显著提升", "改写引用": "顺了一些", "说明": "程度从显著降成了一点点"}], "问题": [{"编码": "A1", "改写引用": "超时率从 2% 降到 0.3%", "说明": "原文没有任何数字"}, {"编码": "R", "病灶": "翻案体", "改写引用": "真正的问题在于", "说明": "原文没有，改写新添的翻案句"}], "旗标": [{"旗标": "K1", "结论": "确认", "理由": "2% 和 0.3% 原文都没有"}, {"旗标": "K2", "结论": "排除", "理由": "「几个」对应原文的「若干」"}], "结论": "改坏了"}
```

合格的也要写全：

```json
{"jid": "J012", "场合": "敬语", "对账": [], "问题": [], "旗标": [{"旗标": "K1", "结论": "排除", "理由": "「马上」对应原文的「第一时间」，承诺没变"}], "结论": "合格"}
```

字段：

- `场合`：五类之一。
- `对账`：有事实清单时必填，清单上每条一项；结果是「丢了」「变了」时要写编码和引用。
- `问题`：每条写编码、引用、说明；R 还要写病灶。
- `旗标`：队列里每条旗标一项，结论写「确认」或「排除」，理由不能空。
- `结论`：改坏了 / 没改好 / 合格 / 不确定。脚本按问题清单重算结论，你写的对不上时以问题清单为准。

## 拿不准的时候

只有这两种情况用「不确定」：

- 保真上，这处改动算不算改了意思，取决于原文没交代的背景。
- 场合上，这个语气放在这个文体里合不合适，你判断不了读者会怎么看。

用「不确定」时加两个字段：

```json
{"不确定原因": "原文「业内普遍认为」，改写说成了定论，算不算改意思拿不准", "争议片段": {"问题类型": "保真", "原文引用": "业内普遍认为", "改写引用": "根源是", "疑似编码": "C1"}}
```

争议片段会原样做成是非题问作者，所以原文和改写各引一句就够，让作者不看全文也能判。别的地方判得出来的问题照常写进「问题」。

不要把「不确定」当退路：能按判据判的就判，判据真管不到才用。

## 判例怎么用

队列里每份改写附最多两条相似判例：作者对历史改写的原话，或者作者在待判断的题里的回答。

- 判例是作者的原话，照字面理解，不要自己推广成更宽的规则。
- 眼前这份跟判例是同一类情况，按判例判。
- 你觉得判例本身判错了、或者这份跟判例像又不完全一样，按判据判，同时把这份判成「不确定」，在不确定原因里写明跟哪条判例冲突，交给作者定。

## 作者说明怎么用

队列里的「作者说明」是作者平时交代的话，比如「感谢信里的客套别删」「计算机专业名词一律用原词」。它不针对某一份改写，是作者给这类文体定的标准。

- 照字面用，管到它说的范围为止，不往外推。
- 改写违反了作者说明，按对应的编码记问题（删了客套记 G，术语换了记 C2），说明里写上作者说明的编号，比如「违反 N003」。
- 作者说明跟本协议的判据冲突时，保真的判据优先；其余情况按作者说明判，同时判「不确定」，写明冲突在哪。

## 常见误判

- **口语不等于自然。** 改写更口语，不加分；场合要求正式时，改得口语反而是 D。
- **删套话不算丢信息。** 「深刻认识到」「有效提升」这类空话删了，原意一点没少，不是 B。判据永远是：盖住删掉的部分，读者的理解会不会少一块。
- **同义换说法不算变。** 「若干」和「几个」、「一半」和「50%」、「第一时间」和「马上」，意思没变就是保留。
- **没改不等于合格。** 原文有 AI 味，改写原样没动，记 R；原文本来就干净，没动才是合格。
- **动了手不等于 H。** 这处改动治了一个说得出名字的毛病，就不是 H；原文这处没毛病、改了也没变好，才是 H。
- **短不等于好。** 字数少了多少不重要，重要的是信息有没有丢、意思有没有变。
- **起草题看材料。** 起草题的「原文」是材料，「要求」是作者的要求。起草稿里的每条信息都要在材料或要求里找得到出处，材料里的要点没写进去算 B。
- **每份单独判。** 不要回想这份是哪个版本写的，不要拿同一题的另一份来比。
