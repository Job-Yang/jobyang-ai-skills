# 最小实验 · 用一次低成本可逆试错，替代反复空想

> **一句话理论**：纸上推演很多遍，世界不会给新信息。把决定成败的假设挑出来，用**最小、可逆、短周期**的实验让现实回答。
> 方法来自精益创业的**构建—测量—学习**循环、波普尔的**可证伪性**（一个实验必须允许证明假设是错的）与工程里的**探针式开发（Spike）**。
>
> **它解决什么**：想法卡在"我觉得可行/我觉得不行"，讨论再久也没收敛——把争论变成一周内可见分晓的反馈。
> **它不做什么**：不替你决定方向（抉择归 steelman-choice）、不评想法值多少分（scorecard）、不写完整 PRD（product-brief）、不重复工程测试体系。

## 触发与边界

启用：有一个或几个**待验证的假设**，且需要现实反馈才能推进。

| 情况 | 去向 |
| --- | --- |
| 想法还没形成、要先扫机会 | `opportunity-radar`；要打分排序 `opportunity-scorecard` |
| A/B 方向选不出来 | `steelman-choice`（选完再用本技能验证关键假设） |
| 重推路径后要低成本验证第一步 | `root-rethink` 的下游，直接接本技能 |
| 拆完优秀成品想小范围试做 | `reverse-teardown` 的最小练习可接本技能细化 |
| 验证完要正式立项排期 | `product-brief` |
| 线上代码/崩溃/性能假设的可复现验证 | 工程环境自带测试、真机/日志取证或 TestSpec 流程，不用本技能 |
| 事实是查得到的（价格、政策、规范、数据） | 先查（`claim-check` / 检索），别拿实验代替查资料 |
| 假设无法被实验证伪，或根本没假设 | 不启用，先澄清要验证什么 |

产品实验与技术探针都适用：前者验"用户/价值假设"，后者验"技术可行性假设"（技术 Spike），但运行态、可编译复现的那类工程验证仍走工程环境自带流程。

## 流程

### 1. 列出决定成败的假设

把想法背后的假设全部摊开，区分：

- **价值假设**：用户/受众真的有这个问题、会用/买单吗。
- **可行性假设**：技术/资源上做得出来、跑得动吗。
- **关键前提**：哪些外部条件成立它才成立。

每条假设写成可被证伪的陈述句（"X 在 Y 条件下会发生 Z"），不写"也许可能大概"。

### 2. 选一个最该先验的

用两条标准排序，只选一个：

1. **关键性**：它若不成立，整个想法是否需要大改或放弃（致命假设优先）。
2. **不确定性**：现在掌握的信息是否足够；越没把握、越能用便宜实验快速降不确定的，越优先。

不要一次设计五个实验。一次只打最致命、最不确定的那个。

### 3. 设计最小实验

使实验尽量小：去掉一切与验证该假设无关的部分（能手动就不写系统、能假数据就不接真接口、能小范围就不全量）。写清：

1. **具体做什么**：可执行动作，明确到下一步就能开工。
2. **投入**：时间、人力、资源上限（建议短周期，如数天到一两周）。
3. **观察指标**：事先定好、可观测、与假设直接相关；区分虚荣指标（看着热闹）和可决策指标（能改变下一步）。
4. **继续信号（预设阈值）**：拿到什么结果就加大投入。
5. **停止/转向信号（预设阈值）**：拿到什么结果就停或改方向。
6. **时间盒**：到点无论结果如何都收口判读，不许无限拖。
7. **可逆性**：先确认做砸了能撤回、代价可承受。
8. **实验后获得的新信息**：无论成败，这次试错能回答什么此前不知道的事。

继续/停止阈值必须在实验前写死，不能看完结果再改标准（防止移动球门）。

### 4. 明天的第一个动作

给一个当天或次日就能开始的最小动作，把启动成本降到最低。

## 防失败模式（硬规则）

- **实验必须可证伪**：结果怎么都能解释成"还行"的实验是无效实验；必须事先存在一个能证明假设错误的结果。
- **阈值先行**：继续/停止标准实验前定，禁止事后挪线。
- **一个实验一个假设**：别把多个假设塞进一次实验，失败时分不清是谁错。
- **不许用实验代替查资料**：能查到的事实先查；实验只回答资料回答不了的真实反应。
- **最小而非完整**：任何与待验证假设无关的开发/打磨都砍掉；做成正式产品是浪费。
- **诚实对待失败信号**：到了停止阈值就停或转向，不追加投入硬撑；失败也是有效信息，不是白做。
- **不假装精确**：样本小、周期短时如实标注结论强度，不把个例当规律。
- **守住可逆与边界**：不动真实数据/线上用户/资金等高风险面，除非用户明确授权并有保护措施。

## 可感知信号（触发宣告与收口）

命中本技能并完整走流程时：

- **开头一行轻量宣告**：`〔思考：最小实验〕挑出最致命的一个假设，设计一个低成本、可证伪的试错`，让用户知道是哪个技能在起作用、这轮要做什么。一句话快答或顺带提一句时不贴标签。
- **收口自检多答一句**：在结论后用一句话说明"这轮让你的下一步具体改变了什么"（例如把纠结缩成一个待查事实、给出一个本周可做的动作、指出一条不该照搬的点）。读完仍不知道下一步该干嘛，视为本次失败，重做。

好坏的用户体感判别与反馈话术见仓库 `docs/SKILL-QUALITY-CARD.md`。

## 输出骨架

```text
待验证的决定/想法：……
假设清单（价值/可行性/前提，可证伪陈述）：……
本次选定的假设：……（关键性 × 不确定性排序）
最小实验：做什么 / 投入上限 / 观察指标（可决策指标）
继续信号（阈值）/ 停止·转向信号（阈值）/ 时间盒 / 如何保证可逆
实验后能获得的新信息：……
明天的第一个动作：……
```

简单探针可压缩，但"假设、指标、继续阈值、停止阈值、时间盒"五项不能省。

## 交付前自检

- [ ] 假设写成了可证伪陈述，且一次只验最致命、最不确定的一个。
- [ ] 指标事先定好、可观测、与假设直接相关，不是虚荣指标。
- [ ] 继续与停止阈值在实验前写死，带时间盒。
- [ ] 实验足够小且可逆，没有夹带与假设无关的开发。
- [ ] 明确了"查得到就不用做实验"的部分没有被实验替代。
- [ ] 给了次日可开工的第一个动作，并说明了无论成败能学到什么。
