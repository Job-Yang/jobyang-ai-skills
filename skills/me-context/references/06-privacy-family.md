# 06 · 隐私分层与家庭角色

> 本技能是**本地 Markdown 工具**：不做身份认证、不验证他人是否真的同意、不为数据真实性或隐私合规背书。

---

## 1. L0-L4 敏感分层

| 层 | 含义 | 投喂策略 |
|---|---|---|
| L0 公开名片 | 称呼/职业角色/领域/协作语言 | 可给任意 AI |
| L1 工作画像（默认层） | 工作上下文、沟通输出偏好、当前目标 | 默认随档案加载 |
| L2 个人偏好/家庭概况 | 详细偏好、决策风格、价值观、家庭情况 | 按任务显式解锁 |
| L3 敏感（逐次确认） | 健康、财务、家庭细节与关系实体 | 云端逐次确认、用完不留 |
| L4 秘密（永不入云） | 密钥/证件/隐私事件 | 仅本地、永不发送 |

---

## 2. 诚实信任边界（不和稀泥）

- 本档案是纯本地 Markdown + 通用脚本，**没有密码学认证、没有登录态**。
- 它**不做身份认证、不验证配偶/家人是否真的同意被记录、不为数据真实性或隐私合规背书**。
- 你想记录配偶/家人的信息，**请自行取得对方知情，责任在使用者本人**。
- 将来若做成独立 APP，才可能有真正的认证与授权流程；现在这个本地工具不假装自己有。
- 读取他人信息时只过 L0–L4 / audience 门禁，**没有"本人到设备前确认"这一步**——那需要真正的认证，本地 md 做不到。

---

## 3. 关系网怎么记（轻量圈层）

- 概览写一页 `network.md`：inner/close/peripheral 三圈列人 + 一句话。
- 详情在 `entities/<人>.md`（带 `circle`），用 `relations.md` 连边。
- 读取关系信息 = 取 `network.md` 概览或点名的实体，统一只过层门禁，无认证环节。
- **家人健康**：在各自 `entities/<人>.md` 独立健康小节，一人一份、各自 L3/provenance，不合并家庭总表；同样受健康本地授权门（`CONSENT-health.md`）约束，未授权不出结构化健康。

### 对未成年人的温和建议（非强制门禁）

- 尽量少记、只记明示事实（称呼/学校），**别贴人格标签**。
- `source: inferred` 的观察对孩子仅作提示，本工具不硬性禁止，但建议克制。
- 这条是建议，不是门禁——责任仍在使用者。

---

## 4. 加密的诚实结论

> **本地文件加密只防"设备丢了"，不防"你把它喂给云 AI"——上传即必须明文。**

- FileVault 解决静止卷（丢电脑），解锁后一切明文在内存里。
- 根本手段不是加密，而是**"不传 + 分层最小投喂"**：① 永不入档 > ② 本地模型处理 > ③ 加密了再上云。
- 用户自己把备份放远端时，加密的作用是"远端和拿到包的人看不到明文"，见 §6。

---

## 5. 读 / 写 / 上云权限小表（授权轻量化，工具零上报、安全在你手里）

| 动作 | 未授权 | 已授权（本地） | 上云 |
|---|---|---|---|
| 读本地辅助 | 不读结构化健康 | 写了就默认可读，不另设读授权 | 逐次确认（L3 门，未 confirm 0 明文） |
| 写 / 补记录 | 不写、不落盘 | 同范围默认直接记；扩范围才再确认一次 | 另需确认 |
| 撤回 | — | 撤一处即停写停用；历史删不删用户定 | — |

- 写授权一次给、长期有效、可随时撤回/缩范围；`style: direct|gentle` 只改怎么说，不改能不能访问。
- 记家人信息先取得对方知情；该家人无授权记录时通用答、不编造、不擅自建档。
- L4 秘密层默认永不导出、永不入云；导出 md 须显式 `--include-l4` 才会包含并打印警告。

---

## 6. 存储与备份：交给用户

技能只负责产出本机文件（数据仓、`export.py` 导出、`viz.py` 图谱），**不提供版本记录、加密、上传脚本**，不调 git、不调 openssl、不联网。存哪、备不备份、怎么加密，是用户自己的决定：每个人的秘密和设备环境都不一样，技能代办只会多出泄露面（比如机器上全局配置的提交钩子会扫描仓库并上报，技能无从判断）。

用户问起时，只讲利弊，不替用户执行：
- 只在本机：不经第三方；设备丢失或误删无法找回。
- 自己用 git 记版本：能回退；`init.py` 写的 `.gitignore` 已排除 `private/ inbox/ exports/ .migrate-backup/`；注意本机的全局 git 钩子可能扫描仓库内容。
- 自己加密后放远端：防设备丢失；口令丢了打不开。**不建议把明文档案推到远端**，哪怕是私有仓库：平台方在合规排查等情形下能访问内容，账号被盗、误改公开都会整体泄露，git 历史想删一条要改写全部历史。

技能自己守住的几条：`export.py`、`viz.py` 写出的文件只有本人可读写；`migrate.py` 写出的过程层沿用原文件权限，写入失败整体回退；迁移备份 `.migrate-backup/` 不导出、不 lint，确认无误后可自行删除。

**公司电脑上的提醒**：公司管理的设备可能装有终端安全或防泄漏软件，扫描范围由公司策略决定，本工具判断不了。家人健康这类数据，主副本建议放个人设备；公司电脑只放你愿意让它看到的几层。
