# 08 · 健康信息提取协议（给当轮 AI 的规范，纯文档、无脚本）

> 本文是**当轮 AI 读完体检 PDF / 截图 / 医院解读结论 / 口述后，如何映射进健康档案**的规范。
> me-context **不内置 PDF/OCR 导入器、不引三方依赖**：读 PDF/截图是宿主（Harness）或当轮模型的能力，
> 本技能只规定"抄什么、怎么分层、怎么存、怎么比"。provenance 由当轮 AI 手动填写，无自动导入。

## 0. 前置：先过本地授权四档
首次进入健康任务，先请用户显式选 `full / facts_only / index_only / off`（不施压、可拒绝、可事后改），
写 `CONSENT-health.md` 后才采集。未授权不主动问、不落盘；当轮就事问用药/急症可给安全必要信息但不落盘。

### 0.1 健康意图召回（从 SKILL.md 下沉的完整版，不用报技能名）

判定主轴是「是否已授权 + 问的是谁」，不是"有没有材料"：已授权=结合本人档案个性化答，不重复索权；未授权=先把公共层面答好 + 最多一次轻邀请，不翻本地、不强行索权。纯公共问题即使含病名也不建档。

### 召回正例（应进入本技能）
（本人归属 + 记录/个性化使用意图）
- 这是我体检报告 / 化验单 / 检验报告 / 病历 / 出院小结，帮我存一下 / 你看看
- 帮我看看我这个体检报告要不要紧（材料在场 → 先授权再解读存储）
- 把我两年体检整理一下 / 存起来；看看我的健康记录 / 这两年指标趋势
- 我尿酸 / 血压 / 血糖 / 血脂有点高，记一下；我有三高 / 脂肪肝，以后结合我的情况提醒我
- 这是我老婆的体检，也存一下（先取得对方知情，再落各自 entities 独立健康小节，见 06）

### 召回反例（不进入，仅公共科普）
（只做公共科普，不索权、不读本地健康）
- 未授权时问"高血压吃什么好 / 尿酸高一般要注意什么 / 平时吃点啥 / 胆固醇偏高要不要紧"
- 一次性症状（"今天头晕"，无材料无"记一下"）；体检前注意什么；ALT 是什么意思（名词解释）；推荐体检套餐

**触发后流程**：① 授权前不读已有健康正文、当轮材料也先不解读不落盘 → ② 用温度话术请用户选四档（只存本地、可撤回、可只存原件、不是诊断）→ ③ 选定后当轮 AI 读 PDF/截图/口述，按本文件提取、过收录三问、人确认后分两层落盘 → ④ 选 off 不读不存 → ⑤ 上云另过外发逐次确认。

**授权轻量化**：一次授权长期有效、可随时撤回或缩范围；同范围的新年检默认直接记，扩范围（facts_only→full、首次记精神/生殖/遗传）才再问；本地读随写开放；`style: direct|gentle` 只改怎么说。

## 0.5 理论依据（借思想，不实现协议）

本分片受 **FHIR / LOINC / OMOP / POMR-SOAP / EP28·EP33·RCV / ICF** 等思想启发，但**仍是人读得懂的轻量 Markdown：
不实现 FHIR、不引 JSON、不做 LOINC/ICD 标准编码**，只借其原则组织字段与门槛（完整映射见 `references/09-domain-blueprint.md`）。

- **FHIR Observation/valueQuantity/referenceRange**：一个指标点 = 指标 + 数值 + 单位 + 时间 + 本院参考区间 + 来源，
  我们用 Markdown 行轻量承载，不建 FHIR resource；原件只索引（DocumentReference 思想），人话结论与结构化行并存（Narrative 思想）。
- **LOINC 六轴 / OMOP**：方法、标本不同同名指标不可直接比；原始值/原始单位照抄、不强换算——支撑"同法才比、跨法参考"。
- **SOAP**：客观指标表 = O，结论区 = A（仅建议、**非诊断**），复查计划 = Plan；评估判断归医生。
- **ICF**：关注功能与生活上下文，不只抄病名；**ICD 仅作可选术语参考，不自填编码、不诊断**。

### 趋势判定的原则门（借 EP28 / EP33 / RCV 的参考区间思想与通用实验室原则，不伪算常数）
- **参考区间思想（EP28-A3c 参考区间概念）**：参考区间是健康人群中间多数，按通用实验室原则**单次出界 ≠ 有病** → 单次只建议复查确认，`persistent` 要 ≥2 次，`resolved` 留历史不删。
- **Delta check（EP33 思想）**：相邻差值超阈只触发**复核**（可能标本差错，也可能真变化）→ 差值小、条件不一致一律 `fluctuating`，可疑挂 needs_review。
- **RCV（参考改变值，原则借用）**：真变化需超过参考改变值；个人档案没有每个指标的 `CV_i`（个体内变异）/`CV_A`（个体间变异）常数与同室质控，**不伪算精确 RCV**，只做生活辅助级判读，分三级置信：
  - **高置信（出方向箭头）**：同机构 + 同方法 + 同单位，两点都确认、幅度明确；
  - **中置信（软方向·仅供参考）**：跨机构但属标准化生化项、**单位可换算归一**（尿酸 mg/dL×59.48=μmol/L、血糖 mg/dL÷18=mmol/L、肌酐 mg/dL×88.4=μmol/L），归一后方向明确 → "大致好转/上升（不同机构·仅供参考）"，不给强箭头色；
  - **不可比（不判方向）**：单位无法归一 / 两方写明且方法或标本明显不同 / 非标准化项方法缺失 / 参考区间体系冲突 / 只有单次。
  能换算先归一；差异微小或临界不确定不强行给方向。医学界用 RCV/delta-check 求精确，我们借思想做生活辅助级，刻意不过度精确。
  **体检报告普遍不写检测方法**：方法缺失时，通用标准化项（血脂 TC/LDL/HDL/TG、血糖 FPG、尿酸、肌酐、转氨酶 ALT/AST、血压、BMI/腰围，常规方法高度统一）跨院同单位或可换算仍给 mid 软方向；方法差异较大的项目（HbA1c 色谱法、CK 偶联法）方法缺失、或两方写明方法明显不同 → 不可比。
  任何置信档下，练后高强度/脱水的运动性升高都不标恶化。

## 1. 七条映射规则
1. **→ L1 结论区**：总检结论 / 医嘱原文 / 异常项 / A·B 类 / 复查计划，**原文保留不改写**，不替医生下结论。
2. **→ L2 最新关键指标表**：只取设计报告 §3.3 那一小撮决策相关指标（血压/腰围/BMI/TC/LDL-C/HDL-C/TG/FPG/HbA1c/UA/ALT·AST/肌酐·eGFR/CK），每条带 `value / 原始 unit / 本院 ref_range / 日期 / 机构 / 方法 / 采血条件（空腹·练后·脱水）/ provenance`。
3. **其余数值一律不抄**；原件只留本地路径索引，不搬正文。
4. **跨院趋势三级置信（生活辅助级，不一刀切）**：
   - 同机构 + 同方法 + 同单位 → **高置信**，出方向箭头；
   - 不同机构但项目标准化、单位相同或可换算、方法相容（或方法未写且属通用标准化项）→ **仍然比较**，归一后给"大致好转/上升/回到正常（不同机构·仅供参考）"的**中置信软方向**，不用强箭头色；
   - 单位无法归一 / 两方写明且方法明显不同 / 非标准化项且方法缺失 / 参考区间体系冲突 / 只有单次 → **不判方向**（fluctuating）。
   恢复正常（resolved）的置信也随可比性：跨院各自回到本院区间给中置信软结论，不假装临床级确定。
5. **多年比较基准 = 最近一次**：历史快照 append-only，按日期排序，取"上一份最近的检查"为比较基准（三年数据时比的是最近两年，不是最早一年）；viz 历点可展开看全部年份；历史行缺日期时继承所在 `### YYYY-MM-DD` 小节标题日期。
6. **健身语境三看**：CK / 尿酸 / 肌酐 / ALT·AST 的运动性升高，按"练后 + 无症状 + 复查回落"判断，不套普通人阈值吓人，标 `fluctuating/运动性待复查`。
7. **不诊断**；过敏与在服药每次用药前当次确认；不做临床营养治疗、不给治疗剂量。

## 1.5 拍饭 / 热量蛋白：逐顿不记，仅可选周期摘要
- 默认当轮帮算蛋白/热量即算即走、**不留存**：逐顿是过程数据，不进档案、不膨胀。
- 仅用户明确要跟踪（减脂/增肌期）才写**轻量周期摘要**（近 7 天平均蛋白 g/kg、平均热量缺口、达标率），
  进 `profile/body.md`（L2，不是 health L3），只保留最近一期，不存每顿；点餐当轮被动禁忌提示仍在，菜单本身不入档。

## 1.6 关注因子（watchlist）：千人千面的呈现重点，不诊断
解读/展示前在**已授权范围内**形成本人关注清单，让同一份体检详略不同；**只改呈现重点，不硬安病、不诊断**，正常就是正常。

**三来源**（写在 health.md 可见、可删的 `## 关注因子（watchlist）` 小节）：
- `auto`：从**已记录的本人正向事实**——慢病/痛风/手术史/在治疗/在服药/过敏——**自动关联**相关指标（痛风→尿酸/肾功能；脂肪肝→肝功/血脂/腰围；高血压→血压/肾功能；糖代谢→血糖/HbA1c/肾；血脂→血脂四项；在服他汀→LDL-C/转氨酶）。确定性"病/情况→指标"小映射，**宁少勿滥**，无病史正常人不触发。
  **auto 只扫本人正向事实**，下列一律不触发，避免给正常人硬安病：否认句（"否认高血压"）、检查结论（"未见脂肪肝"）、家族/亲属病史（"父亲高血压"）、空白模板占位行（`<例：…>`）、watchlist 小节自身（含 `proposed` 未确认条目的原因，防止绕过确认）、指标表与历史快照（数值词不代表病史）。
- `stated`：本人明说"重点盯尿酸/备孕/备赛"→直接加入。
- `proposed_confirmed`：AI 提议须本人 confirmed 才生效；未确认（`proposed`）是建议态，不置顶、不当真。
每条带来源、一句话原因、可删除（删后不再自动重加，尊重删除）。

**详略三档**（viz/gate 组织解读时）：
1. **固定呈现**：所有异常项 + 医嘱/复查计划(A/B 类、followup_due)，无论在不在清单都展示（安全兜底）；
2. **关注项即使正常也显示**：清单内指标本次在区间内也显示，附"结合你的目标/既往史"情境句（如"尿酸本次正常，结合痛风史继续关注、维持"）；
3. **其余正常项只索引**：既不异常也不在清单的正常指标，折叠为"其余 N 项正常"，不逐条铺开（降噪）。

**红线**：正常就是正常，不因在清单就说有病；构建只读 health.md + body.md 运动/目标，**绝不读 finance 等无关分片**；配偶/家人各受各自授权约束，不把本人清单套到家人、不读未授权家人健康，备孕只在双方各自授权信息内组合、不做生育诊断。

### 理论锚点（借思想，不实现协议）
- **"基本 1 + X 个体化加项"**（国家卫健委《成人健康体检项目推荐指引(2025年版)》：基本项目 + 慢性病风险筛查专项，按既往史/风险按需加项）→ watchlist 即个人版"X 加项"，只决定多盯哪几项，URL: https://www.nhc.gov.cn/yzygj/c100068/202511/4feaeb6de63e44cb9fd4ac8f579ca279.shtml
- **POMR 活动问题清单（active problem list，Weed/SOAP，R5 已引）**：只围绕已确认问题/目标列关注项，不把泛泛正常值都挂上 → auto 映射只由已记录既往/用药触发。
- **个体化参考区间**：运动员/孕妇/老人等亚群参考区间与常人不同（运动 CK/肌酐已见 R1 健身节；孕期仅作"特殊人群需结合临床"提示）；本轮未取到单一权威通用 URL，不据此改判单值。
- **共同决策 SDM**（Cochrane：医患结合证据与个人偏好共同决定）→ 关注项需本人确认/可删，AI 提议不替用户定，URL: https://www.cochrane.org/CD013822/BREASTCA_does-shared-decision-making-help-women-when-making-decisions-about-whether-or-not-participate-breast
- 定位不变：生活辅助级、不诊断、不替代医生。

## 3. AI 读完报告后应产出的结构化 Markdown 片段（标准模板）

**两层落点**：过敏/在服药、当前状态、结论区、里程碑、原件索引写 `profile/health.md`（结论层，做判断时带）；
「最新关键指标」「历史快照」写 `journal/health-metrics.md`（过程层，问具体数值或趋势时才读）。下面模板按小节给出，落盘时按这个分法分两处写。

**写入契约（强制）**：
- 最新指标与历史点都必须**一项一行**，禁止把 `血压`、`体重/BMI/腰围`、`ALT/AST`、`尿红细胞/尿蛋白/尿隐血` 合成一行。
- 数值、单位、参考区间、上下箭头/定性结果必须原样抄报告；报告未写的方法/标本/采血条件留空，不编造。
- 定量结果写数值；定性结果写原词（`阴性 / ± / + / ++ / 阳性`），不得改成 0/1。
- canonical 指标建议：`systolic / diastolic / weight / bmi / waist / ua / tg / tc / hdl_c / ldl_c / fpg / hba1c / alt / ast / creatinine / egfr / ck / urine_rbc / urine_protein / urine_occult`。未列指标可用清晰英文 snake_case，同时在结论区或原件索引保留报告中文名。
- `confidence` 是数据点来源可信度，不是诊断概率：电子报告原文=`confirmed`；OCR 草稿=`single_measurement`/`needs_review`，人工核对后才改 `confirmed`。

```markdown
<!-- profile/health.md（结论层） -->
## 过敏 / 在服药 / 慢病禁忌
- （原文事实，用药前当次确认）

## 当前状态（据最新体检，细节见 journal/health-metrics.md）
- <指标>：偏高 / 偏低 / 阳性（日期）——只写需要留意的项，不写数值

## 结论区
- 总检结论：<原文>
- 医嘱 / 复查计划：<原文>
- followup_due: YYYY-MM-DD

## 变化里程碑（confirmed 人话，declared 才落）
- （本人确认的长期变化，如"脂肪肝健身后持续好转"）

## 体检原件索引
- <本地路径，不进 cloud/导出>

<!-- journal/health-metrics.md（过程层） -->
## 最新关键指标
- 指标 <analyte> | 数值 <报告原值> | 单位 <原始单位> | 参考 <本院原文> | 日期 YYYY-MM-DD | 机构 <院> | 方法 <报告原文或空> | 标本 <原文或空> | 采血条件 <空腹/练后/脱水/空> | provenance <枚举> | confidence <confirmed|single_measurement|inferred>

## 历史快照（append-only，只增不改）
- （上一份最新状态整体追加，带 date/org/method/preconditions/provenance/confidence）
```

## 4. 张三虚构两年完整示例（2025 → 2026）

```markdown
## 过敏 / 在服药 / 慢病禁忌
- 青霉素过敏
- 在服药：无
- 慢病禁忌：无

## 最新关键指标（2026-10-01，甲院，酶法，空腹12h / 72h未训练）
- 指标 ldl_c | 数值 2.8 | 单位 mmol/L | 参考 <3.4 | 日期 2026-10-01 | 机构 甲院 | 方法 酶法 | 采血条件 空腹12h、72h未训练 | provenance imported_report | confidence confirmed
- 指标 ck | 数值 900 | 单位 U/L | 参考 <190 | 日期 2026-10-03 | 机构 甲院 | 方法 酶偶联 | 采血条件 练后高强度、无症状 | provenance imported_report | confidence single_measurement
- 指标 hba1c | 数值 6.1 | 单位 % | 参考 4.0-6.0 | 日期 2026-10-01 | 机构 乙院 | 方法 高效液相 | 采血条件 空腹 | provenance imported_report | confidence confirmed

## 结论区
- 总检结论：血脂较去年回落，建议继续饮食控制（以医生报告为准）
- followup_due: 2027-04-01

## 历史快照（append-only）
### 2025-10-01 甲院
- 指标 ldl_c | 数值 3.6 | 单位 mmol/L | 参考 <3.4 | 机构 甲院 | 方法 酶法 | 采血条件 空腹 | provenance imported_report | confidence confirmed
- 指标 ck | 数值 300 | 单位 U/L | 参考 <190 | 机构 甲院 | 方法 酶偶联 | 采血条件 静息 | provenance imported_report | confidence confirmed

## 变化里程碑
- 脂肪肝健身后持续好转（本人确认，declared）

## 体检原件索引
- private/health/2025_checkup.pdf（本地，不进 cloud/导出）
```

读时派生（不写死）：
- ldl_c 3.6→2.8 同院同法同单位、两点 confirmed → `improved`；
- ck 300(静息)→900(练后高强度) → `fluctuating/运动性待复查`，**不标 worsened**；
- hba1c 2026 在乙院、方法不同（HbA1c 属非标准化项、方法缺失/不同） → `仅供参考`，不出方向。
- 同一项跨院但报告未写方法（如尿酸 2025 甲体检中心→2026 乙医院，同 μmol/L）→ 标准化项可给 `improved·mid（不同机构·仅供参考）`，不是一律不比。

## 5. 源头规范（写进 03/05）
健康细节只写在健康分区；`network.md` 概览 / 人物档案**不重复抄健康明细**（如"最该记住：青霉素过敏"这类可留一句安全禁忌，
但指标/结论/病史不进概览）。导出与读取在 scope≠full 时再做兜底剔除（见 `consent_filtered_body`）。
