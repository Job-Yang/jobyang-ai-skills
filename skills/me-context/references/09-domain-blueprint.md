# 09 · 领域细分通用蓝本（任意垂直领域如何并进 me-context）

> 健康是**第一个实例化**的领域，不是为健康专用。本文件抽象"把一个垂直领域（健康 / 财务 / 法律 / 学习 …）并进
> me-context"的通用骨架；健康按此骨架落地为 `profile/health.md` + `CONSENT-health.md`，其它领域可照套。
> 全程仍是**人读得懂的轻量 Markdown、零三方依赖、fail-closed**，不实现任何行业标准协议。

## 1. 七个通用要素（任何领域都按这七步落）

### ① 领域分片（domain shard）
一个垂直领域 = 一个 Markdown 分片（`profile/<domain>.md` 或 `entities/<人>.md` 内一节），
frontmatter 复用 `personal-context/v1`：`schema / entity / layer / source / updated / domain / audience`。
人可读、可审、随文件夹搬走；不引数据库、不引行业专有格式。

### ② 敏感层映射（该领域落 L0-L4 哪层 + audience）
按"外发会不会造成伤害"把领域内容分到 L0-L4：
- L0 名片 / L1 公开画像 → cloud 默认可读；
- L2 一般偏好与概况 → cloud 按需；
- L3 敏感（健康、财务明细、家庭细节）→ 本地完整、cloud 逐次确认；
- L4 秘密（密钥、证件、私密事件）→ 永不入云。
`audience: local` 标在分片上，与层门禁配合。

### ③ 本地授权档（需要时一个 `CONSENT-<domain>.md`）
涉及高敏领域时，在数据仓根放一份人可读可删的授权记录，四档通用：
`full`（完整记录+解读）/ `facts_only`（只记事实，不给评估/计数/趋势）/
`index_only`（只存原件本地索引，不出结构化解读）/ `off`（暂不记录）。
显式同意、可撤回、可缩范围；**无授权 fail-closed**（不主动问、不写、读取也不输出结构化正文）；
它与"上云 L3 逐次确认"是**两道独立开关**（本地先过授权门，上云再过 L3 门）。撤回不删历史，只停后续。

### ④ 提取协议三分（当轮 AI 读原始材料后怎么落）
当轮 AI（Harness 层直接读 PDF/截图/口述，本技能不做导入器）把原始材料分三层：
1. **结论/评估原文** → L1 结论区，原文保留不改写；
2. **关键结构化少数项** → L2 只取决策相关的一小撮，带值/单位/来源/日期/方法；
3. **原件只索引** → 本地路径，不搬正文、不内嵌。
其余数值/细节一律不抄（降噪）。

### ⑤ 最新 + append-only 历史 + 读时派生标签
- 主表永远是**最新权威值**；更新前先把上一份最新状态整体追加进**历史快照（append-only，只增不改不覆盖）**，再写新值。
- 变化标签**读时派生、不写死**，分**三级置信**：高置信（同机构+同方法+同单位、两点都可信、幅度明确）出方向箭头；中置信（跨机构但标准化项、单位可换算归一）给软方向"大致好转·仅供参考"；不可比（单位无法归一/方法标本明显不同/单次/不可信）不判方向。每个领域自定义"什么算显著变化"准则，借 RCV/delta-check 思想做生活辅助级，不伪算精确常数。
- **freshness / 复核周期（通用，挂钩 03 与 v11 checkup）**：稳定事实标 `stable`（基本不变，长复核周期）、当前事实标 `current`（易过期，短复核周期，如近期目标/在做的事）；易过期领域定期复核，到期未复核只弱提示"可能过期"、不静默当现状，体检/清理只列不删（见 `lint.py --checkup`，删除/转历史人工确认）。

### ⑥ 最小切片 gate（scope × layer 双重裁剪，含跨文件夹句级过滤）
读取按 `--domain` 切出该领域分片；先过本地授权 scope（off/index_only/facts_only/full），再过 layer 门。
不止裁剪本领域分片：散落在概览/他人档案里夹带的该领域敏感句，也要按 scope **子句级**剥离
（只留安全事实子句，删掉非安全子句，无安全子句则整句去掉），堵住"换 domain/换导出路径绕过授权"。

### ⑦ 不越界（专业判断归外部专业角色）
档案只负责**组织事实、分层、留痕、提示**；诊断、投资建议、法律意见、用药剂量等专业判断一律归医生/理财师/律师，
档案不替专业角色下结论、不给处方/建议剂量/买卖指令。

### ⑧ 关注因子 / 活动问题清单（可选，只改呈现重点）
任何领域都可有一份本人"关注项/活动问题"（健康=watchlist，财务=本人重点盯的目标指标）：
- 三来源：既往/规则自动关联（仅由已记录事实触发，不给无事实者硬安）、本人明说、AI 提议经本人确认；未确认是建议态不生效；可删、删后不自动重加。
- 详略三档：异常/待办固定呈现；关注项即使正常也显示+一句情境；其余正常/无关项折叠只计数索引。
- 只在**本授权域内**构建，不读无关分片；只改重点详略，不越界下结论。

## 2. 理论 → 设计映射（借思想，不实现协议）

> 下列标准/理论只为设计背书，**本档案仍是轻量 Markdown，不实现 FHIR、不引 JSON、不做标准编码**。

| 理论来源 | 借的思想 | 我们的落点 |
|---|---|---|
| **FHIR Observation / valueQuantity / referenceRange** | 一个测量结果 = 指标码 + 数值 + 单位 + 时间 + 本院参考区间 + 状态 + 来源 | 指标点字段 `analyte/value/unit/ref_range/date/lab/method/preconditions/provenance/confidence`（Markdown 轻量版，不建 FHIR resource） |
| **FHIR DocumentReference** | 存元数据+访问位置，不内嵌整份文档 | "原件索引"只存本地路径，不搬 PDF 正文 |
| **FHIR Narrative** | 人话摘要与结构化事实并存、可单独给人读 | 整份 Markdown 即 narrative，结论人话与指标行共存 |
| **HL7 IPS** | 用户拥有、可携带的最小必要摘要（过敏/用药/问题清单为必含） | 过敏·在服药·禁忌 → 最新关键指标 → 结论区的最小分区排序 |
| **LOINC 六轴（成分/属性/时间/标本/刻度/方法）** | 同名指标方法/标本不同不可直接比 | 同院同法同单位=high；跨院标准化项可换算/方法相容(含未写方法)=mid 软方向；方法写明冲突/非标准化项缺方法=不比。LOINC 码仅可选预留，不强制 |
| **OMOP CDM MEASUREMENT** | 标准概念 / 数值 / 标准单位 / 来源原值分列 | 原始值/原始单位照抄、本院参考区间照存；仅标准化项在标准化单位间归一后跨院软比较，非标准化项不换算 |
| **POMR / SOAP** | 客观 O、评估 A、计划 P 分开；A 由医生 | 指标表=O，结论区=A（仅建议非诊断），复查计划=Plan；主观 S 可选 |
| **EP28-A3c 参考区间概念（思想借用）** | 参考区间是健康人群中间多数，按通用实验室原则单次出界 ≠ 有病 | 单次出界只建议复查，persistent 要 ≥2 次，resolved 留历史不删 |
| **EP33 Delta check（思想借用）** | 相邻差值超阈值只触发复核，可能是标本差错非真变化 | 差值小/条件不一致一律 fluctuating，可疑挂 needs_review |
| **RCV（参考改变值，原则借用）** | 差值超 RCV 才大概率是真变化 | 个人档案无 `CV_i`/`CV_A` 与质控，**不伪算精确 RCV**，只写原则门 |
| **ICF（功能视角）** | 关注身体功能/活动/参与，而非只看病名 | 记录与生活/健身/目标相关的功能上下文；关注人和功能 |
| **ICD-11** | 面向统计/报销/临床的诊断编码 | 不实现编码、不自填 ICD 码，医生结论按 doctor_diagnosed 原文照录，ICD 仅可选术语参考 |
| **WHO STEPS** | 慢病危险因素核心项按需采集 | 生活方式只记决策相关行为因素，不做全量问卷、不算个人风险评分 |
| **DRIs 2023（数值为二手旁证、以纸书为准）** | 推荐摄入量是群体参考，非个体处方 | 营养给区间不给处方，临床营养治疗转医生；具体克数不写死、以正式纸书为准 |
| **DIKW 分层** | 原始数据→信息→知识→智慧需逐层提炼降噪 | L1 结论 / L2 关键项 / L3 原件索引，决策智慧属本人+专业人，AI 不替代 |
| **PIPL §28/29 + GDPR Art.9** | 健康属高敏/特殊类别，默认禁止、靠单独明示同意 | 本地授权门（先）+ L3 云门（后）两道，最小投喂、可撤回、用完不留 |

## 3. 第二领域套演：财务（证明蓝本不是健康专用）

按七要素套一遍财务：

1. **分片**：`profile/finance.md`（domain=finance，复用 personal-context/v1）。
2. **敏感层**：财务明细/账户余额落 **L3 / audience local**；公开的理财偏好/目标可放 L1-L2。
3. **本地授权档**：需要时 `CONSENT-finance.md`（full/facts_only/index_only/off 四档同构），无授权 fail-closed。
4. **提取三分**：财务目标/约束原文 → 结论区；关键结构化只记**区间**（如"每月可结余约 X 元、应急金目标"），**不记精确密码/卡号**；账单原件只留本地索引。
5. **最新+append-only**：主表记最新区间快照，历史只增不改；领域标签自定义为"现金流变化（改善/紧张/持平）"，读时派生。
6. **最小切片**：gate `--domain finance` 先过授权 scope 再过 L3；entities/概览夹带的财务句同样子句级剥离。
7. **不越界**：只组织目标与约束，**不给投资建议、不做买卖指令、不推荐具体标的**（归持牌理财师）。

可见七要素与领域无关，健康只是第一个实例。
