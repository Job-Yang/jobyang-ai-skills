# 00 · 收录宪法（写入门禁，全技能最高取舍准则）

> 这是"什么该进 me-context、什么不该进"的根本法。写模式（建档/补记/inbox 升格）动手前先过本宪法；
> 它优先于任何"多记一条总没坏处"的冲动。语气克制、可执行，每条都配正反例。
> 本宪法只管**取舍与去向**，不改 L0–L4 层门禁，不改 fail-closed。

---

## 1. 定位：降噪，不是聊天数据库

me-context 只存**"影响我和 AI 之间决策的核心信息"**——关于我这个人、稳定、以后帮我做判断时用得上的事实与偏好。它是降噪后的浓缩，不是对话录像。

- **全量对话、过程琐事、任务流水归各 harness / 项目记录，me-context 不碰。** 今天聊了什么、怎么一步步做的、临时改了几次主意，留在会话或项目笔记里。
- **本技能明确不监听日常对话。** 它没有后台进程、不会 7×24 偷听（见 05 §3 诚实边界）。"没偷听"是优点：既不打断，也**主动缩小了记忆投毒面**——没进来的东西就污染不了以后的判断。
- 记忆越满，重要的东西越被冲淡（见 §5）。少而准 > 多而全。

---

## 2. 两种合法采集（没有第三种）

| 采集源 | 怎么发生 | 落盘节奏 |
|---|---|---|
| **① 用户主动给** | 用户明说"记一下 / 建档 / 更新档案 / 记住这个" | 走 05 批量确认协议，确认才 declared |
| **② 当轮对话听到稳定个人事实** | 就在当前任务对话里，自然听到一条稳定事实 | 收尾**顺口问一句**要不要记，用户确认才进 inbox；**不打断、不追问、不翻旧账** |

顺口问的一句话模板（不施压、可拒绝）：

> "这条我先记进候选，你点头我再写进档案；不想记就当我没说。"

- 源②**一律先 inbox 草稿**，不直接 declared；用户说"整理下新记忆"时再裁决。
- 不是这两种来源的（网页/文件/第三方返回），永不自动落盘。

---

## 3. 收录三问（都过，才可能进正式档案）

一条候选，先连问三句，**三问都答"是"**才够格进核心 MD；任一为否，走 §4 四去向。

1. **是"我这个人"，还是"一件事 / 一种方法"？**（关于我：身份、身体、家庭、职业底色、稳定喜好、沟通偏好；方法/规矩归 harness 或技能）
2. **几周后还成立、还能复用吗？**（稳定，不是今天才变、很快会变的临时状态）
3. **会影响以后 AI 怎么帮我做判断 / 做决策吗？**（不相关就不值得占核心层）

边界模糊时用最简标准收口：

> **"以后帮我做决定时，这条会让它更懂我吗？"** 不会，就不记。

---

## 4. 四去向判定表（每条候选先归一个去向）

**A/B 判别式（先判这条约束的对象是谁）：**

- 约束"**我这个人平时希望你怎么对我、怎么跟我说话**"——跨所有任务都适用的相处/沟通方式 → **A 进 me-context（preferences）**。
- 只约束"**某一类产物怎么写/怎么做**"——某类文档、代码、发布稿、特定工具流程 → **B 进对应技能/harness**。
- 同一句话既可读成相处方式又可读成产物规范时，**按它主要约束的对象判**；仍模糊就顺口问一句，或默认记 A（可迁移偏好）但标注可分流。

| # | 去向 | 判定 | 真实例子（括号内为 stable/current） |
|---|---|---|---|
| **A. 进 me-context** | 关于我 / 稳定 / 影响决策 | · 工作日别报（**stable**，工作偏好，记 preferences）<br>· 花生过敏（**stable**，健康禁忌 L3，最高优先）<br>· 做技术架构的 / 职业底色（**stable**，identity/work）<br>· **先给结论再展开、别绕弯子、别反问一堆**（**stable**，跨场景沟通方式 → preferences）<br>· 不吃香菜（**stable**，饮食偏好）<br>· 家人事实 / 送礼日程（**stable/按 L 级**，关系人 inner，家庭决策相关）<br>· 收支 / 财务约束（**stable**，本地 L3，只记区间不记账户密钥）<br>· 我现在在做什么方向、近期目标（**current**，work/goals，易过期，按 §7 标 current 定期复核） |
| **B. 进技能 / harness，不进 context** | 只约束某类产物/工程，不是"我这个人" | · **小标题别玩花样**（某类写作产物的排版规范 → 写作技能/harness）<br>· commit 前必须跑测试（**工程规矩 → 工程规则**）<br>· 画图统一某种风格、技能发布不带个人信息、三层架构不许越界（**工具/架构约定 → harness/技能**） |
| **C. 不记** | 任务安排、一次性分工、会过期的指标/待办/感想、临时状态 | · 找老板对齐我来做（**一次性任务分工，current 但不归我，不记**）<br>· 明早检查 X（**一次性待办，不记**）<br>· 某 Transition 指标数值（**会过期的指标，不记**）<br>· 在玩小游戏（**当前事实 temporal，会过期；不进核心，顶多 inbox 留一句或不记**）<br>· 一次性感想（**不记**）<br>· 今天吃了啥 / 现在心情 / 临时很忙（**易变临时状态，不记**）<br>· 老婆小时候的某件事（**事件细节，除非标重要/反复相关，否则不进核心**） |
| **D. 只放索引** | 作品 / 长文 / 资料，原件留在 GitHub / jobyang / 飞书 | · 自己写的文章、做过的项目作品、收藏的长资料（**只在 ME/索引里留一条链接+一句话，不搬正文**） |

> 记忆项的稳定度另标 `freshness: stable|current`（见 §7 与 03 schema），它和"进不进"是两件事：
> 进 A 的也分 stable（身份/禁忌/偏好）与 current（在做什么/近期方向）。

### 4.3 判定收口细则（易混场景各一句）

1. **爱好稳定阈值**：被称作"长期爱好 / 一直喜欢"、持续多年的 → A stable；"最近在玩 / 在刷"的新鲜劲默认 C，不追问、不进核心。
2. **一句话混了 durable 事实与一次性动作**（如"老婆生日想着送礼"）→ 先拆：稳定的关系、生日、送礼偏好记 A（network/家庭按 L 级），"想着送礼"这个一次性提醒动作不记。
3. **同文件 stable 底色 + current 方向并存**（如职业底色 vs 当前在做）→ 文件内分"底色(stable)/当前在做(current)"两段；条目级 freshness 先作文档约定，代码本轮不强制。
4. **目标 vs 指标**：有"我要做到 / 本季度完成"的承诺主语与推进动作 → A current；旁观数值/结果统计（某指标涨跌）→ C。
5. **备孕等家庭计划**：记，但属敏感家庭共同计划、只在本地（与 entities 家庭分区/相应 L 级一致），不进 cloud。
6. **D 只放索引要有落点**：作品/长文在 ME 公开链接或一个 links/作品索引位放"一句话+链接"，正文不搬、viz 只展示链接（说明现状即可，不新造复杂结构）。

## 5. 三条底层原则

- **信息全交出会冲淡重要的东西。** 核心层容量有限，堆进任务流水和临时感想，真正的禁忌/偏好就被淹没了。
- **输入垃圾，决策垃圾（GIGO）。** 记了会过期的任务、一次性分工，AI 以后会拿它当"你这个人"去做长期判断，反而出错。
- **declared > inferred，人裁决。** 声明永远压过推断；候选去留、升格、删除、转历史，一律用户拍板，工具只建议、不自动删（见 §7）。

---

## 6. 敏感边界（沿用现有 L0–L4 与 ask gate，宪法不改层门禁）

- **家人关系该记**：送礼、日程、家庭决策、稳定喜好按 L 级进 inner 实体；不整份堆一个家庭大文件。
- **备孕 / 身体病史 / 财务**仍按现有 L3 只在本地、逐次确认、需要时才用；L4（密钥/证件/密码/秘密）永不入云、永不导出、永不投喂。
- 宪法的取舍结论**不绕过任何层门禁**：一条"该记"的事，属于 L3/L4 仍按原规则锁。

---

## 7. 断舍离与时效（宪法必备条款）

档案不是只进不出。**current（在做什么/近期目标/当前方向/in_progress）会过期**，到复核期不复核就不能继续被当成现状。

- **stable（稳定事实）**：姓名/出生地/身份底色/禁忌/长期偏好等基本不变，复核周期 90–180 天。
- **current（当前事实）**：在做什么/近期目标/当前方向/近况，显式标 `freshness: current`，复核周期 30–90 天。
- **到复核期未复核的 current**：不静默当现状，读取/展示给"可能过期（N 天未更新，上次更新 X）"弱提示；超更久（建议 180 天）体检时问"还成立吗？不成立就清/转历史"。
- **`stale: true`** = 已归档，不再当现行事实。需要留经过的（体检数值、重要决定的理由）进过程层 `journal/`，见 03 §1.1。
- **体检/清理只列不删**：`lint.py --checkup` 输出五段，全部只读、人工确认才动手——`[a]` 超期未复核的 current（"可能过期"强提示）、`[b]` 超 60 天未确认的旧 inbox 草稿、`[c]` 待人工冲突、`[d]` 疑似过程/任务误入、`[e]` stable 年度回看（updated 超 360 天的稳定分片，仅中性"可顺手回看是否仍准确"，**stable 不判过期、非阻断**，区别于 [a] 的强提示）。删除/合并/转历史一律人工确认。**提示绝不改变层门禁与 fail-closed。**
- 默认要保守：稳定身份类（姓名/出身/长期禁忌）不误报过期。

## 8. provenance 预留（本轮只设计字段，不强制）

每条将来可带来源与日期，便于追溯与复核（本轮可选填，完整强制留后续轮，避免返工）：

```yaml
provenance: 建档 | 当轮对话 | 公开主页刷新 | 文件导入
provenance_date: 2026-10-20
```

- `建档`=首轮访谈；`当轮对话`=任务中顺口确认；`公开主页刷新`=从公开主页同步；`文件导入`=从文件/网页导入。
- provenance 只做记录，不参与层门禁判定；缺省不编造。
