# 05 · 写协议：两源进 inbox、批量确认、写探针、记忆取舍

---

## 1. 两源都先进 inbox

| 源 | 内容 | 去向 |
|---|---|---|
| 源 A 访谈作答 | bootstrap/定向访谈的答案 | 当轮已确认的可直接 declared 落正式分片；**未经确认的进 inbox** |
| 源 B 日常对话观察 | AI 从对话里观察到的候选偏好/事实 | **一律先 inbox**，不直接落正式档案 |

inbox 候选草稿字段（见 `templates/inbox/_draft-template.md`）：
`status: draft`、`source: observed|inferred`、`quote`（原话可空）、`date`、`suggest_layer`、`suggest_domain`、`suggest_entity`、`reason`（相关度理由）。

- **gate 永不扫描/加载 inbox；export 默认排除 inbox。**
- inbox 是候选暂存，与正式档案物理隔离；lint 不对 inbox 草稿做严格 schema 校验。

---

## 2. 批量整理确认协议

用户说"**整理下新记忆 / 更新档案 / 看看 inbox**"时：

1. 列出 inbox 里所有候选草稿（不直接投喂其内容给外部）。
2. 逐条走：**采纳 / 修改 / 否决 / 升级重要度**。
3. 仅"采纳"项转 declared 正式落盘：写到对应 profile/ 分片或 entities/<人>.md；旧条目 supersede 留痕；CHANGELOG 记一行。
4. 否决项删除草稿或归档；修改项改完再落。

铁律不变：**未确认不落盘**；外部内容（网页/文件/聊天/第三方返回）永不自动落盘。

### 2.1 访谈节奏：句中轻确认 + 收尾一次性汇总

- 自然访谈中 AI 在心里记，对事实顺势一句轻确认（"行，那我记下你是夜猫子、最近在转 AI 方向"），
  **不逐条停下审批、不发清单式复述**。
- 完整大白话汇总确认放到**整段聊完或用户要结束时一次性做**；未确认内容仍先进 inbox 草稿，确认后才 declared。
- 禁止报表式：不编号列表一次抛多题、不说"一次问三题/答完复述落盘/下一个是 XX 包/模块进度"。

### 2.2 信任梯度 T0/T1/T2 与召唤制（写死）

- **T0** 建档即可自然聊；**T1** 建立信任后/用户主动聊到顺带问，不做固定轮次；
  **T2 高敏绝不主动批量问**（收入/具体财务/负债、详细病史/体检/长期用药、婚姻家庭细节、证件号）。
- **T2 触发三条件，缺一不可**：①当次任务显式需要（做理财/预算、健康用药咨询）；②已向用户说明用途与"只存本地/可不给"；
  ③用户愿意给。就这一个用途、就事问最小一条；收入优先用职业/城市/资历作低置信弱假设，不主动索要精确值。
- **禁止 onboarding 主动问 T2；禁止建档结束后自动按顺序推进财务/健康包**。深度包是用户召唤制，
  收尾只允许轻描淡写一句："以后想让我帮你管健康、做财务规划，随时说，我再就那件事问你一两条，平时不打听。"

### 2.3 当轮顺口问（源②，不打断、可拒绝）

当轮对话里听到一条**稳定个人事实**，收尾顺口问一句即可，不打断当前任务、不追问、不翻旧账：

> "这条我先记进候选，你点头我再写进档案；不想记就当我没说。"

用户确认才进 inbox；拒绝就丢弃。本技能**不监听日常对话**（见 `00-constitution.md` §1），没有第三种采集方式。

## 3. 写探针 + 触发两档

本 skill 没有前端表单；采集是**对话式引导访谈**。探针分两档：

### 默认唤起档（所有宿主）
- 普通闲聊**零加载、零抓取**；不主动翻档案。
- 仅当用户明确说"记一下 / 更新档案 / 记住这个"，或任务明显涉个人上下文时，才用**几百字轻探针**（不读取画像内容）发现稳定新事实 → 追加 inbox 候选。

### 可选常驻档（仅支持用户级常驻指令的宿主）
- 在 `CLAUDE.md / AGENTS.md / custom instructions` 放一句观察指令：发现候选时问一句"要不要记一笔？"。
- 即使用常驻档，候选也**只进 inbox**，不直接 declared。
- 不支持常驻指令的宿主自动回退唤起档。

### 诚实边界（写死）
纯 skill 无后台进程、无守护进程，**做不到任意宿主 7×24 无感监听**；常驻档依赖宿主本身的常驻指令能力。

## 4. 记忆取舍：三问 + 四去向（inbox→正式分片升格的强制门禁）

> **先读 `00-constitution.md`（收录宪法）**。一条 inbox 候选要升格进核心 MD，必须先过**收录三问**、
> 并明确归入**四去向**；答不上三问或去向不是 A（进 me-context），就**不建议升格**（留 inbox / 丢弃 / 转索引 / 分流工程规则）。

### 4.1 升格前必答：收录三问（都为"是"才可能进）

1. **是"我这个人"，还是"一件事/一种方法"？**
2. **几周后还成立、还能复用吗？**
3. **会影响以后 AI 怎么帮我做判断/决策吗？**

模糊时用最简标准："以后帮我做决定时，这条会让它更懂我吗？"不会就不进。

### 4.2 四去向（每条候选必须明确归一个）

**A/B 判别式（详见 00 §4）**：约束"我这个人平时希望你怎么对我、怎么跟我说话"（跨所有任务的相处/沟通方式）→ A；只约束"某一类产物怎么写/怎么做"（某类文档、代码、发布稿、工具流程）→ B。同句两可时按主要约束对象判，仍模糊顺口问一句或默认 A 但可迁移。

| 去向 | 处理 |
|---|---|
| **A 进 me-context** | 关于我/稳定/影响决策；**先给结论、别绕弯子、别反问一堆属跨场景沟通方式（preferences）** → 落对应 profile/ 或 entities/，标 freshness |
| **B 进技能/harness** | 只约束某类产物/工程：小标题别玩花样、commit 规范、画图风格、发布去个人化 → 分流到对应技能/工程规则，不抄进 context |
| **C 不记** | 任务安排、一次性分工、会过期指标/待办/感想、临时状态 → 丢弃 |
| **D 只放索引** | 作品/长文/资料 → 原件留 GitHub/飞书，只在索引留链接+一句话 |

> 旧"四问"（稳定/决策相关/用户标重要/层合适）并入本门禁：用户标重要、层合适作为 A 去向的补充判断，不替代三问。

### 记 / 不记对照

| 内容 | 处理 |
|---|---|
| "老婆小时候的某件事" | 默认属**事件细节、不进核心层**；除非用户标重要 / 与禁忌喜好或反复决策相关。可在其 inner 实体留一条带日期的轶事，或直接不记 |
| 一次性闲聊（今天吃了啥） | 不记 |
| 易变临时状态（现在心情/临时忙） | 不记 |
| 密钥/证件/隐私事件 | L4，永不入核心、永不导出 |
| 未经确认的推断 | 留 inbox，不升 declared |
| 他人敏感隐私 | 不记，或只记用户明确要求的梗概 |
| 稳定偏好/禁忌/目标/沟通方式 | 记（declared） |

### 容量预算

- `ME.md` ≤ 约 2000 字；
- 单个 inner 实体核心 ≤ 约 1500 字（close/peripheral 更短）；
- 超限把细节下沉为摘要，核心只留决策相关稳定条目。

## 5. 作用域边界：me-context 只收"你这个人"，不收"AI 怎么干活的规矩"

me-context 是"我这个人"的中心，**不是**"AI 怎么干所有活的规矩"的垃圾桶。工程/研发/做技能的规矩由
personal-harness / iLoop / 各专项技能 / CLAUDE.md·AGENTS.md 负责，**me-context 不收、建档时也不问**。

只沉淀两类：
1. **关于"你这个人"的事实**：身份 / 身体 / 健康 / 家庭 / 职业方向 / 喜好。
2. **全场景通用的 AI 协作偏好**：结论先行、给一个推荐、别反问、格式语言等——不管聊什么都适用。

**一律不写进 me-context**（属 harness 或具体技能/项目规则）：
自检/对抗验证方式、git commit 频率与规范、架构分层（如"三层不许越界"）、技能发布与去个人化带版本、
编码/绘图/文档规范、某工具/某仓库/某宿主的约定。**不新建 workstyle/engineering 文件、不加 engineering domain**。

### inbox 候选的 scope 字段（可选，仅记账）
inbox 草稿可带 `scope: general | engineering`（默认 `general`，不出现在对话黑话）：
- `general` → 正常走四问，采纳后落 profile/* / entities/。
- `engineering` → **不得升格进 profile/**；确认环节走下面分流话术，提示用户写到工程规则处。

### 整理时的分流规则与话术
用户"整理新记忆/更新档案"时，遇到 `scope: engineering` 或工程类候选，对用户说大意：
> "这条是你做研发/做技能时的规矩，有专门的工程规则/技能管，我不放进你的个人档案；
> 需要的话我可以帮你写进工程规则（CLAUDE.md/AGENTS.md 或对应技能）。"

判定示例：
- **进 me-context**：你有花生过敏；你是做技术架构的；你喜欢先看结论再看过程；你不吃香菜。
- **不进（分流到工程规则）**：commit 前必须跑测试；画图统一用某种风格；技能发布不许带个人信息；三层架构不许越界。

> scope 是**可选**字段：inbox 草稿豁免严格 schema、正式 profile frontmatter 不要求 scope；
> lint 绝不因缺 scope 报错；gate/export 完全不读 scope，切片/层级/导出行为不变。
> lint 还会对疑似工程类草稿给 `scope: engineering` 的启发式 WARN（仅提醒、不改写、不影响通过）；
> 但最终 scope 判定与分流仍由用户在确认环节拍板（工具建议、人裁决，与 contestable 立场一致）。

## 6. 落盘温度风格（写给将来自己看的人话，不是招聘简历）

落盘是把事实写成**完整人话**，viz 展示层会自己排版，不要为了"好看"先写成战报：

- **事实记完整**：一件事的单位、角色、区间、做了什么自然写进句子；指标数字（增速/时长/访问量）放句尾作灰色旁注，不做大数字胶囊、不堆"核心能力/代表作/履历"这类招聘硬词。
- **一句话定位放最前**：事业分片第一条用一句大白话说"你现在在做什么、往哪走"，后面再补履历/能力/项目。
- **待补不硬凑**：领证/结婚年份空着就留"待补"，别编；viz 会用虚线占位提示"等你想起来再补"。
- 只改展示、不改写已落盘内容；本条只约束今后新写。

## 7. 断舍离 / 体检 / 时效（temporal 与 stale）

档案只进不出会被过期信息稀释。新写时就标时效，定期体检清理。

### 7.1 stable vs current（写时标注，缺省按域）

- **`freshness: stable`**：姓名/出生地/身份底色/禁忌/长期偏好等基本不变；复核 180 天。
- **`freshness: current`**：在做什么/近期目标/当前方向/近况（work/goals 的"最近在忙""当前最在意"），易过期；复核 60 天。
- 不显式标时按域默认（work/goals=current，其余=stable，见 `03-storage-schema.md` 默认表）；稳定身份类保守，不误报。

### 7.2 过期不静默当现状

- current 到复核期未复核：读取/展示给"可能过期（N 天未更新，上次更新 X）"弱提示；**不删除、不改层、不 fail-closed**。
- 超 180 天：体检时问"还成立吗？不成立就清/转历史"。
- `stale: true` = 已归档，不再当现行事实；要留经过的进过程层 `journal/`（见 03 §1.1）。
- health/finance 即便 current 也仍受 L3 锁，提示文案本身不含敏感细节，cloud 不借此带出明文。

### 7.3 体检（用户说"体检一下我的档案 / 清理过期信息"时）

```bash
python3 scripts/lint.py --data ~/me-context-data --checkup
```

`--checkup` **只列不删**，输出五段，全部只读、人工确认才动手：

- `[a]` 超期未复核的 current（**"可能过期"强提示**，到复核期未复核、不能继续当现状）；
- `[b]` inbox 堆超过 60 天未确认的旧草稿（建议丢弃或归档）；
- `[c]` 显式 `conflict: needs_review` 的待人工冲突；
- `[d]` 启发式疑似过程/任务误入（待人工确认，不自动判错）；
- `[e]` stable 年度回看：updated 超 360 天的稳定分片，仅中性"可顺手回看是否仍准确"，**stable 不判过期、非过期、非阻断**，区别于 [a] 的强提示。

**删除/合并/转历史一律人工确认**（人裁决），脚本不自动改任何文件。普通 `lint.py` 的过期项只给非阻断 WARN，rc 仍 0。

## 8. 健康采集：召唤制 + 先选授权档（T2，不主动盘点）

健康是 T2：建档 onboarding **不主动推进**，只在用户当次健康/用药任务召唤时进入。首次进入先请本人显式选授权档，不施压、可拒绝、可事后改，选完才生成根目录 `CONSENT-health.md`：

> "健康记录只存在你这台电脑上，不是诊断。你可以：完整记（full）、只记过敏/在服药这些事实不给趋势（facts_only）、只存体检原件本地路径索引（index_only），或先不记（off）。随时能撤回或缩小范围，撤回不会删掉已经记下的，只是之后不再记。"

- 选 full 才记录关键指标时序/结论；facts_only 只记事实；index_only 只留原件路径；off 不记录。
- **授权轻量化**：写授权四档一次给、长期有效、可随时撤回/缩范围；授权期内同范围新年检/口述补充默认直接记录不再每次问，只有写入范围扩大（facts_only→full 升级，或首次记精神/生殖/遗传等高敏类）才再确认；本地读随写开放，不另设读授权；上云仍另过 L3 逐次确认。
- 当轮用户自己问用药/急症，可就事给安全必要信息，但**不落盘、不视为授权**。
- 更新指标（写进过程层 `journal/health-metrics.md`）：先把上一份"最新状态"整体追加进**历史快照（append-only）**，再写新值；历史只增不改。写完同步结论层 `profile/health.md` 的「当前状态」：只写需要留意的项和方向（如"尿酸：偏高"），不写数值。趋势读时派生、三级置信：同院同法同单位=高置信出方向；跨机构但标准化项、单位可归一=中置信软方向（"大致好转·仅供参考"）；单位不可归一/方法标本不同/单次/运动守卫=不判方向。
- **拍饭/热量蛋白：逐顿不记**。当轮帮算蛋白/热量即算即走、不留存（逐顿是过程数据，不进档案、不膨胀）；仅用户明确要跟踪（减脂/增肌期）才写**轻量周期摘要**（如"近 7 天平均蛋白 X g/kg、平均热量缺口 Y、达标率"），进 `profile/body.md`（L2，不是 health L3），只保留最近一期、不存每顿；点餐当轮被动禁忌提示（结合健康异常）仍在，但**菜单本身不入档**。
- 不做诊断、不给治疗剂量、不主动推送监督；肿瘤标志物不普筛式吓人（见设计报告 §10 不做清单）。
- **提取规范见 `references/08-health-extraction.md`**：当轮 AI 读完 PDF/截图/口述后，先保留报告结论/医嘱，再把关键指标按**一项一行**的规范契约落盘；数值/单位/本院参考区间/定性结果原样保留，禁止把多个指标合并成一行，禁止把 `±/+ /++/阳性` 改成 0/1。原件仍留本地索引，me-context 不内置 PDF/OCR 导入器。
- **写后验收**：运行 `lint.py`；若已有 `full` 授权，再生成一次本地图谱，确认异常/临界项数量不为假零、低于下界显示“偏低”、尿蛋白/尿隐血等定性项未丢失、趋势没有使用无单位/无方法的猜测值。
- **源头规范**：健康明细只写健康分区；`network.md` 概览与人物档案不重复抄指标/结论/病史（安全禁忌一句可留），导出/读取在 scope≠full 时再兜底剔除。`lint.py` 会提醒：会默认带给外部 AI 的文件（L0/L1 且没标只在本机，含 `relations.md` 的边备注）、以及关系网概览里出现健康/财务细节。

## 9. 重要决定：只记少数几条，进过程层

- 只收改变人生走向的决定：换工作、搬家、大额花钱、家里大事。一年几条就够；日常选择、一次性任务按 00 宪法不记。
- 决定带来的**新事实**照常更新结论层（如换了工作就改 work.md）；**当时为什么这么选**才写进 `journal/decisions.md`，一条一行：日期｜决定｜主要理由｜放弃了什么｜回看日期（可空）。
- 只在用户明说"记一下这个决定""以后想回头看"时才写；不在每次给建议后自动记，也不要求每次回答都列用了哪几条档案。
- 过程层默认不加载：做新判断时不翻旧决定，免得被过去的选择框住；用户说"回头看看当时怎么想的"才读。
