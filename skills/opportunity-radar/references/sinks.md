# 记录出口（sink）契约

> 每日结果写到哪里、用什么格式写，是宿主参数，不写死在技能里。本文件定义 sink
> （记录出口）要满足的最少动作，以及已验证的几种接法。换出口时 daily-runbook 的
> 漏斗、评分、条目正文一律不变，只换这里的四个动作。

## sink 描述符

宿主参数里带一个 sink 描述符，字段如下：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| type | 是 | 出口类型，见下表；自定义出口写 `custom` |
| target | 是 | 目标地址：文档 URL、文件绝对路径或其他平台资源标识 |
| identity | 否 | 读写身份，例如飞书的 `--as user`；不填用宿主默认身份 |
| anchor | 条件必填 | 每日记录挂在什么标题或结构下，默认「每日记录」；文件类出口可省 |
| note | 否 | 出口限制备注，例如不支持 callout、表格的平台在这里声明 |

sink 描述符要原样写进定时任务的 query，任务每次执行照它操作，不猜、不换出口。

## sink 必须支持的四个动作

不管接到哪种文档，出口都要能完成这四件事；做不到的动作要在任务输出里明说，不能假装成功。

1. **可写性自检**：开始漏斗前确认目标存在、当前身份能读能写。不可写就按 runbook 的失败留痕处理。
2. **读历史**：能拿到已有的每日条目，用于整理 coverage.json 和跑 dedup。至少要拿到条目标题和日期；拿全文更好。
3. **按日期追加**：把当天条目插到最新位置（默认在 anchor 标题紧下方、最新日期在最上面）。只新增，不覆盖、不改历史。平台不支持插入位置时，退化为追加到 anchor 段落末尾，并在首次使用时说明顺序差异。
4. **写后回读**：写完重新读一遍，确认新条目在、历史条目没丢。回读和写入用同一条链路。

条目的富文本需求（黄色 callout、链接、十行表格、加粗）是内容契约的一部分。出口原生支持就照用；不支持时按平台能力降级，降级映射见下面的适配要求，但不许丢内容，也不许因此少写证据链接。

## 已验证接法

### type: lark-docx（飞书/豆包在线文档，默认）

- target：文档 URL；identity：`--as user` 用本人身份，换租户要重新登录。
- anchor 是一个 H1，标题默认「每日记录」。
- 读历史：lark 文档能力读 anchor 下方正文，整理 coverage 和 dedup 输入。
- 追加：插入到 anchor block 紧后方，不追加到文末。
- 写后回读：重新取文档正文，核对新 H2 在最上方、历史 H2 都还在。
- 富文本全部原生支持：callout、链接、表格、加粗直接用。
- 写入前先回读 revision，防止并发改动顶掉别人的更新。

### type: local-markdown（本地 markdown 文件）

- target：由使用者提供的文件绝对路径；identity 不适用。
- anchor 是一行 `# 每日记录`；文件不存在时新建并写入这行标题。
- 读历史：直接读文件，按二级标题（`## YYYY-MM-DD`）切分历史条目。
- 追加：把当天的 markdown 段落插到 anchor 行紧下方。
- 写后回读：重新读文件核对。
- 降级映射：callout 退化成引用块（`> `）开头的两段；表格保留 markdown 表格；链接保留行内链接；加粗保留。

### type: custom（其他平台：Notion、企业文档、wiki 等）

接新平台时，宿主自己回答四个问题，答得上来就能接：

1. 怎么确认目标存在、当前身份能写？
2. 怎么读出 anchor 下的历史条目标题和正文？
3. 怎么在 anchor 下插入一个带标题、段落、列表、表格、链接的新块，且不动旧块？
4. 写完怎么重新读回来核对？

把四个答案写进首次开启时的配置说明（可以作为 daily-setup 的附录留一份）。平台富文本能力缺什么就在 sink 描述符的 note 里声明，降级规则照本地 markdown 的映射：callout 用带 emoji 的引用或高亮块，表格用平台表格或等宽文本，链接不许丢。

禁止把出口做成「每天新建一份文档、链接发到别处」：追踪台是一份持续追加的文档，历史和去重都依赖它。
