# 一键开启每日雷达（给执行 agent 的说明）

> 场景：技能装好后，用户只说一句「按 opportunity-radar 装一个自动任务，每天给我召回」。
> 本文件是开任务的标准动作，照走即可，规则不要重新发明。每日怎么跑看 `daily-runbook.md`，
> 结果写到哪看 `sinks.md`。

## 开启步骤

1. **只问缺的参数，别让用户重讲规则。** 需要确认四件事，有合理默认就带默认值一次问完：
   - 时间：默认工作日早上（避开整点，沿用类似 `2 8 * * 1-5`），周末不跑；用户说每天就改 `* * *`。
   - sink：写到哪里。默认飞书在线文档；要新建就建一份，文档里放一个 H1「每日记录」。
   - 身份：默认用户本人身份读写。
   - 推送边界：默认只写文档、不发任何群或个人消息；用户明确要推送才加。
2. **前置自检**：确认 opportunity-radar、opportunity-scorecard、haohao-shuohua 已装好；
   `python3 scripts/collect.py --help` 能跑；联网可用。缺技能或没网，先告诉用户缺什么，不建空任务。
3. **sink 就绪检查**（按 `sinks.md` 的四个动作）：目标存在、身份能读能写；新建的出口要有
   anchor 标题；已有文档要能读到历史条目。
4. **用下面的模板生成 query**，只填宿主参数，漏斗和格式规则不复制进 query。
5. **建定时任务**：用宿主的定时任务能力创建，runtime 选能联网、能长期在线的环境（云端优先）。
   建好后把下次触发时间告诉用户。
6. **第一天留意信源**：首次跑完看漏斗里的信源异常，和 `references/sources.md` 对照；
   新环境的不可达清单不同就更新该文件。

## query 模板（方括号替换，其余原样）

```text
本次请求是由「[任务标题]」定时任务到时触发的。

执行已装好的 opportunity-radar 技能的每日值班手册：references/daily-runbook.md。
每日漏斗、深挖和评分门槛、静默日扩源、条目格式、失败留痕、输出格式全部照手册做，不另立规则。
技能从当前已安装的用户技能目录加载；深挖评分用 opportunity-scorecard（综合分由 score.py 机器产出），
写进文档的中文先过 haohao-shuohua 的 quick_scan.py；脚本计算用技能自带脚本。
不要下载、安装或更新任何东西。技能、脚本或登录态不可用时按手册「失败也要留痕」处理，
禁止编造机会或评分。

宿主参数（与手册默认值冲突时以这里为准）：
- sink：type=[lark-docx|local-markdown|custom]，target=[文档 URL 或文件绝对路径]，
  identity=[如 --as user；不适用写无]，anchor=每日记录。
  sink 的四个动作（可写性自检、读历史、按日期追加到 anchor 下、写后回读）照 references/sinks.md 做。
  每天只新增当天一条，最新日期在最上面，不覆盖、不改历史。
- 边界：[默认：不向任何群或个人发消息、不做推送；有其他要求写这里]。

最后任务输出只回三句话：当天结论（机会名称和综合分，或没有值得深挖的，或任务未完成原因）、
文档链接、漏斗各层数量和失败源。
```

## 迁移到新环境的检查单

- 三个技能版本一致（radar 0.4.2 起才有本手册和 sink 契约）。
- 新 sink 已过四动作自检；历史为空时第一天 coverage 照空文件跑。
- 新环境的信源可达性重测一遍，`sources.md` 的不可达清单按实测更新。
- 登录态失效属于运行期问题：按失败留痕写条目，再引导用户重新登录，不静默重试。
