# 每日值班手册（daily runbook）

> 0.4.2 起，每日定时任务的「怎么跑」全部沉在这份手册里。宿主的定时任务只负责
> 「几点触发」和一组宿主参数（结果写到哪个 sink、用谁的身份），再附一句
> 「执行 opportunity-radar 的 daily-runbook」。换公司、换调度平台、换记录出口时，
> 技能一行不用改，只换宿主参数。

## 宿主参数（定时任务里只留这些）

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| sink | 是 | 记录出口描述符（type/target/identity/anchor），结果写到哪、用什么格式写全由它定，见 `sinks.md`。默认是飞书在线文档；以后换成别的文档只换这个参数 |
| 运行日期 | 否 | 默认当天 |
| 工作目录根 | 否 | 默认当前会话可写目录，每日在其下建 `radar-<日期>/` |
| 调度频率 | 否 | 完全归宿主：cron、几点、只跑工作日还是每天，技能不关心 |

技能不内置任何 token、文档链接和调度器。宿主参数缺失时不硬跑：sink 缺失就在任务输出里说明缺什么，不写到别的地方。怎么一键开启每日任务（含 query 模板）见 `daily-setup.md`。

依赖：深挖环节调 `opportunity-scorecard`（十维评分）；结果文档是中文时，写前用 `haohao-shuohua` 的 `scripts/quick_scan.py` 过硬闸。脚本都在各技能自己的 `scripts/` 下，纯 Python 标准库，不安装任何东西。

## 每日漏斗

在工作目录根下建当天目录 `radar-<日期>/`，后面所有产物都落这里。

1. **采池**：`python3 scripts/collect.py --out <工作目录>`（默认 5 天窗口；需要时 `--since-days` 调整），得到 `pool.json`/`pool.md`，逐源记状态。退出码 4 表示所有源都空，按失败留痕处理；单个源 blocked 不算失败，只在条目的信源异常里记一笔。
2. **定镜头**：从追踪台历史整理 `coverage.json`（每天跑完追加一行 `<日期>: [<anchor>, <补位>]`），跑 `python3 scripts/rotate.py --date <今天> --coverage coverage.json`，拿当天的 anchor 垂直和补位方向（含 lens/keywords/queries）。追踪台是空的、第一天没有 coverage 时也照跑，rotate 接受空文件。
3. **过滤取证**：用镜头 keywords 在池子里过滤、归并相关信号，挑最强的几条；再用 `references/search-queries.md` 的词补网页搜——评论原话、谁在付钱、竞品和差评。信源可达性照 `references/sources.md`，不可达的源不硬搜，记进信源异常。
4. **候选落盘**：写成 `candidates.json`，依次跑 `scripts/dedup.py`（与追踪台历史去重）和 `scripts/freshness.py`。硬旗挡旧证据、垃圾源和 DUP；软旗（付费未验证、RELATED 等）只提醒补证，不挡候选。
5. **每天必须深挖一条，不许跳过**：从池子里选最值得看的一条补取证，再用 `opportunity-scorecard` 做十维评测，综合分必须由它的 `score.py` 机器产出，证据带 URL，跑完 `artifact_io.py validate`。
   - 综合分 ≥ 6.5：判「值得去验」。
   - 综合分 < 6.5：这条深挖照样保留，写清短板和补什么能改变判断；可以用同一套脚本试算「补上某一维会到多少分」，试算输入和分数都留痕。
   - 只有池子经多源扩搜后仍然没有任何带真实证据的候选，才写「当天没有值得深挖的机会」。
6. **静默日扩源**：连续两个工作日没有出 ≥6.5 的机会，下一次自动放宽——镜头扩到相邻垂直、对最强候选加做竞品和差评深挖，并在条目里标注「连续静默日扩源」。出过分线后计数清零。

宽进严出是总原则：召回尽量宽（默认窗口、全源、最新流和热门流都采），筛选严格。目标是每 1 到 2 个工作日产出一条值得深挖的机会。池子有几百条还写「没有」时，必须附上漏斗各层数量证明是筛掉的、不是没采到。

## 写进追踪台的条目规范

- 位置和写法由 sink 决定（见 `sinks.md`）：默认插在 anchor「每日记录」紧下方，最新日期在最上面。只新增当天一条，不覆盖、不改历史。
- 写入前先做 sink 可写性自检并读历史；写完按 sink 的回读动作核对新条目在最上面、历史条目没丢。
- 平台不支持 callout 或表格时，按 `sinks.md` 的降级映射写，证据链接不许丢。
- 读者只看结论，不写技能加载、脚本步骤、运行目录这类过程。

**有深挖结果时**，标题两选一：

- ≥ 6.5：`YYYY-MM-DD · 值得去验 · <名称>（<分数>）`
- < 6.5：`YYYY-MM-DD · 今天最值得看的一条 · <名称>（<分数>，待补强）`

正文固定五段，顺序不变：

1. 顶部黄色 callout 结论框：机会是什么（一两句话说清给谁、解决什么、什么形态）、综合分、值不值得去验。
2. 「机会和切口」：背景、为什么是现在、具体切口。
3. 「关键证据」：3 到 5 条，每条是事实加链接，写清出处和时间；没有链接的事实不写。
4. 「十维评分表」：十行，维度、分数、一句话依据；维度名称与 scorecard 完全一致。
5. 「短板和下一步」：没到线就写为什么、补什么证据能改变判断（含脚本试算分）；到线就写最小验证动作和风险。

末尾一行小字交代漏斗：`漏斗：采集 X 条，镜头命中 X 条，入候选 X 条，去重后 X 条（其中 X 条 RELATED），硬旗后 X 条。信源异常：<哪个源 blocked 或报错>，其余 X 个源正常。`

可以再补一小段「今天还看过」，用一两句话点过其余候选和没深挖的原因，让读者知道当天扫描范围，但不展开。

**当天没有值得深挖的机会时**（仅限池子扩搜后仍无真实候选），标题写 `YYYY-MM-DD · 当天没有值得深挖的机会`，正文写扫描过的方向、已有信号、为什么没有一条能深挖，末尾同样附漏斗数字。

中文写文档前跑 `python3 <haohao-shuohua>/scripts/quick_scan.py <条目文本>`，半角标点等硬闸项清零后再写；代码、URL、英文产品名里的半角符号属于豁免。

## 失败也要留痕

任何一步报错——技能或脚本缺失、文档登录态失效、网络全失败、文档不可写——都不能静默结束，也不能编造机会或分数：

1. sink 还可写：在 anchor 下新增当天一条，标题 `YYYY-MM-DD · 当天任务未完成`，正文写明失败步骤和原始报错。
2. sink 不可写：放弃写出口，在任务输出里完整写明失败原因和原始报错。
3. 全部源都空（collect 退出码 4）：按第 1 种处理，记为任务未完成，不写「没有机会」。

## 任务输出只回三句话

1. 当天结论：机会名称和综合分，或「没有值得深挖的机会」，或「任务未完成：原因」。
2. 追踪台文档链接。
3. 漏斗各层数量和失败源。

不向任何群或个人发消息、不做推送，除非宿主参数里显式要求。

## 新环境第一次开跑

照 `daily-setup.md` 走：装技能 → sink 就绪（建出口、放 anchor、过四动作自检）→ 用模板建定时任务 → 首跑核对信源可达性。
