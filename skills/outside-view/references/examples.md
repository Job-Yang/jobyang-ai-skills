# 路由例子与回归边界

只在以下情况读取本文件：

- `DIRECT / QUICK / DEEP` 路由拿不准。
- 维护 `outside-view` 的触发规则。
- 编写或执行技能回归测试。

普通任务不要加载本文件。

## 典型路由

| 请求 | 路由 | 理由 |
| --- | --- | --- |
| 把按钮文字改成“继续” | DIRECT | 纯执行，外部信息不会改变动作 |
| 根据给定段落做忠实摘要 | DIRECT | 任务要求保真，不应擅自扩充 |
| 已稳定复现空数组导致越界 | DIRECT | 现场证据可以直接定位，先修复和回归 |
| 计算固定调用量和单价 | DIRECT | 算术可以直接得到答案 |
| 已有六个可比项目的实际工期，判断当前点估算是否可信 | DIRECT | 参照数据已经给足，不因任务重要继续泛搜 |
| 确认 SDK 当前版本是否支持某 API | QUICK | 读取当前官方文档即可 |
| 确认公开协议对重试的明确要求 | QUICK | 核对正式规范和必要勘误 |
| 查询公开云服务当天价格 | QUICK | 核对官方定价和适用区域 |
| 五人团队是否应在三个月内全面迁移微服务 | DEEP | 高影响且现有证据不足，需要案例和失败边界 |
| 为大型 UIKit 应用制定两年 SwiftUI 迁移路线 | DEEP | 长期、难回退，会影响人员和组件体系 |
| 两个支付鉴权方案如何选 | DEEP | 高风险、多目标权衡，需要直接证据和反方 |
| 判断一份行业报告能否支撑产品决策 | DEEP | 需要审查方法、独立性和适用范围 |

## 容易误判的边界

### 重要任务不必然检索

一项三个月的重写计划看似应进入 `DEEP`。如果用户已给出多个高度可比项目的真实结果，且这些数据足以否定当前估算，应直接用现有证据裁决。影响等级决定验证强度，不自动产生检索义务。

### 能否否定与能否设计是两件事

现有材料可能足以否定“固定 top-10”一类简单方案，却不足以支撑完整替代架构、上线策略和参数选择。用户只问是否采用时可以 `DIRECT`；还要求设计重要替代方案时，要继续检查推荐部分是否有依据。推荐部分存在会改变行动的未知项，应进入 `DEEP`。

### 有冲突不必然深搜

厂商当前官方文档说 API 仍受支持但新增限制，三年前个人博客说它已废弃。先核对版本和适用范围。若冲突已由时效和来源直接性解释，`QUICK` 或 `DIRECT` 即可，不必为了“双方观点”继续找网页。

### 多数来源可能只有一个源头

四篇博客都声称审计要求必须采用 Event Sourcing，但它们引用同一篇文章。监管原文只要求审计记录不可篡改。四篇博客仍只算一份间接证据，不能按票数压过监管原文。

### 指标不同不等于结论冲突

框架 P 的吞吐高 30%，框架 Q 在小团队复盘中缩短交付周期。若当前目标是八周上线且流量中等，两份材料优化的目标不同。先设性能底线，再判断交付效率是否更符合当前约束。

### 停止搜索仍可保持 DEEP 判断

一次架构研究已经覆盖当前官方规范、独立基准、失败复盘和关键冲突。随后两轮新增结果都重复同一上游报告。此时停止检索，保留已有 `DEEP` 分析；停止不代表把任务改判为 `DIRECT`。

### 用户禁止外部访问

用户要求三年架构建议，同时明确禁止访问外部信息。遵守限制，走 `DIRECT`：只基于用户材料给条件化方案，说明假设和未知，不伪装成行业共识。

## 触发硬负例

以下请求不应加载本技能：

- 翻译、改写、格式整理。
- 只总结指定文章或给定材料。
- 查询天气、时间等普通实时事实。
- 用户明确要求搜索某份官方文档，且不需要判断来源冲突或决策影响。
- 执行已经批准的迁移方案。
- 修复已有稳定复现和明确错误栈的问题。
- 用两句话解释一个普通概念。

普通搜索任务由搜索工具完成。本技能只在“如何利用外部输入形成重要判断”时介入。

## 维护回归集

修改 `description` 或主协议后，至少覆盖：

- 纯执行、计算、摘要、本地证据各一个 `DIRECT`。
- 当前官方事实和公开规范各一个 `QUICK`。
- 架构选型、大型计划、高风险决策各一个 `DEEP`。
- 已有证据足够但任务重要的硬负例。
- 冲突已由版本或一手材料解释的硬负例。
- 重复来源导致信息饱和的停止案例。
- 用户禁止外部访问的边界案例。

分别测试：

- **触发精度**：该加载时加载，该安静时安静。
- **路由行为**：已有证据充分性优先于任务影响等级。
- **内容质量**：外部输入确实改变或限定判断。
- **执行成本**：记录工具调用、时延和输入输出长度。

开放题必须与无技能基线做盲化 A/B。交换候选顺序复评，避免位置偏差。不能只看答案更长或引用更多。
