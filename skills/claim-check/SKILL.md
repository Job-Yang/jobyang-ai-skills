# 说法核查 · 先拆开事实，再判断该信多少

> **一句话理论**：一句话里往往混着三种东西——**事实**（可被外部证据验证）、**推论**（从事实得出的结论）、**价值判断**（好坏取舍）。不加核查就全盘接受或全盘否定，都会上当。
> 方法来自**事实核查（Fact-checking）**与笛卡尔式**系统怀疑**：先拆，再只对事实验真，最后检查推论站不站得住。
>
> **它解决什么**：传言、截图里的数据、文章结论、方案承诺，到底能不能信、信到什么程度、最关键的漏洞在哪。
> **它不做什么**：不评判整篇文章（那是 `argument-reading`）、不在两个方案间抉择（`steelman-choice`）、不替某个决策做开放调研（`outside-view`）、不核查纯口味偏好。

## 触发与边界

| 情况 | 去向 |
| --- | --- |
| 一整篇新闻/长文/宣传文案要看论证质量与可信度 | `argument-reading`（整篇阅读地图） |
| A/B 两个方案都讲得通要选 | `steelman-choice` |
| 为某个技术/产品决定系统找外部证据 | `outside-view` |
| 只有价值偏好、无事实主张（"我更喜欢 X"） | 不核查，直接说明这是偏好 |
| 要的是摘要/翻译/转述，不问真假 | 不启用 |

与取证工具的关系：**离线也能用**——不联网时完成"拆解 + 推理审计 + 标注哪些必须外部验证"，但绝不能把没验证的说成已验证。宿主具备检索/网页能力时才做外部核查；需要为一个决策补多源证据的开放调研，交给 `outside-view`。

## 核查流程

### 1. 拆解：把说法分成三堆

对输入逐条标注：

1. **可外部验证的事实**：数字、时间、事件、引语、因果性事实主张、来源声称。
2. **从事实推出的结论**：作者/说话人基于事实的判断。
3. **价值判断/立场**：好坏、该不该、喜欢与否。

只对第 1 类做事实核查；第 3 类不争对错，但要点明它在结论里起了什么作用。

### 2. 事实验真（逐条，只查高影响项）

不做无差别核查。先问"这条事实若不成立，结论会怎样"，优先查影响最大的。每条给五级可信度裁决：

- **已证实**：可靠一手/独立来源直接支持，口径与时间范围相符。
- **基本成立但需收窄**：方向正确，但原说法在范围、程度、时间或条件上被夸大，需限定。
- **存在争议**：可靠来源之间有实质冲突，列出分歧点。
- **证据不足**：查了但现有来源无法判定。
- **明显错误**：可靠来源直接反证。

另外两个**过程状态**不算裁决，但必须显式标注，避免与上面五级混淆：**待外部核查**（值得查但当前条件不允许）、**未执行外部核查**（本轮根本没检索）——处于这两个状态时，结论只能是"暂不可信判定"，不许给五级里的任何肯定档。五级与过程状态的口径与 `argument-reading` 的事实核查规程保持一致，两个技能交叉引用时不产生第二套词汇。

来源纪律：

- 优先一手来源：官方机构、原始数据/报告/记录、论文、当事人原话；二手媒体只作线索。
- 链接必须真的指向原始发布者；只有媒体转述时写"媒体转述官方数据"，不得标官方来源。
- 作者自述、匿名转述、个案、历史类比、预测，可以引用但**不能算外部证实**，要保留证据类型。
- 多个页面转载同一上游说法，不算交叉验证。
- 记录来源标题、机构、日期与链接；没实际检索时禁止使用"支持/属实/已验证"等措辞。

### 3. 推理审计：事实成立，结论就成立吗

在"假设事实都成立"的前提下检查：

1. 这些事实能否推出当前结论？有没有推理跳跃。
2. 是否把**相关性当因果性**、把个例当规律、把短期当长期。
3. 藏着哪些未经验证的假设。
4. 是否遗漏了其他解释或关键信息（基数、分母、对照、选择性呈现）。
5. 结论在什么条件下成立、什么条件下失效；统计口径、样本、时间窗口是否一致。

### 4. 输出

```text
原说法：……
事实部分及可信度：逐条 [已证实/需收窄/争议/不足/错误] + 来源与日期
需收窄之处：原说法哪里被夸大或越界
推理链关键漏洞：……（或"推理基本成立"）
补强后的最合理版本：……
当前可以相信到什么程度：一句话置信结论 + 还需验证的关键一项
```

用户只要快速判断时，给精简版：结论可信度 + 最关键的一条依据 + 最大疑点。

## 可感知信号（触发宣告与收口）

命中本技能并完整走流程时：

- **开头一行轻量宣告**：`〔思考：说法核查〕把这条说法拆成事实/推论/立场，只对事实做可信度判定`，让用户知道是哪个技能在起作用、这轮要做什么。一句话快答或顺带提一句时不贴标签。
- **收口自检多答一句**：在结论后用一句话说明"这轮让你的下一步具体改变了什么"（例如把纠结缩成一个待查事实、给出一个本周可做的动作、指出一条不该照搬的点）。读完仍不知道下一步该干嘛，视为本次失败，重做。

好坏的用户体感判别与反馈话术见仓库 `docs/SKILL-QUALITY-CARD.md`。

## 防失败模式（硬规则）

- **没查就是没查**：未实际检索时只能写"证据不足/待核查"，严禁凭模型记忆或语言流畅度判定为真。
- **不编造来源**：找不到就写找不到；不虚构机构、数字、链接或发布日期。
- **不被立场带偏**：只按证据强度判，不因说法合不合自己心意而放宽/加严标准。
- **不做虚假平衡**：证据一边倒时如实说，不为"客观"硬凑一个反方。
- **事实与立场分开**：价值偏好不争对错，但不允许它伪装成事实。
- **控制范围**：只回答"这条说法可信吗"，不蔓延成开放式行业调研（那是 `outside-view`）。
- **可证伪**：每条结论尽量写清"出现什么证据会推翻它"。

## 交付前自检

- [ ] 已把原说法拆成事实/结论/价值三堆，且只对事实做了验真。
- [ ] 每条事实给了五级可信度之一，高影响项有真实打开的来源（或如实标未核查）。
- [ ] 官方源与媒体转述已区分；转载同一上游没有冒充交叉验证。
- [ ] 在"假设事实成立"下审过推理链：相关/因果、隐藏假设、替代解释、成立条件。
- [ ] 给了"能信到什么程度"的一句话结论和"还需验证的关键一项"。
- [ ] 没有编造来源、没有虚假平衡、没有把价值判断当事实。
