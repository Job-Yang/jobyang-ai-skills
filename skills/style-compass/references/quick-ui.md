# Quick UI 路径

quick 用于基础单页、简单组件、明确需求和“直接做一版”。它把结构、交互和视觉合并成一次完整实现，不是把 full 的四关压缩后逐项打勾。已有品牌、已确认行为和上游约束照常继承；若要定义支付规则、改变权限模型、设计不可逆写入、跨角色交接或复杂恢复，即使只有一页也转 full；仅展示现有规则或无外部副作用的本地演示，不按关键词误判风险。

## 开始前

- 先读取 `craft-packs.md`（9 套视觉锚点与样张 `assets/craft-packs/<id>.png`）与 `craft-genome.md`（五轴工艺基因＋三旋钮 `VARIANCE / MOTION / DENSITY`），自由选用或跨流派混搭质感材质与构图，再读 `motion-craft.md`、`visual-craft.md` 与 `cjk-typography.md`，结合真实内容、现有品牌材料和已确认行为立定视觉基准。
- 只在真实业务歧义会改变任务、行为或验收时追问。内容充分时不问样式，不重新做口味问诊；若用户想看不同方向或对某版局部微调，直接出画廊或按五轴做 Remix 混搭。
- 内部方向最多五行：工艺流派或跨轴混搭配方；首屏主对象构图；字体与字阶反差；表面光学层级与强调色；默认搭载的 3 项以上互动与物理动效亮点。
- 用户要求更有表现力时，把意图落实到表面光影、尺度反差、非对称构图与物理动势。不能把“清楚、可信”自动翻译成灰白中性，也不能牺牲对比度、可用性和熟悉的任务骨架。
- 不采用全局样式禁令。“只能一个强调色”或“禁用某字体”只有在当前品牌与任务有依据时才成立。

## 一次做成

直接制作完整可点 prototype，并同步整理页面实际使用的 tokens。不要强制执行以下 full 步骤：

- 8–12 个初始想法、2–4 个方向候选或反向候选；
- 固定“空间画室”工作台与持久评论服务；
- 全量 `DESIGN.md` 建档、阶段契约或全部平台 tokens 导出；
- 按每个样式逐步询问、批准和修正。

只有用户明确要求多方案，或确有会影响整页组织的设计分歧时，才提供 2–3 个候选。候选须用可见缩略图在首屏组织、字体角色、色面、内容重点或互动亮点上明显区分；不为满足“三项差异”标签拼凑同构卡片。

## 交付

至少交付：

1. 完整 prototype 代码，关键操作真实可点；
2. prototype 实际使用的 tokens；
3. 简短使用说明与必要假设。

quick 是可评审的完整稿，不是正式审批记录。个人口味持久写入、外部发布以及危险或不可逆动作继续使用原有授权与确认边界。

## 一次批量验证

1. 用实际 tokens 检查最终页面：

   ```bash
   python3 scripts/lint_design.py check <prototype.html> --phase final --tokens <actual-tokens.json>
   ```

2. 使用独立 Playwright 或本技能自带脚本 `node scripts/capture_preview.mjs --html <prototype.html> --out <preview_dir> --click "<核心交互按钮>"` 打开 prototype，分别检查桌面与移动宽度，并执行关键操作。查看真实内容、溢出、层级、反馈、关键状态和移动布局，不以源码存在代替渲染结果。
3. 直接用宿主读图工具查看截图，按 `craft-packs.md` 的「出图前六点视觉审视清单」做一轮审美挑刺（主对象面积是否够强、表面光影与字号反差是否拉开、有无缺失微动效或简陋灰边框），把发现合并后最多集中修复一轮，再复查受影响项；不按每个样式打断用户。
4. 浏览器不可用就明确写“未视觉验收”。lint 或 unittest 通过只证明相应机械契约，不证明页面更好看。

当前 `lint_design.py` 仍使用既有 final 规则；若规则与 quick 产物明显不匹配，记录具体规则和现象，不顺手修改 lint、阶段校验器或服务器。
