# `prototype/` 与评审工作台

设计罗盘独立使用和接入 OPC 时都交付 `prototype/`，入口是 `index.html`，核心旅程必须能点通。标准入口是技能统一维护的 `spatial-studio/v1`“空间画室”工作台。新项目只替换画板内容和设计清单，不重新实现导航、资源面板、上下文对象坞、讲解、评论和关卡确认。

## 目录形态

```text
prototype/
├── index.html                         # 设计评审工作台入口
├── index.design.json                  # 阶段边界与 R/P/J/A/S 层间继承契约
├── review-framework/
│   ├── review-framework.css           # 公共评审外壳
│   └── review-framework.js            # 讲解、评论、画板和状态逻辑
├── review-data/
│   ├── comments.json                  # 用户区域评论
│   └── workflow.json                  # 关卡状态、方案选择和融合意见
├── wireframe-<页面>.html              # 结构关产物
├── interaction-<页面>.html            # 交互关产物
├── style-<方案>.html                  # 视觉方向候选
└── final-<页面>.html                  # 定稿页面
design-spec-<topic>.md                 # 与 prototype/ 平级
```

## 工作台各区域只负责一件事

- **顶部**：项目身份、结构／交互／视觉定稿／设计交付四关和全局动作。
- **中央画板**：真实设计内容，是页面的第一视觉主体。支持全部页面、单页聚焦和直接缩放；触控板双指或拖动空白处即可平移，空格或手形工具可从页面上拖动。
- **左侧项目内容**：按需展开，统一管理页面、状态、素材和产物。
- **画布评审工具**：常驻体验、讲解、评论和对比四个入口。
- **右侧上下文检查器**：按需展开，随当前工具切换为体验提示、模块讲解、评论列表、对比选择或方案决策。
- **底部上下文对象坞**：结构关显示页面，交互关显示旅程与状态，视觉定稿显示风格候选，设计交付显示交付物；保存、导出和关卡确认也在这里完成。
- **窄屏**：左右面板互斥，打开检查器会收起项目内容，避免遮住评审工具和画布。

顶部关卡、左侧资源和底部对象属于三个不同层级，命名不能互相重复。

以上区域都属于固定工作台。项目只能改 `index.html` 中标明的“可替换画板”和“可替换设计清单”，不得为了新需求复制一套相似外壳。

## 页面与方案怎么对比

- 左侧“页面”选择页面，视觉定稿关的底部对象坞选择方案。
- 全部页面＋某一方案：查看一套方案的完整页面。
- 某一页面＋全部方案：横向比较同一页面的多个方案。
- 某一页面＋某一方案：聚焦一张画板做细节评审。
- 当前关卡没有多方案时，底部按关卡显示页面、旅程／状态或交付物。

页面、方案和关卡导航都由 `review-manifest` 自动生成，不能手写两份再人工保持一致。

## 四种评审工具

所有阶段共用 `review-framework.md` 定义的四种工具：

- 体验：走真实产品动线。
- 讲解：点击大模块查看完整说明，支持从头讲解。
- 评论：点击放钉、拖动框选，评论写入结构化文件。
- 对比：勾选二至四张画板，按 A、B、C、D 并排查看。

讲解标注和用户评论是两种数据。设计者负责把设计讲清，用户负责指出疑问和修改意见，不能混成同一组编号说明。

## 生成顺序

- 第 0 关先搭评审工作台，挂入灰阶结构页面。
- 结构关建立 `R → P` 映射，交互关继续补齐 `J → A → S`。
- 交互关补齐真实业务交互，复用公共四种评审工具和评论写入，不在产品画板里再造评审控件。
- 视觉定稿先生成通过方向覆盖门禁的高保真候选；选择或融合后继续在同一关展开全部页面和状态。
- 设计交付前通过最终覆盖门禁，再冻结 `index.html`、`index.design.json`、评审记录和设计规格。

不要再照抄历史项目的控制台，也不要把“空间画室”当成一张参考图重新实现。公共能力来自 `assets/review-framework/`，新需求先跑脚手架，再只生成产品画板和 `review-manifest`。

## 落盘

- OPC 标准道：`$ILOOP_DATA_ROOT/analysis/opc.product-pipeline/<topic>/prototype/` 和 `design-spec-<topic>.md`。
- 自由模式：写到用户或宿主指定的 `<产物目录>/prototype/`，不自动猜工程路径。
- 过程产物不能写进用户工程源码目录。

## 启动与验收

先复制公共资源：

```bash
python3 scripts/scaffold_review.py <prototype目录>
```

替换画板和设计清单后，校验公共外壳：

```bash
python3 scripts/validate_review_workspace.py <prototype目录>/index.html
```

再启动评审服务：

```bash
python3 scripts/review_server.py --root <prototype目录> --port <空闲端口>
```

交付用户前至少验证：

1. `validate_review_workspace.py` 通过，页面返回 200，桌面和窄屏没有遮挡。
2. 不切换工具时可双指平移或拖动空白处；空格和手形工具可从页面上平移；缩放、复位和适应窗口可用。
3. 体验、讲解、评论和对比四种工具互不误触。
4. 每个大模块能显示五项说明。
5. 点击评论和区域评论都能写入 `review-data/comments.json`。
6. 点击右侧评论能跳回原页面和原区域。
7. 评论能标记解决、重新打开和导出。
8. 方案选择、融合意见和关卡状态能写入 `review-data/workflow.json`。
9. 未解决的“必须修改”会阻止进入下一关。
10. 方向候选执行 `python3 scripts/validate_stage_contract.py --contract prototype/index.design.json --html prototype/index.html --phase direction` 并通过。
11. 设计交付执行同一命令的 `--phase final` 并通过。
12. 900px 窄屏下顶部四关名称完整，左右面板互斥，底部对象坞和确认动作可见。
