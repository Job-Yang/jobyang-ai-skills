# 交互内核：让每一步都可发现、可解释、可恢复

quick 与 full 都用本页检查代表性任务。它约束行为设计，不改变 `interaction-guide.md` 的灰阶确认关、既有阶段字段或评审工作台。

## 一条完整的任务链

按顺序走一遍：

1. **目标。** 用用户语言写清想完成的结果和完成信号；页面入口、默认选择与信息密度围绕这个目标，而不是围绕已有组件。
2. **可发现动作。** 在用户需要它的时刻，让下一步可见、名称对应结果、位置靠近作用对象。低频能力可以按需展开，但关键下一步不能只靠猜图标、隐藏手势或说明文档。
3. **前置条件。** 在触发前展示范围、权限、依赖、未保存内容和不可逆后果。能提前补齐就在原位补齐，不要等提交后才返回模糊失败。
4. **可见状态。** 触发后让用户知道系统已收到什么、正在做什么、是否仍需要人、结果落在哪里。状态名称表达事实，不用一个“处理中”覆盖不同业务阶段。
5. **及时反馈。** 先确认输入已被接收，再用与耗时相称的进度、局部更新或通知解释变化。反馈与作用对象同处，避免用户来回寻找。
6. **恢复路径。** 失败要说明保留了什么、问题在哪里、可重试／修改／返回哪一步；恢复后不要要求用户重输仍然有效的内容。
7. **保留上下文。** 返回、切换对象、窄屏重排或错误恢复后，尽量保留筛选、选中项、滚动位置、草稿和已完成步骤，让用户从中断处继续。

它能提高交互质量，是因为每一步都回答“我现在能做什么、系统发生了什么、下一步是什么”。控件存在不等于动作可发现，动画存在也不等于状态可解释。

## 长任务不是一个 loading

| 状态 | 用户需要看到的事实 | 合适的下一步 |
|---|---|---|
| 排队 | 尚未开始、排在何处或受什么资源限制 | 离开页面继续等待；只有业务支持时才取消 |
| 运行 | 已开始、当前阶段、最近进展与产物位置 | 查看细节或继续其他工作 |
| 等待输入 | 系统已停在哪、缺谁的什么输入、已完成内容是否保留 | 就地补输入或明确转交 |
| 失败 | 失败点、影响范围、保留内容与可恢复条件 | 重试、修正输入或返回安全状态 |
| 等待验收 | 执行已结束、待验什么、依据和产物是什么 | 打开产物、提出修改或按既有授权确认 |

取消是业务状态迁移：只有 backend 明确允许且能说明取消后的数据／资源状态时才显示。**动画可打断**只是界面能跟上人的连续输入，不等于队列、上传、支付或其他任务可以取消。

## 按频率与后果分配反馈

- **高频、低风险动作**：即时或轻量反馈，避免弹窗和重复庆祝拖慢节奏；连续操作从当前状态接续。
- **重要但可继续的动作**：在作用对象附近明确范围和结果，必要时就地确认，不把用户赶到脱离上下文的说明页。
- **破坏但可逆的动作**：优先执行后提供清晰撤销，并说明撤销有效范围；不能恢复时不要伪装成可逆。
- **不可逆或需授权的动作**：保留真实权限检查和显式确认，按钮写具体动作与对象；“更顺滑”不能删掉授权。

## 控件、输入与极端条件

- 优先使用成熟平台 primitive 及其原生语义、禁用、校验和可访问性能力；自造组件必须达到同等行为，不只复制外观。
- 对话框、菜单、抽屉等明确初始焦点、Tab 顺序、关闭后的焦点归还；适用平台支持 Esc，不能让焦点落到被遮挡内容。
- 所有键盘操作可见聚焦；拖拽提供键盘或按钮替代；触控目标、滚动和手势不依赖悬停。
- 用过长标题、长数字、空内容、无素材、缩放、窄屏和宽屏检查重排；响应式改变布局，不改变任务语义或丢动作。
- 尊重减少动态设置。来源里的 React、浏览器 API、CSS 或 Web 控件细节只在对应技术栈使用，不升格为 native 约束。

## 动效只解释变化

动效用于维持空间关系、说明对象如何加入／移除、连接触发与结果，或帮助理解层级变化。高频动作减少等待，连续输入允许从当前视觉状态接续；减少动态时保留状态变化本身。

不要让所有元素入场、每次成功都庆祝，也不要用长动画遮住真实等待。动效是否顺滑与任务是否可取消、结果是否正确是三件不同的事。

## 审视路径

在同一浏览器尺寸走默认路径和一次恢复路径，再看窄屏、键盘／触控替代与极端内容。分别记录：

- **任务目标**：是否完成正确结果，状态与 backend 能力是否一致。
- **体验目标**：动作是否可发现，反馈是否及时，变化是否连贯，上下文是否保留。

保留首次稿与修改稿；静态截图用于看布局和状态，不作为交互正确证据。自查先挡住缺路径、缺状态的稿，原有 full／OPC 人类评审仍按既有链路发生，不为每条检查新增审批。
