# 第 0 步 · 理结构 —— 用 HTML 线框图(真形状 + 编号标注)确认

> 目的：碰视觉之前，先把“哪几个界面、每屏怎么布局、每块是什么、怎么跳”理清楚。
> **产物是一张能在浏览器打开的低保真 HTML 线框图，不是 Markdown，更不是 ASCII 假图。**
> 铁律（踩过的坑换来的）：
>   - **别甩 Markdown／文字描述**：人读文字费劲，一张线框图扫一眼就懂。
>   - **别用 ASCII 画框**：那是“装饰性 monospace”，假装是图，其实丢信息。我们都用 HTML 了，就画真的。

## 输入分流(这个节点的输入)

正常 OPC 流转到设计节点时应已有 **PRD**。分三种：
- **有 PRD** → 直接读 PRD 抽功能清单，不自己编功能。
- **没 PRD（只有一句话需求）** → 先跑轻量“需求→功能清单”环节：点选跟用户确认要做哪些功能，形成 mini-PRD，再进结构。别跳过直接从一句话硬推。
- **已有成型工程** → 读真实代码和界面定结构，别凭空想。

## 怎么画线框图（两条业界原则，必须遵守）

### 原则一：用真实形状画元素，不用文字描述填格子
低保真线框的第一原则与 Figma 等工具一致：
- 键盘 → 画一排真键帽；列表 → 画真实的行（左图标＋右灰条）；按钮和输入框也画出真实形状。
- 文字／标题 → 用灰色线条（`背景灰条`）表示，不写真内容，也不写“这里是标题”。
- 图片／头像 → 使用带 X 的灰盒。
- **反面教材**：在格子里写“键盘拾取区（MacBook ANSI 键盘）”。要画就画出来。

### 原则二：每个大模块必须能被讲清，也能被精确评论

只在画面上放 ①②③，再把几句说明堆在右边，不足以支撑原型评审。用户不知道编号覆盖了哪块，也无法把意见准确绑回具体区域。

所有线框都要套用 `review-framework.md` 的评审工作台：

- 每个大模块添加稳定的 `data-review-module` 标识。
- 在 `review-manifest` 里登记“是什么、为什么、能做什么、有哪些状态、要确认什么”。
- 左侧“项目内容”的页面页签列出全部页面，底部上下文对象坞显示当前结构对象；不要另做永久页面栏或第二套缩略导航。
- 讲解模式下，点击模块打开完整说明；支持从头按顺序讲解。
- 评论模式下，用户可以单击放评论钉，也可以拖动框选区域。
- 编号只表示讲解顺序，不能代替完整说明。

结构关只讲功能和行为，不讲颜色、间距、字号。视觉问题留到视觉关，避免淹没结构判断。

### 全程灰阶，无风格
黑白灰 + 灰盒。**一个颜色、一个品牌字体都不上**——风格是第 2 步的事。
这样用户的注意力会锁在“结构对不对”，不会被颜色带跑。

## 产物与预览（标准手段，别让用户点源码）

1. 线框 HTML 写到用户或宿主指定的产物目录（如 `<产物目录>/prototype/wireframe-<屏名>.html`），不默认写进工程根或技能目录。
2. 用 `scripts/scaffold_review.py <prototype目录>` 生成 `spatial-studio/v1` 固定工作台。只替换“可替换画板”和“可替换设计清单”，不要手写四关、左右面板、上下文对象坞和评审外壳。
3. **起带评论写入能力的本地服务给链接**，别让用户点 HTML（点了只在编辑器弹源码）：
   ```
   python3 scripts/review_server.py --root <产物目录> --port 8823
   # 给用户：http://127.0.0.1:8823/wireframe-<屏名>.html
   ```
4. **自己先用受控浏览器截图确认渲染没破**。没有受控浏览器时明确降级，不要直接调用可能注册后台项的系统浏览器，也不要只查源码就宣布视觉通过。
5. 自己再走一遍讲解和评论：至少点开一个模块说明、放一个评论钉、框选一个区域，并确认 `review-data/comments.json` 真正写入。

截图使用宿主提供的浏览器能力，保存到指定证据目录。截图只验证视觉表现，不能替代评审交互验证，也不要求安装额外工具链。

## 确认

用点选让用户确认：布局对不对、功能点缺不缺、标注的行为对不对。**改动在这一步最便宜**，因为还没画任何像素级视觉。

结构确认后必须同步更新 `index.design.json`：

- 为范围内需求分配稳定 `R` 编号。
- 为页面或稳定工作区分配 `P` 编号。
- 写清每个 `R` 由哪些 `P` 承载。
- 记录本关的“已确认、可发挥、待确定、验证证据”。

每个 `R` 都有承载位置，且没有需求外页面，结构关才算通过。完整格式见 `stage-contracts.md`。

## 边界

- **只理结构，不碰视觉**：全程灰阶。
- **轻但具体**：简单工具 1～3 屏；别硬拆，也别抽象。
- **代表界面只用于视觉选向**：它必须覆盖会决定布局是否成立的旅程和状态；选定方向后仍要展开全部页面，不能直接交付。
- 线框的评审外壳统一复用 `assets/review-framework/`，不再照抄某个历史项目页面。
