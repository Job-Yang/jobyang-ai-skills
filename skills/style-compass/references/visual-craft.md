# 让具体设计手段服务于完整画面

本页在视觉创作前读取。它安排在现有视觉定稿阶段内部，不增加用户逐项确认样式的关卡。结构与交互已确认的任务、动作、状态和结果继续继承；构图、组件外观和表现方式仍可设计。

## 先确定这一页要让人看见什么

读真实内容、目标用户、使用情境和关键状态，再读方向简报 `design/direction.md`。已有产品先看完整页面与实际使用，写下值得保留的特点；从零设计则从已确认的内容和旅程出发。

为每个方向留一段简短创作说明，放在设计材料中，不塞进产品正文：

- 页面最重要的内容或任务，以及希望形成的感受。
- 准备怎样组织整页，和另一个方向的实质区别。
- 采用哪些具体手段，预期改善什么，可能牺牲什么。
- 哪些画面、状态或操作能帮助判断这些选择。

明确方向或局部任务只需处理相关部分。不能为了凑候选，把同一构图换几种颜色，也不能为了制造差异改变已确认的任务语义。

## 候选怎么拉开：先写方向卡，检查过再渲染

同一个模型连续出几版，彼此往往很像：开放式问题上，同一模型的回答有 79% 的情况平均相似度超过 0.8，换模型也一样会收敛（Artificial Hivemind，2025）。所以“出三版”本身不保证有三个方向，差异要在渲染前就设计出来。

1. **先多想，再挑。** 根据方向简报列 8 到 12 个一句话方向，再挑出彼此最不像的 2 到 4 个。“先列很多、再让它们大胆且不同”是提示策略里最能恢复多样性的一种（Meincke 等，2024）。
2. **每个候选写一张方向卡**，存成 `prototype/directions.json`：

```json
{
  "brief": "design/direction.md",
  "candidates": [
    {
      "id": "direction-a",
      "name": "冷静表格",
      "coordinate": "calm-tech",
      "one_liner": "分隔线分区的高密度表格，状态一眼可见",
      "axes": {
        "bg": "#F6F7F9", "accent": "#0B7A75", "heading_font": "PingFang SC", "radius": 4,
        "layout": "顶部一行状态汇总，下面整宽表格", "density": "compact", "container": "分隔线",
        "decoration": "无", "motion": "subtle"
      },
      "moment": "任务从卡住变成进行中时，状态标签有一次颜色过渡",
      "defaults": [{ "id": "SMELL-CARD-STACK", "status": "avoided" }],
      "cost": "首屏信息多，新用户第一眼会有压力"
    },
    {
      "id": "direction-c",
      "name": "看板叙事",
      "coordinate": "warm-clarity",
      "contrarian": true,
      "keeps": ["状态一眼可见", "可信"],
      "flips": ["表格换成按状态分栏的看板", "无衬线标题换成衬线", "分隔线换成色带"],
      "axes": { "bg": "#FBF8F3", "accent": "#C2410C", "heading_font": "Source Han Serif SC", "radius": 12,
                "layout": "按状态分栏的看板", "density": "comfortable", "container": "色带",
                "decoration": "插画", "motion": "expressive" },
      "defaults": [],
      "cost": "信息密度低一半，重度用户要多滚动"
    }
  ]
}
```

3. **运行检查**：`python3 scripts/lint_design.py diverge prototype/directions.json`。每对候选至少在 3 个维度上不同（明暗、强调色、字体类别、整页布局、圆角、密度、容器、装饰、动效），并且有一个标了 `contrarian: true` 的反向候选。不通过就改卡片，不要只换颜色。
   - `layout` 用一句话写整页怎么组织：导航和筛选放在哪、摘要用什么形式、主体是表格、列表还是卡片流。
   - 明暗、主色、字体类别和整页布局是并排时一眼能看出的四项。一对候选这四项都一样、只在密度、容器、装饰这类标签上不同，检查会提醒 `DIVERGE-SURFACE`：卡片写得不同，页面并排时可能还是很像。
   - 反向候选反的是第一直觉，不是需求。它仍要满足简报的目标感受和每一条“X 但不 Y”，只推翻最常规的做法；`keeps` 写保住了哪些目标感受，`flips` 写推翻了哪些常规做法，缺一项检查会提醒 `DIVERGE-CONTRARIAN-BRIEF`。挑法见 `intake-questions.md` 第五节。
4. **候选彼此独立生成。** 宿主支持子代理时，每个候选单独生成，只给它方向简报和自己的卡片，不给它看其他候选。看过别人的稿再画，很容易被它固着：生成式图片会增加固着、减少想法的数量和多样性（Wadinambiarachchi 等，CHI 2024）。
5. 渲染后数值可以调整，把调整写回卡片，交付时选中的那张卡片就是 tokens.json 的起点。

不要矫枉过正。设计竞技场的数据显示，几套精选模板加上针对产品的个性化，比一味追求多样更受欢迎。坐标库就是精选的起点，每个候选都要明显贴合这个产品的真实内容。

## 熟悉度预算：骨架守惯例，表现力集中用

第一印象里，低复杂度加高“典型性”（看起来像用户熟悉的这类产品）的网站得分最高（Tuch 等，2012）。所以：

- **骨架守惯例**：导航位置、表单写法、表格操作这些用户已经学会的东西，不为了新颖去改。
- **表现力集中在一两个时刻**：首次完成、关键数据变化、品牌首屏。把它写进方向卡的 `moment` 和 tokens.json 的 `guardrails.moments`。Material 3 Expressive 的研究也提醒，打破熟悉模式（比如去掉文字标签）会伤害可用性，而且有相当一部分用户更喜欢平静的版本。
- 高频任务区保持安静，动效在 100 到 400ms 之间，提供减少动态替代。

## 默认长相自查

每个坐标在 `style-library.yaml` 里都列了 `default_attractors`：这个方向最容易掉进去的默认长相。写方向卡时逐条标 `avoided` 或 `accepted`；接受的要写理由，交付时进 tokens.json 的 `guardrails.accepted_defaults`。

- 能用脚本查的（紫蓝渐变、近黑底加靛蓝、全大写小标签、回弹缓动、表情符号当图标、彩带、卡片堆叠、高频训练字体），`lint_design.py` 会以 `SMELL-*` 规则提示。它们只是提示，不是禁令：好玩类方向用回弹完全合理。
- 脚本查不出的，用 OpenAI 的**品牌测试**：去掉导航后，首屏还能不能认出是这个产品。认不出，说明品牌太弱。
- 禁什么由方向决定，不设全局禁令。“全局禁用 Inter”这类规则会把所有产品推向同一组替代品，换一种方式趋同。

## 从参考中找关系

产品名和 `style-library.yaml` 帮助找到线索。已有可用资料时，优先观察实际页面和关键状态，记录来源、观察对象及可借用的关系，例如图文比例、标题与正文的区别、操作强调和内容分组。

借用前说明内容密度、用户任务、品牌和载体是否相近。把多个参考的部件组合后，要回到整页检查比例是否协调。没有访问到参考，就标成模型推测；不把产品名当作已经看过页面的证据。参考只借关系，不借颜色、字体和标志性构图；照着一张参考图生成，最容易做成它的复制品。

现有材料足够就直接设计，不为每个项目重复检索。没有外网或外部技能仍可执行本页，保留未知。具体像素值和品牌禁用项只在适用情境内成立，不把某种字体、颜色或圆角列为所有产品的好坏标准。

## 按当前问题选择手段

| 手段 | 具体处理 | 比较时看什么 |
|---|---|---|
| 构图与结构 | 内容分组、先后、栏宽、主体比例、共同对齐线；并排和独占区域的安排 | 整页阅读顺序是否清楚；窄列是否挤压长标题；是否靠删内容制造简洁 |
| 主次与留白 | 联合处理位置、大小、字重、间距与对比；区别组内和组间距离 | 重点能否被认出；是否每块都抢眼；弱信息是否仍读得清 |
| 字体与排版 | 按展示、阅读、操作和数据等角色选字形与尺度；处理行长、行高、中英混排、数字和换行（中文规则见 `cjk-typography.md`） | 实际字体是否加载；标题和正文是否协调；长内容、缩放和回退是否成立 |
| 图文关系 | 先确定图像的内容作用，再选主题、视角、裁剪、比例和文字位置 | 图像与文字是否共同表达内容；手机裁剪是否保留主体；是否有必要使用图片 |
| 配色与层次 | 背景、表面、文字、边框、强调和状态分别承担明确角色 | 相邻颜色和不同背景下的关系；重点与气氛是否冲突；文字及状态可辨认性 |
| 组件细节 | 动作强调、字形和图标的视觉对齐、内边距、描边、圆角关系及交互状态 | 默认、悬停、聚焦、按下、禁用等适用状态是否协调；长文案与实际点击是否正常 |
| 交互与动效 | 反馈、等待、完成、恢复、区域联动、过渡和减少动态替代 | 代表性任务中注意力如何变化；是否及时反馈、打断阅读或拖慢高频操作 |

这些手段会互相影响。字体改变可能需要重新安排栏宽，图片裁剪会改变视觉重点，强调色同时影响按钮和内容。先处理当前最影响整页的关系，再细化相关组件；局部问题直接修局部，不重做无关区域。

相同角色保持一致，不同角色可以有意区别。展示区可以更有表现力，高频任务区可以更紧凑。避免把“有设计”理解成处处装饰，也避免把“克制”理解成删掉所有辨识度。

## 先切片还是直接整页

方向简报弱（滑杆都在中间、用户说不清）时，可以先做一轮**风格切片**：每个方向只做一个关键屏，用真实内容，4 到 6 个并排。用户指出两三个，再展开成完整候选。切片来自 Samantha Warren 的 Style Tiles，好处是便宜、快；代价是看不出整页构图是否成立，所以切片只用来缩小范围，不能代替整页候选和交互验收。

简报已经清楚时直接做整页候选。

## 用完整内容生成和检查

候选必须放入真实标题、段落、数据与可用素材，覆盖布局相关的长内容和关键状态。缺素材明确说明，不用占位图冒充最终视觉。图片、字体的来源与网络依赖随交付保留。

先看整页构图与节奏，再按实际尺寸看字体、图像、按钮和细字。按产品平台检查目标宽度，不能把一张桌面稿等比缩小当成手机设计。影响动态表现时，走代表性路径并看过程；静态截图不证明联动与手感。

展示前运行 `python3 scripts/lint_design.py check prototype/index.html --phase direction`：`error` 先修，`warn` 修掉或在创作说明里写理由。脚本只查确定性的底线（中文字体回退、行高、lang、可访问名称、缩放、动效、默认长相），不判断好不好看。

可验证错误先修：内容丢失、溢出、无反馈或状态不一致。审美意见另记，指向画面并说明影响；功能通过不等于视觉出色。比较时先给画面与使用过程，再展示创作说明，避免解释引导判断。允许原版胜出、各有优势或没有明显提升。

## 看图选词

用户看完候选后，用 `intake-questions.md` 里同一张 24 词表收集反应：

1. 词表顺序每次打乱，正负词混排。
2. 用户给最喜欢的候选点 3 到 5 个词；时间允许时每个候选都点。
3. 技能记录命中：方向简报里的目标词命中几个，反面词出现几个。反面词出现，即使用户选了这个候选，也要回头查是哪块画面引起的。
4. 用户只负责指出问题，改法由技能提：只给一个方案时评分偏高、批评偏少，用户也不擅长自己想出改法（Tohidi 等，CHI 2006）。
5. 选择和理由用 `design_memory.py record` 记下来（`--words` 写用户点的词）。

一个人的反应是偏好信号，不是验证。好看的界面会让人觉得更好用，并掩盖可用性问题（审美-可用性效应），所以交互仍以真实操作为准。

## 把反馈变成可复用经验

保留原稿、修订和失败稿。反馈至少包含场景、具体画面、影响及适用条件；不能把某一项目的黑底、宋体或并排布局变成通用规则。

每次选定方向后写决策记录：给了哪些候选、选了哪个、为什么否掉其他的。决策写进产品档案的 `design/decisions.md`，同时进个人口味记录（见 `design-archive.md`）。口味记录只用来提建议和避免重复：同一个人反复选同一种方向时，下一次要主动放更远的候选，否则作品集会越做越像。多项目重复出现的现象才考虑提升为默认建议。

方法效果的正式比较按 `visual-evaluation.md`。研究支持的是设计因素与感受存在联系，不能直接证明把这些条目交给 AI 就会提高首稿质量。

## 方法来源与边界

- [NN/G：四个网站的设计分析](https://www.nngroup.com/articles/why-does-a-design-look-good-part2/)提供构图、字体、图文和细节关系的案例；属于专家分析。
- [Carbon：字体策略](https://carbondesignsystem.com/elements/typography/style-strategies/)、[颜色](https://carbondesignsystem.com/elements/color/usage/)、[按钮](https://carbondesignsystem.com/components/button/style/)、[动效](https://carbondesignsystem.com/elements/motion/overview/)提供按任务和角色设计的实践；具体样式属于 IBM。
- [IBM：摄影](https://www.ibm.com/design/language/photography/overview/)说明图像的情境与表达目的；推广到插画与三维属于本技能建议。
- Seckler 等（2015），DOI `10.1016/j.chb.2015.02.056`：本次方法整理只读到论文前两页预览，作者报告结构与颜色影响不同审美感受，不能推广特定色相或构图偏好。
- [Artificial Hivemind（2025）](https://arxiv.org/abs/2510.22954)：同一模型和不同模型在开放问题上都高度重复。
- [Meincke 等（2024）](https://arxiv.org/abs/2402.01727)：先列很多再挑大胆不同的提示策略，多样性接近人类小组；研究对象是产品创意，不是界面。
- [Anderson 等（2024）](https://arxiv.org/abs/2402.01536)：趋同主要来自工具给不同用户推荐相似的东西，所以共用的风格库要轮换、要有新颖度预算。
- [Dow 等（2010）](https://www.cs.cmu.edu/~spdow/files/PrototypingParallel-TOCHI10.pdf)：并行做多个原型比串行改一个，效果更好、更多样。
- [Tohidi 等（CHI 2006）](https://www.billbuxton.com/rightDesign.pdf)：只给一个方案时评分虚高、批评变少。
- [Wadinambiarachchi 等（CHI 2024）](https://arxiv.org/html/2403.11164)：构思时看生成图片会增加固着。
- [Tuch 等（2012）](https://research.google/blog/users-love-simple-and-familiar-designs-why-websites-need-to-make-a-great-first-impression/)：低复杂度加高典型性的网站第一印象最好，陌生布局即使简单也被判得更丑。
- [Style Tiles](https://styletil.es/)：介于情绪板和整页稿之间的风格切片。
- [NN/g：用反应词评估视觉吸引力](https://www.nngroup.com/articles/microsoft-desirability-toolkit/)：词表不超过 25 个、打乱顺序、提前定目标词。
- [OpenAI：用 GPT-5.4 设计前端](https://developers.openai.com/blog/designing-delightful-frontends-with-gpt-5-4)：品牌测试和“拒绝这些失败”清单。
- [Design Arena：哪些设计会赢](https://notes.designarena.ai/how-openais-sol-finally-learned-design-taste/)：点名的 AI 设计气味；属于基准运营方的分析，未经同行评审。
- [Material 3 Expressive 研究](https://design.google/library/expressive-material-design-google-research)：表现力能提升偏好，打破熟悉模式会伤害可用性。

这些来源帮助提出方案与解释取舍，最终效果仍以当前产品的实渲、使用和评审为准。
