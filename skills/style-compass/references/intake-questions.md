# 第 1 步 · 问诊 —— 只问产品，不问风格

> 铁律(这一版最重要的修正):**只问用户答得出的"产品问题",绝不问"风格判断题"。**
> 反面教材："你要拟物还是极简？""想要什么感觉？""爱用哪个 App？"——这些要求用户**已经懂设计/已知参考**，
> 非设计师会懵。正确做法：问产品事实，**由技能**把答案翻成风格候选。
>
> 更重要：**这一步是可跳过的快速通道，不是必经关卡。** 默认主路是第 2 步的"直接渲染给你看"。
> 只有当用户表现出"我已经挺确定方向"时，问诊才帮他快速锁定；只要用户流露"想象不出/不确定"，
> 立刻停止提问，一句话进第 2 步渲染。**不要逼用户在文字里做视觉决策。**

## 什么时候用问诊 vs 直接渲染

- 用户说得出参考/明确方向("我要像 Linear""要沉稳深色")→ 问诊几个产品问题快速收敛 → 渲染验证。
- 用户说"我也不知道""想象不出""你先做几个我看看"→ **跳过细问，直接进第 2 步**，渲染差异化 3-4 版让他指。
- **拿不准就默认后者。** 多数非设计师本就想象不出，展示优先永远安全。

## 只问这几类"产品问题"(点选，不让用户打字)

### Q1. 这东西主要给谁用?
- 专业/内部用户(开发者、运营、同事)
- 普通大众消费者
- 面向创作者/早期尝鲜用户
- 高端/挑剔的用户

### Q2. 用户主要在上面"做什么"?
- 高效处理任务 / 看数据(工具、后台)
- 频繁、长时间操作(每天用很久)
- 偶尔用一下 / 配置一次就走
- 沉浸阅读 / 学习
- 放松 / 情绪相关
- 被吸引、想行动(营销、展示)

### Q3. 使用场景/时长?
- 高频重度(专业工具)
- 中频(日常效率)
- 低频(偶尔配置)

> 注意：以上**没有一个字**提到颜色、风格、字体。用户只在描述自己的产品，这他一定答得出。

## 从产品答案 → 风格候选(技能内部做，不暴露给用户)

把答案映射到 `style-library.yaml` 的坐标(权重累加取 top,规则可裁剪):

| 产品信号 | 倾向坐标 |
|---|---|
| 专业/内部 + 高效看数据 + 高频重度 | calm-tech, neutral-flexible |
| 专业 + 偶尔配置 + 想要"设备感" | (硬件控制台方向，库暂无完美坐标，直接喂"参考 TE/NI") |
| 大众 + 日常效率 | warm-clarity, neutral-flexible |
| 大众 + 情绪/放松 | soft-wellness, warm-clarity |
| 创作者/尝鲜 + 想行动 | bold-expressive, editorial |
| 高端/挑剔 + 展示 | minimal-zen, editorial |
| 沉浸阅读 | editorial, neutral-flexible |

## 关键：候选拉开光谱，别摆三个像的

进第 2 步渲染时，若用户没明确方向，**故意选差异大的 3-4 个坐标**(如：一个深色工具 + 一个温暖清爽 + 一个大胆)，
让用户用"三选一"快速三角定位自己在光谱哪头。摆三个都像 Linear 的没意义。

## 边界

- **用户明确指令 > 一切**：他说"必须深色""要保留现有的红"，直接锁定，不问不猜。
- **绝不让用户在文字里判断风格**;风格判断是技能的活。
- 库里没有完美坐标时(如硬件控制台),**直接构造"参考 X"喂给渲染**,不硬塞进不合适的坐标。
