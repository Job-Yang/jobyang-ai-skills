# 第 1 关 · 问诊并写方向简报：只问产品，不问风格

> 铁律：**只问用户答得出的“产品问题”，绝不问“风格判断题”。**
> 反面教材：“你要拟物还是极简？”“想要什么感觉？”“爱用哪个 App？”这些要求用户已经懂设计或已知参考，非设计师会懵。
> 正确做法：问产品事实，由技能把答案编译成**方向简报**，再从简报推出候选方向。

页面写得丑，多数时候不是模型没审美，是需求太宽：模型只能落回最常见的做法。方向简报就是把“宽”收窄的那张纸。它要具体到能**否掉**一个候选：“专业但不冰冷”能否掉近黑底加冷色强调，“好看一点”什么也否不掉。

## 什么时候问、问多少

- 用户说得出参考或明确方向（“要像飞书”“必须深色”）：问几个产品问题补齐简报，然后渲染验证。
- 用户说“不知道”“你先做几个我看看”：不再追问，技能根据已有材料自己写简报，直接进入渲染。简报照样要写，只是由技能起草，用户在看候选时用点选纠正。
- 拿不准就默认后者。问题总数不超过 6 个点选，全部可跳过。

## 一、产品事实（点选，不让用户打字）

### Q1. 这东西主要给谁用？
- 专业/内部用户（开发者、运营、同事）
- 普通大众消费者
- 面向创作者/早期尝鲜用户
- 高端/挑剔的用户

### Q2. 用户主要在上面“做什么”？
- 高效处理任务 / 看数据（工具、后台）
- 频繁、长时间操作（每天用很久）
- 偶尔用一下 / 配置一次就走
- 沉浸阅读 / 学习
- 放松 / 情绪相关
- 被吸引、想行动（营销、展示）

### Q3. 使用场景和时长？
- 高频重度（专业工具）
- 中频（日常效率）
- 低频（偶尔配置）

### Q4. 有没有必须保留的东西？（已知就跳过）
- 已有 Logo、品牌色或字体
- 已有产品，新页面要和它一致（转“延续”或“补档”路线，见 SKILL.md 入场分流）
- 没有

> 以上没有一个字提到颜色、风格、字体。用户只在描述自己的产品，他一定答得出。

## 二、产品性格：四根滑杆（点选五档，可选“说不清”）

每根滑杆问的是“这个产品对用户是什么态度”，这是产品判断，不是视觉判断。来源：Google Ventures 设计冲刺的品牌滑杆练习。

| 滑杆 | 左端（-2） | 右端（+2） |
|---|---|---|
| friend_authority | 像朋友 | 像权威 |
| young_mature | 年轻新潮 | 成熟经典 |
| playful_serious | 轻松好玩 | 严肃专业 |
| mass_elite | 大众亲民 | 小众讲究 |

- 至少一根要明确站到一端（±2）。四根都在中间，说明产品还没想清楚定位；这时候选方向要拉得更开，让用户在渲染结果里找自己。
- 用户选“说不清”的滑杆，由技能根据 Q1 到 Q3 推断，在简报里标“推断”。

## 三、感受词：希望第一眼说出的词，和绝不能出现的词

从下面 24 个词里，技能根据产品事实先勾 3 个目标词、2 个反面词，用户点选改正。看候选时也用同一张表（见 `visual-craft.md` 的“看图选词”）。

- 正面：可靠、专业、清爽、高效、亲切、安心、有品质、有活力、有个性、精致、轻松、有条理、现代、温暖
- 负面：廉价、冰冷、拥挤、杂乱、沉闷、幼稚、浮夸、过时、千篇一律、让人紧张

词表来自微软的产品反应卡（118 个词，至少四成是负面词）和 NN/g 的用法建议：在线使用时控制在 25 个词以内、顺序打乱、目标词提前定好。

## 四、技能把答案编译成方向简报

简报写进档案目录的 `design/direction.md`（没有产品仓库时写进输出目录），交付时随 `DESIGN.md` 一起导出。模板：

```markdown
# 方向简报 · <产品名>

## 产品事实
- 给谁用：……  做什么：……  频率：……
- 平台与语言：Web，中文（zh-CN）
- 必须保留：……（没有写“无”）

## 产品性格
- 像朋友 ↔ 像权威：+1
- 年轻新潮 ↔ 成熟经典：0（推断）
- 轻松好玩 ↔ 严肃专业：+2
- 大众亲民 ↔ 小众讲究：0

## 感受词
- 希望第一眼：可靠、高效、有条理
- 绝不能出现：冰冷、拥挤

## X 但不 Y
- 专业，但不冰冷
- 高效，但不拥挤

## 产品原则（能用来否掉方案）
1. 宁可多一行字说清状态，也不用只靠颜色表达。
2. 宁可首屏信息少，也不让用户找不到下一步。

## 参考：像什么、不像什么
- 像：<产品> 的 <具体关系>，因为 <理由>
- 不像：<产品> 的 <具体关系>，因为 <理由>

## 候选方向（技能填写，见下一节）
```

写简报的规则：

- “X 但不 Y”从滑杆和反面词推出，每条都要能排除一类处理。写法参照 Mailchimp 语气规范（“古怪但不失礼，聪明但不势利”）。
- 产品原则用“宁可……也不……”，两三条就够。没有取舍的原则（“简洁易用”）不写。好原则能让人重新审视大部分旧方案，也能把产品和竞品区分开（Jared Spool 对设计原则的检验）。
- 参考只写关系，比如“列表密度”“筛选的组织方式”，不写“风格像某某”。“像什么、不像什么”两边都写，不要什么和要什么一样重要（Jackie Colburn 的 This / Not That 练习）。
- 简报里不出现色值、字号、字体名。这些是渲染之后的事。
- 滑杆和 PRD 的信号冲突时（比如 PRD 写“面向大众”，用户把“小众讲究”拉满），把冲突摆给用户点选，不要悄悄取平均。
- 用户坚持“做成像某某”时照做，同时加一个反向候选，并说明照着一个参考做容易被它固着。

## 五、从简报推出候选坐标（技能内部做，不暴露给用户）

1. **按滑杆找最近的坐标。** 把简报的四根滑杆和 `style-library.yaml` 每个坐标的 `axes` 逐项相减取绝对值再相加，取距离最小的两个。有几对坐标在四根轴上只差 1（editorial 和 minimal-zen，warm-clarity 和 soft-wellness），距离并列或只差 1 时不要硬选，交给下一步的产品信号；还分不开就两个都进候选，让用户看图选。
2. **用产品信号校正。** 下表命中的坐标加入候选；落在 `avoid_for` 里的坐标排除。

| 产品信号 | 倾向坐标 |
|---|---|
| 专业/内部 + 高效看数据 + 高频重度 | calm-tech, cn-enterprise, neutral-flexible |
| 国内企业后台、表单和审批多 | cn-enterprise, calm-tech |
| 专业 + 偶尔配置 + 想要“设备感” | （库里没有完美坐标，按任务直接提方向，参考 TE、NI 的面板关系） |
| 大众 + 日常效率 | warm-clarity, neutral-flexible |
| 大众 + 情绪/放松 | soft-wellness, warm-clarity |
| 创作者/尝鲜 + 想行动 | bold-expressive, editorial |
| 高端/挑剔 + 展示 | minimal-zen, editorial |
| 沉浸阅读 | editorial, neutral-flexible |

3. **固定放一个反向候选：反第一直觉，不反需求。** 第一直觉是拿到这份简报最先想到的做法，通常就是最近的坐标加它最常规的版式。反向候选仍要满足简报的目标感受词和每一条“X 但不 Y”，只在整页布局、字体或用色策略上推翻常规做法，至少推翻两处。可以换一个每根滑杆都与简报相差不超过 1 档、又不在 `avoid_for` 里的坐标，也可以沿用最近的坐标，换掉它的常规版式和用色。方向卡里标 `contrarian: true`，用 `keeps` 写保住了哪些目标感受，用 `flips` 写推翻了哪些常规做法。它让用户看到同一个目标的另一种做法，也防止所有候选挤在第一直觉附近。滑杆反过来的坐标不能当反向候选：需求要年轻、轻松，深色的安静检索台就反过了头。
4. **看口味记录。** 运行 `design_memory.py taste`；出现新颖度提醒时，候选里至少放两个最近没选过的坐标。
5. 把选出的坐标和理由写进简报的“候选方向”一节，再进入第 3 关写方向卡。

## 边界

- **用户明确指令 > 一切**：他说“必须深色”“要保留现有的红”，直接写进简报的“必须保留”，不问不猜。
- **绝不让用户在文字里判断风格**；风格判断是技能的活。滑杆和感受词问的是产品态度，用户答“说不清”时由技能推断。
- 库里没有合适坐标时，从当前任务提出设计方向，按 `visual-craft.md` 说明具体构图与手段。参考产品名只是查找线索，不代表已看过页面，也不必把需求塞进已有分类。
