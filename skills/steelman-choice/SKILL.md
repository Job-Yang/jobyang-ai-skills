# 钢人抉择 · 先把两边立到最强，再决定

> **一句话理论**：批评或放弃一个选项前，先把它重建到它**最强、最合理、最难被反驳**的版本（钢人），而不是攻击它最弱的版本（稻草人）。
> 出自论证伦理的**善意原则（Principle of Charity）**与**钢人论证（Steelman Argument）**。
>
> **它解决什么**：人在两个都说得通的选项前犹豫，常见假动作是——把倾向方的优点和反方的弱点摆在一起，自以为权衡过了（确认偏误）；或两边各说一句好处就凭感觉选。本技能强制你先听完两边最强版本，再定位**真正的分歧**和**一个能翻盘的事实**。
> **它不做什么**：不替你拍板、不制造第三个"折中方"糊弄、不假装角色扮演出独立观点。

## 触发与边界

启用：存在两个或少数几个**已成形的选项**，且都有一定道理、用户在权衡。

| 情况 | 去向 |
| --- | --- |
| 没有现成选项，要从本质重推一条新路 | `root-rethink` |
| 评单个想法值不值得做 | `opportunity-scorecard` |
| 核一条数据/说法真不真 | `claim-check` |
| 读一篇文章论证强不强 | `argument-reading` |
| 关键事实缺失、要查外部资料 | 需要时先调用 `outside-view` 取证，再回本技能收口 |
| 只有一个选项、或纯执行已定的决定 | 不启用 |
| 用户直接要"你告诉我选哪个"且责任在他 | 不替他决定；做完结构化后把决定权交还 |

选项由谁给：
- 用户已给出 A/B：直接进入协议。
- 用户只描述纠结、选项不清：先用一两轮澄清把候选**显式列成两个互斥选项**（一次问清最影响结论的），再开始；不要自己脑补第三个选项凑数。
- 确实存在三个实质不同的选项时，可对每个做"最强版本"，但超过三个先帮用户收敛，否则是在做选项罗列而非抉择。

## 钢人协议（主轴按序推进，简单二选一紧凑呈现）

### 1. 重述抉择

用一句话写清：**要决定什么、A 是什么、B 是什么、目标和硬约束是什么**。选项需真正互斥、在同一目标下可比；若发现两个选项其实在回答不同问题，先纠正问题定义。

### 2. 把每边立成钢人（核心步骤）

对 A、B 分别立出最强版本，涵盖五面核心维度（简单或边界明确的二选一可紧凑合写，不必强行拉长成 10–15 条独立列表）：

1. **最强理由**：支持这一边最有说服力的论证，用它支持者会用的最好方式表达，不用「有人可能觉得……」式敷衍。
2. **适用条件**：它在什么前提下确实是更优解。
3. **最大收益**：选它最好能拿到什么。
4. **最大风险与代价**：最诚实的坏处，不回避。
5. **最难回答的反对意见 + 当前最好回应**：主动找最锋利的反方一击，并给出这一边能给出的最强回应；答不上来就如实标注「此处无回应」，不编造。

钢人合格线：写出来的 A 方最强版本，**要让真正支持 A 的人看了觉得「这确实是我的意思，而且说得比我好」**。如果明显在树稻草人（用反方弱论证反衬倾向方），重写校准。

### 3. 让两边互相质疑，找三样东西

钢人各自立完后，让最强版本对撞，输出：

- **共同认可的事实**：两边其实不吵的部分（很多犹豫在这里就消失一半）。
- **共有前提检验**：若两边共同默认的预设本身就有误（说明两个选项可能都在同一错误前提上打补丁），**停止在原二选一里硬挑，显式提醒用户重框问题并转入 `root-rethink`**。
- **真正的分歧**：不是表面选项不同，而是背后**哪个假设、价值排序或约束判断**不同。
- **关键变量**：最可能改变结论的 1–2 个变量（某个事实、某个前提、某个未来条件）。

### 4. 收敛到能翻盘的问题或假设

把「还缺什么信息」收敛成**一个**最可能改变结论的问题/待验证项：

- 这个问题的答案若为 X → 选 A；若为 Y → 选 B。写清这个映射。
- 一次只问一个，且聚焦能翻盘的真分歧；不影响选择的问题略去。
- 能查的事实先去查（宿主具备检索则调用，上限 **1–2 轮**；无检索工具或连续受阻即停，标注「待外部核查 / 未执行外部核查」），别用纯对话拖延。

### 5. 交还决断

按信息完整度分单轮 / 两轮收口，不硬拖轮次：
- **单轮收口**（用户条件已够，或翻盘事实已在检索/上下文里查明）：跳过追问，本轮直接给条件化判断、倾向推荐与第一步动作，**并写清关键证伪/推翻条件与退出信号**。
- **两轮收口**（确实缺一个能翻盘的外部或偏好事实）：先输出第 1–4 步并问清那唯一一个翻盘问题（可同时给基于假设的暂定推演）；等用户回答或补到事实后，再给出完整收口。

收口内容：
- **条件化判断**：在什么前提下推荐哪个（把选择规则讲清，不替用户担责拍板）。
- **推荐选项 + 理由 + 第一步行动**：若关键变量已明朗，明确给出倾向；若仍取决于用户价值偏好，说明「事实层面已无分歧，剩下是你的价值选择」，再给参考倾向。
- **退出/止损条件**：选了之后出现什么信号说明选错了、该回头（若单轮收口，写明出现什么新证据会推翻当前判断）。
- 多候选时每个候选都应是用户真心愿意走的方案，不留凑数的备胎。

## 防失败模式（硬规则）

- **禁止稻草人**：每边呈现其最强理由和最强反方回应，不用弱论证凑数。
- **禁止假平衡**：证据明显一边倒时不「各打五十大板」，如实说明哪边更强、强多少。
- **不做假独立角色扮演**：不写「请三位专家发言」式剧本（价值在输出结构而非人格表演）。
- **禁止虚构**：找不到最佳回应就写无回应；关键事实未查就标待外部核查，不编造数据或来源。
- **不和稀泥**：不默认推出「A 和 B 结合一下」的第三方案，除非它真能同时满足两边目标且不付双倍代价。
- **不过度追问**：最多一个翻盘问题；信息足够时直接单轮收口。
- **决定权归属**：事实与推理归本技能，最终价值取舍和拍板权在用户；结论以「在……前提下」保留边界。

## 交付口吻（默示执行，直入主题）

- 默认**静默执行**，直接从核心抉择与双边论证切入，不在开头或中途输出「〔思考：钢人抉择〕」等过程横幅，也不把方法内部标签原样印成生硬小标题。仅当用户明确要求标明方法阶段时，才在首行附简短标识；串联转入 `root-rethink` 时衔接为一份统一结构与连续编号的回答，不叠双横幅、不重复起编号。

## 输出骨架

```text
抉择：在【目标与约束】下，A …… vs B ……
A 的钢人：最强理由 / 适用条件 / 最大收益 / 最大风险 / 最难反驳与回应
B 的钢人：（同上，简单抉择可合写要点）
共同事实与前提检验：……（若共有前提有误，提示转 root-rethink）
真正分歧与关键变量：……
一个翻盘问题（或关键证伪条件）：……（答 X→A，答 Y→B）
条件化判断、第一步行动与退出条件：……
```

简单二选一直接按信息密度紧凑呈现，重点立清两边最强处、真分歧与翻盘变量即可；若信息已足直接单轮收口，将「一个翻盘问题」改为写清「关键证伪条件」和第 5 步收口即可。

## 交付前自检

- [ ] 两边都写成了支持者会认可的最强版本，没有稻草人。
- [ ] 每边都包含最难反驳意见及其最强回应，答不上的地方已如实标注。
- [ ] 找到了共同事实、真正分歧（背后的假设/价值差异）、1–2 个关键变量。
- [ ] 信息不足时收敛出唯一一个能翻盘的问题并写清 A/B 映射；信息已足够时直接给出证伪条件与条件化判断。
- [ ] 没有假平衡、没有硬凑第三方案、没有角色扮演、没有编造。
- [ ] 最终把拍板权交还用户：事实结论与价值取舍分开，给了第一步与退出条件。
