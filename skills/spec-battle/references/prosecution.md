# 检察四镜、证据门槛与输出格式（按需查阅）

> 检察方严格只读：不修改任何文件，不看文档诞生前的闲聊记录，只信文档字面、当前代码与其它现行文档。

## 1. 通用四镜（所有文档均逐项排查）

1. **真实性（Truth）**：文档提到的每个文件名、函数/类型签名、路由、配置项、命令、数字或「目前系统做法」，都要在代码或现行文档里核到实物；找不到且未注明新建即属阻塞（写出查找路径）。
2. **术语一致（Terms）**：是否混用 `GLOSSARY.md` 中 `_Avoid_` 词、一词两义、两词一义，或未定义关键概念。
3. **自洽一致（Agreement）**：文档内部 Behavior vs `Not this`、Limits vs Does、Decisions vs 方案是否互掐，是否违背 `AGENTS.md` 项目状态/原则或设计规范。
4. **可执行精确度（Precision）**：凡涉及实现抉择之处，是否存在「合理 / 及时 / 优雅处理 / 泛泛写『支持 XX』却未给边界或契约 / 尽量 / 暂时 / 视情况 / TBD」等两位工程师会写出不同代码的含糊词；每处需落成明确数字、枚举状态或可测结果。

## 2. 分体裁专项镜

- **需求文档 / PRD / RFC 镜**：检查关键角色、入口、主路径、失败表现、上限约束、持久化与排除边界是否留白；检查用户必然碰到的边界场景（超时、空输入、并发、部分失败）是否都有定论；检查重点权衡是否写明原因与排除备选。
- **实现 Spec 镜**：
  - 上游 `Source` 摘要与实际需求文档一致；
  - 上游每条行为均有模块归属与对应测试；
  - 接口签名、错误态、顺序约束真实可编译调用；
  - 外部依赖类别与测试替身完备；
  - 数据存储写者唯一、多人大仓迁移兼容新老版本混跑且失败可回退；
  - **步骤防碰撞**：并行步（未被 `After` 串联）绝对不改同一文件；每步前置 `After` 完整且 `Check` 非空心测试。

## 3. 四件套门槛与严重度（缺一项立即丢弃）

1. **Where**：精确引用原句 + `file:line`（漏项则写明归属小节与场景）。
2. **Breaks when**：具体触发用户、输入或状态，以及哪里会出错或做错。
3. **Evidence**：涉及代码或他处文档声明时，写出本轮实际读到的 `file:line`。
4. **To close**：明确文档需要拍板或二选一收敛的具体问题。

| 严重度 | 含义 |
| --- | --- |
| `blocker` | 照写必做错、数据损坏、步骤跑不通、并行步骤文件冲突或上游 hash 已过期 |
| `major` | 真实边界场景未定论，或两位工程师按原文会写出两套不同实现 |
| `minor` | 术语偏离、形式小瑕疵或表述易被仓促误读 |

## 4. 汇报与 Hand-off 模板

```text
🦇 <doc> @ <short-sha>: N blocker, N major, N minor
检察方: 独立全新子代理 | 当前会话（存在锚定风险）   辩方: 当前会话 | 用户

## 待你裁决
#<n> [<severity>] <条目>: "<引用原文>" (<file:line>)
   Breaks when: ...
   [Open] 建议: <推荐结论>，原因: <理由>
   （或：检察起诉 → 辩方答辩 → 检察追问）

## 已拟妥修改（请确认）
#<n> [<severity>] <条目>: "<引用>" → 替换为 "<新文本>"

## 已化解
#<n> [<severity>] <一句话总结>. Refuted / Out of scope: <证据>.
```

若对抗对象为 Spec 且需要回流修改，裁决后附只读交接清单：

```text
## Hand-off for implement-spec (<slug>)
- #<n>: <已拍板结论，一条一句>
```
