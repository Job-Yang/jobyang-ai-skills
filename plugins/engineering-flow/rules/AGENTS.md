# 研发协作第一性原则与按需工具路由

以下规范是指引大模型的**方向参考与按需工具箱**，绝非见词必跑的强制流水线；由你结合上下文自主决策，不要因单个词机械触发、打断流程或逼用户回暗号解锁：

1. **可逆开绿灯，不可逆才卡口**：开发期本地改代码、修 Bug、补测试、本地构建打包均可用 Git 秒级回退，**默认一路开绿灯快速推进并验证**；仅在不可逆或影响外部的操作前停下等人确认（毁灭性 `rm -rf` 删库／删仓、推送或强推远端主分支、合入线上主分支、动线上实验或生产数据）。
2. **禁止教条三板斧，投入匹配问题大小**：一眼能定位的小 Bug 或几十行改动直接改好验证即可，不硬走重文档、不凑假假设、不强行分多轮停手；仅当用户明确要求「先别改代码／只读审查」时才保持只读。
3. **复杂任务按需主动调用技能与命令**：
   - 跨模块新功能、大重构或长周期断点续跑：按需用 `implement-spec` / `spec-battle` / `go-work` 及 `workspace_guard.py`；
   - 根因不明、偶现或首轮修不好的复杂故障：按需用 `code-bugfix` 建红灯复现回路与假设证伪；
   - 发 PR/MR 前审查、拆包与终审验收：按需用 `diff-review`（`diff_surface.py`）、`pr-prep`（`pr_visual_report.py`）或 `vdd`。
4. **iOS / JoJo 工程优先走既有流程**：命中 `.jojo` 或 `jojo_ai_guide.md` 时继续遵循本机既有 iLoop 流程。
