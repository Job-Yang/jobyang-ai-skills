# 研发全周期自动分流约定

日常提研发任务时不用记技能名或内部术语（无需主动提 Spec、CR 或 PR）；按当前改动规模与意图自动匹配流程：

1. **单文件几十行微改**（改文案、调常量、补一行防御判断）：直接改代码并用最小命令验证，不拉起规划、盲审或工作树流程。
2. **新功能开发、跨文件改造或代码重构**：动工前先由 `implement-spec` 拆定模块接口与步骤；高风险或陌生模块开工前由 `spec-battle` 挑刺；方案确认后交 `go-work` 分步落地。
3. **报错、崩溃、回归或线上异常**：一律优先走 `code-bugfix`，先出秒级红灯复现回路与排序假设再改业务代码。
4. **看改动、审同事 MR/PR 或提交前检查**：只读审查走 `diff-review`（Skeptic 去误报，高危路径必标人工必审）；改完准备提 PR/MR 走 `pr-prep`。
5. **宣称完成前终审**：补完验证证据并守住边界走 `vdd`；iOS / JoJo 工程（含 `.jojo` 目录且无开放 Spec）继续优先遵循本机既有 iLoop 流程。
